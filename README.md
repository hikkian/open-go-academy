# Open Go Academy

Локальная браузерная платформа обучения Go на русском. В локальный каталог включены 128 глав Zero → Senior и 120 упражнений начальных трёх рангов; для Middle → Senior проходит финальная all-88 техническая приёмка текущего дерева, а педагогическая и governance-проверки ещё открыты. Сквозной сценарий «урок → редактор → изолированный запуск → проверка → сохранённый прогресс» работает. Реализованы P1–P5 workspaces и отдельные project runners, экзамены и evidence pipeline шести рангов, опциональный AI Tutor, локальные подписанные учебные credentials и passport. Advanced award выдаётся только при точных course/project/exam evidence и настроенном доверенном human-review pipeline; автоматическая проверка проекта не заменяет архитектурное ревью. Ранг не является обещанием должности или аккредитацией. Точный статус: [план](docs/EXECUTION_PLAN.md), [handoff](AGENT_HANDOFF.md), [панель прогресса](docs/PROJECT_PROGRESS.html).

## Локальный запуск Linux

Требуются Node 24 LTS, npm, Go ≥1.21 (скрипт выбирает точный 1.27.2), make, **rootless Podman с cgroup v2/systemd, seccomp**. Подтверждённая среда: Fedora 44, Podman 5.8.7. Первоначальная установка скачивает зависимости и Go-образ; обучение не использует AI API и не требует ключа.

```sh
make bootstrap
make build
```

В двух терминалах из корня проекта:

```sh
make runner
```

```sh
make dev
```

Откройте http://127.0.0.1:8380 . Создайте профиль и откройте урок. Runner должен сообщить `local runner ready`. Если preflight не подтвердил ресурсы или runtime отсутствует, исполнение недоступно; API продолжает хранить профиль, уроки и черновики. Unsafe fallback отсутствует. Vite для разработки UI: `cd web && npm run dev` (API нужен на 8380).

Прогресс и профиль находятся в `.data/academy.db`; Unix socket и приватный session.secret — в `.data/`. Остановите процессы Ctrl+C. Для backup остановите API и скопируйте `.data/academy.db` вместе с `session.secret` в закрытый каталог. Не удаляйте БД при обновлении: migrations применяются автоматически. Локальная установка рассчитана на одного владельца ОС, cookie не является внешней проверкой личности.

## Автоматические проверки

```sh
make test
make sandbox-test
python3 scripts/crash-check.py
# С работающим make runner:
make e2e
```

`npm run e2e` без ACADEMY_E2E_RUNNER выполняет reader/editor smoke и явно пропускает запуск кода. Sandbox tests намеренно выполняют ограниченные memory/PID/output/disk/cancel probes внутри rootless контейнеров. Playwright включает desktop/mobile, light/dark, axe, screenshots и trace при ошибке. Артефакты в ignored `artifacts/`; evidence в [VALIDATION_REPORT](docs/VALIDATION_REPORT.md).

## Ограничения и сопровождение

API допускает только loopback. Runner — отдельный процесс с Unix socket 0600, image по digest, uid65532, read-only root, network none, capabilities drop, no-new-privileges, seccomp, cgroups и ограниченный tmpfs. Контейнер делит ядро с host; это локальный учебный режим, не проверенная защита публичного multi-tenant сервиса. [Модель угроз](docs/architecture/THREAT_MODEL.md).

Поддержка Windows/macOS и hosted PostgreSQL пока не проверена. Лицензия кода и учебных материалов ещё не выбрана владельцем; пакеты помечены UNLICENSED. Публикации и платной инфраструктуры нет. Исследование версий: [ADR](docs/architecture/ADR-0001-tech-stack.md) и [матрица](docs/research/VERSION_MATRIX.md). Обновления требуют регрессионной проверки, lockfiles сохраняются.

Необязательные инструкции для [Windows через WSL 2](docs/INSTALL_WINDOWS_WSL.md) и [macOS через Linux VM](docs/INSTALL_MACOS.md) описывают непроверенные маршруты и условия, при которых sandbox должен оставаться выключенным. Они не расширяют список валидированных платформ.

### Необязательный ИИ-наставник

Без AI весь учебный сценарий работает. Для подключения локальной модели из UI задайте её OpenAI-compatible loopback HTTP endpoint и имена моделей в настройках Tutor; конфигурация без API-ключа атомарно сохраняется в `.data/tutor-provider.json` с правами 0600 и временно переопределяет provider из окружения до удаления. Сохранение не вызывает модель; обычный запрос требует отдельного согласия. Также можно экспортировать `ACADEMY_AI_ENDPOINT` (полный OpenAI-compatible `/v1/chat/completions` URL) и `ACADEMY_AI_MODEL`, затем перезапустить API. Пример переменных — `.env.example`; `.env` автоматически не читается. Совместимость конкретной локальной модели необходимо проверять: шлюз отправляет `max_completion_tokens`, не выполняет model discovery и не скачивает модели. `ACADEMY_AI_ADVANCED_MODEL` маршрутизирует review/interview/architecture/deeper, `ACADEMY_AI_FALLBACK_MODEL` включается после ошибки основной модели. `ACADEMY_AI_PROVIDER_LOCATION=local|cloud|unknown` явно описывает местоположение обработки; по умолчанию `unknown`, оно не определяется по HTTP/HTTPS. В настройках интерфейса видны выбранный host/модели и расход; ключи не возвращаются браузеру.

Если локальная модель не подойдёт, в UI можно подключить OpenAI-compatible облачный HTTPS endpoint. Сохранение требует API-ключ, но не отправляет запрос модели; ключ атомарно хранится только в `.data/tutor-cloud-provider.json` с правами 0600 и не возвращается API. Перед каждой отправкой отдельно требуется согласие. Для переменных cloud-провайдера из окружения по-прежнему требуется `ACADEMY_AI_ALLOW_CLOUD=true`. Нужен отдельный API-ключ из [настроек OpenAI API](https://platform.openai.com/api-keys); API и ChatGPT/Codex имеют раздельную оплату ([официальное разъяснение](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)). Пользовательские cloud endpoints проходят HTTPS/public-IP проверки; HTTP разрешён только для loopback, IP адреса закрепляются при настройке, redirects/proxy env отключены. После смены DNS нужно переподключить endpoint или перезапустить сервис. Смена local/cloud конфигурации инвалидирует предыдущую версию согласия; устаревший запрос получает 409 до резерва и внешнего вызова. Историю диалога, текст запросов и ответы сервер не сохраняет. Настроенная модель не обучена и не дообучена этим проектом на student prompts; провайдер обрабатывает только выбранный контекст по собственным правилам хранения, а стоимость зависит от тарифа.

`ACADEMY_AI_DAILY_TOKENS` (по умолчанию100000, максимум1000000) — общий дневной бюджет локального профиля по UTC. Перед запросом резервируется до четырёх консервативных объёмов только выбранного контекста (UTF-8 bytes + system overhead + output); gateway фактически выполняет максимум три вызова. Успех с достоверным usage списывает фактический расход, retry/fallback/timeout/неполный usage — весь резерв. Неоконченные резервы после аварии сохраняются до смены дня, чтобы перезапуск не обходил лимит. Это ограничение токенов, а не гарантия цены в валюте: тариф и достоверность счётчика контролирует внешний провайдер. Retrieval добавляет до 24 КиБ только опубликованных глав: выбранная глава идёт первой, затем до двух подходящих; без lesson_id сервер подбирает до трёх глав по вопросу. Открытый текст текущей главы передаётся полностью, если он вместе с metadata помещается в общий лимит. Черновики, reference solutions, graders и ответы self-check не включаются. Код требует отдельного согласия (`share_code`); структурированная браузерная диагностика `{status,exit_code,stdout,stderr,checks:{total,passed,failed}}` до 4 КиБ — `share_diagnostics` и может включать stdout/stderr; серверная сводка прогресса — `share_progress`. Сводка формируется сервером: подтверждённый ранг, числа проверенных упражнений по рангам и ограниченные ID/уровни навыков. Клиентские значения прогресса не принимаются; имя и история попыток не отправляются. Диагностика — недоверенные данные и не доказательство запуска. Проверьте выбранный контекст на секреты; маскирование неполное. Ответ модели не изменяет XP/ранг.

Воспроизводимый тест без LLM и без денег: отдельным процессом `python3 scripts/tutor-test-provider.py`, затем `ACADEMY_E2E_TUTOR=1 ACADEMY_AI_ENDPOINT=http://127.0.0.1:8095/v1/chat/completions ACADEMY_AI_MODEL=economy-test ACADEMY_AI_FALLBACK_MODEL=fallback-test ACADEMY_AI_DAILY_TOKENS=45000 npm run e2e -- --grep tutor`. Это явный HTTP test double, не AI-модель; он используется только для проверки транспорта, consent, fallback, ошибок и квоты на disposable E2E DB.

### Локальные учебные credentials

После подтверждённого экзамена раздел «Паспорт» позволяет выпустить документ с именем или псевдонимом. Он приватен по умолчанию; публикация credential и паспорта включается раздельно с согласием. Публикация раскрывает перечисленные в форме поля, пока адрес доступен в вашей локальной установке. Публичная проверка `/verify/:id` доступна без cookie только для опубликованной записи; отзыв показывает revoked, снятие с публикации возвращает404. Уже скачанные документы невозможно удалить из чужих копий.

JSON `oga-local-v1` подписан Ed25519 ключом `.data/issuer.key`; PDF и PNG визуализируют этот результат и содержат QR локальной проверки. PDF не имеет отдельной цифровой PDF-подписи. Подпись не доказывает личность, профессиональную должность, опыт или аккредитацию; самостоятельная установка не является доверенным внешним эмитентом. Соответствие Open Badges/W3C VC не заявляется. Ключ в verify-ответе сам по себе не создаёт доверие: для независимой проверки закрепите ожидаемый fingerprint доверенным способом.

Резервируйте **вместе** SQLite `.data/academy.db`, `.data/issuer.key` и session.secret в приватное хранилище при остановленном API; issuer.key должен оставаться0600. Не кладите их в Git, архив исходников, логи или публичный доступ. При потере ключа с выпущенными credentials startup блокируется: восстановите оригинальный ключ из личной резервной копии. Другой ключ не переподписывает старые records; автоматической ротации нет. `ACADEMY_ISSUER_KEY` позволяет указать другой приватный путь. Проверенный runtime остаётся Linux local-only.

## Отдельный исполнитель P2 LinkHub

После базового запуска rootless Podman, `make bootstrap` и `make build`:

```sh
make project-runtime  # локальные образы SDK и checker; загрузка закреплённых Go-зависимостей
make project-runner   # отдельный процесс; оставить работающим вместе с API и basic runner
```

SDK содержит разрешённые зависимости из закреплённых go.mod/go.sum. Проверяющая программа находится в другом образе; эталонная бизнес-логика в SDK не включена. Метаданные immutable image IDs и политика сохраняются локально в ignored `.data/p2-runtime` с правами 0600. Если образ отсутствует, worker не скачивает его автоматически. Для проверки PostgreSQL нужен заранее загруженный образ по digest из [исследования P2](docs/research/P2_LINKHUB.md).

В интерфейсе «Проекты → LinkHub API» доступны вложенные файлы, версии и ZIP. Кнопки исполнения доступны при работающем project-runner. «Запустить» проверяет готовность внутри временной среды, не открывая порт на компьютере; «Запустить тесты» запускает Go-тесты; «Проверить проект» выполняет независимые HTTP-проверки и проверяет сохранение после перезапуска сервера. Dockerfile/Compose из редактора предназначены для экспорта и не управляют учебным worker. БД временная для каждой проверки; учебные исходники сохраняются в платформе.

Автоматические дополнительные проверки разработчика:

```sh
python3 scripts/p2-reference-check.py
python3 -m venv .tools/qa-python
.tools/qa-python/bin/pip install -r scripts/qa-requirements.txt
.tools/qa-python/bin/python scripts/p2-schema-check.py
python3 scripts/p2-worker-check.py
python3 scripts/p2-worker-recovery-check.py
ACADEMY_E2E_PROJECT_RUNNER=1 npm run e2e -- --grep 'P2 real isolated'
```

Первый скрипт выполняет только доверенный эталон в изолированной PostgreSQL-среде и создаёт обезличенные тестовые ответы для schema-check. Recovery-check поднимает отдельный временный worker, проверяет отмену и SIGKILL/restart и удаляет только контейнеры своей установки. Это local-only проверка; публичное многопользовательское исполнение не разрешено этой конфигурацией.

Учебные Junior/Junior+ по автоматическим критериям v1.0.0 требуют всех упражнений соответствующей программы, предыдущего ранга, функциональных проверок P1/P2 и экзамена. Ручное качество проекта не подтверждается этими рангами и явно выделено в критериях сертификата. Тест native-цепочки: `ACADEMY_EXAM_CATALOG_NATIVE=1 sh scripts/go.sh test -count=1 -timeout=10m -run TestNativeJuniorAndJuniorPlusAssessmentChain -v ./internal/httpapi` (предварительные условия — явные тестовые данные; проверяемый код исполняется в настоящей песочнице).
