# Структуры, указатели, методы и nil

## Что ты сделаешь

Ты напишешь три функции над записями `User`: `findUser` вернёт указатель на нужного пользователя, `activeUsers` построит карту «ID → активен», `renamedCopy` создаст копию записи с новым именем и не тронет исходную. По дороге разберёшься, когда структура копируется, когда меняется сама, и что значит `nil`.

## Структура копируется целиком

Структура (`struct`) объединяет поля в один тип. Присваивание `b := a` копирует все поля. После этого `b` и `a` — два независимых значения:

```go
package main

import "fmt"

type User struct {
    ID   int
    Name string
}

func main() {
    a := User{ID: 1, Name: "Ada"}
    b := a
    b.Name = "Bob"
    fmt.Println(a.Name, b.Name)
}
```

Вывод: `Ada Bob`. Изменение `b` не задело `a`, потому что копировалась вся структура.

> **Важно.** Передача структуры в функцию тоже копирует её. Функция, которая меняет параметр-структуру, не меняет исходную переменную.

## Указатель: доступ к исходному значению

Указатель (`*User`) хранит адрес значения. `&a` берёт адрес, `*p` разыменовывает его. Для полей Go разыменовывает сам: `p.Name` — то же, что `(*p).Name`.

```go
package main

import "fmt"

type User struct {
    ID   int
    Name string
}

func rename(u *User, name string) {
    u.Name = name
}

func main() {
    a := User{ID: 1, Name: "Ada"}
    rename(&a, "Ira")
    fmt.Println(a.Name)
}
```

Вывод: `Ira`. Функция получила адрес и изменила то же самое значение.

## nil: указатель ни на что

Указатель без значения равен `nil`. Чтение поля через `nil` аварийно останавливает программу. Поэтому функция, которая принимает указатель, сначала проверяет его:

```go
package main

import "fmt"

type User struct {
    ID   int
    Name string
}

func name(u *User) string {
    if u == nil {
        return "нет пользователя"
    }
    return u.Name
}

func main() {
    fmt.Println(name(nil))
    fmt.Println(name(&User{Name: "Ada"}))
}
```

Вывод: `нет пользователя` и `Ada`.

> **Типичная ошибка.** `for _, u := range users { p := &u }` даёт адрес копии элемента, а не самого элемента. Изменения через `p` в срез не попадают. Указатель на элемент берут через индекс: `&users[i]`.

Пример правильного выбора:

```go
package main

import "fmt"

type User struct {
    ID   int
    Name string
}

func main() {
    users := []User{{ID: 1, Name: "A"}, {ID: 2, Name: "B"}}
    for i := range users {
        p := &users[i]
        p.Name = "x" + p.Name
    }
    fmt.Println(users)
}
```

Вывод: `[{1 xA} {2 xB}]`.

## Если что-то пошло в тупик

- `invalid memory address or nil pointer dereference` → разыменован `nil`. Проверь указатель до обращения к полю.
- `cannot use &u (value of type *User) ...` → тип указателя не совпадает с ожидаемым: проверь сигнатуру.
- Изменение не видно снаружи → возвращалась копия, а не указатель на элемент. Используй `&users[i]`.
- Результат печатается как `null` → функция вернула `nil`-указатель. Для «не нашли» это нормально, если контракт так говорит.

## Практика

Три задания. Функции проверяются на входах из блока «Ожидаемый вывод»; закрытые примеры видны только в «Проверить».

### Задание 1 · Найди пользователя

**Цель.** Вернуть указатель на первого пользователя с нужным ID и `true`; если его нет, — `nil` и `false`.

**Ожидаемый вывод** — входы: ID `2` среди `A` (ID 1) и `B` (ID 2), затем ID `4` в пустом списке:

```text
[{"ID":2,"Name":"B"},true]
[null,false]
```

Указатель печатается как структура, а `nil` — как `null`.

**Шаги.**
1. Выбери задание «Найди пользователя»: в файле есть `findUser` с `return nil, false`.
2. Пройди по `users` через индекс: `for i := range users`.
3. Если `users[i].ID == id`, верни `&users[i]` и `true`.
4. Если совпадений не было, верни `nil, false`.
5. Нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Две строки: `[{"ID":2,"Name":"B"},true]` и `[null,false]`; все три критерия зелёные.

**Если не принято.**
- Вернулась копия, и исходный список не меняется → указатель должен быть на элемент среза, `&users[i]`, а не на переменную цикла.
- Для повторного ID выбран второй → цикл должен остановиться на первом совпадении.
- Закрытый пример с `nil`-срезом падает → цикл по `nil`-срезу безопасен, паники там нет.

> **Подсказка.** Функция возвращает два значения, и второе обязано совпадать с наличием результата.

### Задание 2 · Посчитай активных пользователей по ID

**Цель.** Построить карту «ID → Active» по всем элементам; при повторе ID побеждает последнее вхождение.

**Ожидаемый вывод** — входы: два пользователя (ID 1 активен, ID 2 нет), затем пустой список:

```text
{"1":true,"2":false}
{}
```

Ключи-числа печатаются строками: `"1"`, `"2"`.

**Шаги.**
1. Выбери задание «Посчитай активных пользователей по ID»: в файле есть `activeUsers` с `return nil`.
2. Создай результат через `make(map[int]bool)`.
3. Пройди по `users` и запиши `result[u.ID] = u.Active`.
4. Верни `result`, нажми «Запустить» и сравни с блоком выше.
5. Нажми «Проверить».

**Как проверить себя.** Два JSON-объекта: `{"1":true,"2":false}` и `{}`; все три критерия зелёные.

**Если не принято.**
- Пустой ввод печатается как `null` → карта не создана через `make`.
- Повторный ID показывает первое значение → запись должна перезаписывать ключ при каждом вхождении.
- Закрытый пример с отрицательным ID не совпал → ключ может быть любым `int`, в том числе отрицательным.

> **Подсказка.** Запись `result[id] = value` перезаписывает прежнее значение, поэтому последнее вхождение побеждает само.

### Задание 3 · Создай безопасную копию записи

**Цель.** Для `nil` вернуть `nil` и `false`. Иначе создать копию структуры, поменять в ней имя и вернуть указатель на копию и `true`. Исходная структура не меняется.

**Ожидаемый вывод** — входы: пользователь `Ira` (ID 5) с новым именем `Irina`, затем `nil`:

```text
[{"ID":5,"Name":"Irina"},true]
[null,false]
```

**Шаги.**
1. Выбери задание «Создай безопасную копию записи»: в файле есть `renamedCopy` с `return nil, false`.
2. Проверь `user == nil`: при `nil` верни `nil, false`.
3. Скопируй значение: `c := *user`. Это новая структура, а не адрес исходной.
4. Поменяй имя: `c.Name = name`.
5. Верни `&c` и `true`, нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Две строки: `[{"ID":5,"Name":"Irina"},true]` и `[null,false]`; все три критерия зелёные.

**Если не принято.**
- Исходная структура поменяла имя → вместо копии вернулся указатель на `user`; копируй через `c := *user`.
- Паника при `nil` → проверка `user == nil` должна идти раньше разыменования.
- Закрытый пример с пустым новым именем не совпал → пустая строка тоже допустима: значение заменяется как есть.

> **Подсказка.** `c := *user` копирует структуру; `&c` возвращает адрес этой копии.

## Итог

- Присваивание и передача структуры копируют все поля; указатель даёт доступ к исходному значению.
- `nil` у указателя означает «нет значения»: проверяй его до обращения к полям.
- Указатель на элемент среза берут через индекс: `&users[i]`, а не через переменную цикла.
