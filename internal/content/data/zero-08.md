# Мини-проект и обзор Zero

## Задача проекта

Представьте, что у вас есть результаты небольшой учебной группы. Нужно посчитать, сколько участников набрали проходной балл, получить сводку всех результатов и определить понятный итоговый статус. Здесь соединяются типы, условия, циклы, функции, строки и срезы из предыдущих глав.

У нас есть список целых баллов от 0 до 100. Контракт этого учебного проекта считает проходным результат `60` или выше. Для сводки пустого списка количество и сумма равны нулю, а среднее равно `0`. Минимум и максимум для пустого списка тоже равны `0`; поле `HasScores` явно показывает, есть ли реальные результаты. Такое решение исключает угадывание по нулевому min/max.

Это маленькая модель для практики, а не правила реального экзамена. Она не хранит персональные данные и не доказывает квалификацию человека. Программа получает значения как аргументы функций и возвращает вычисленные структуры.

## План разбиения на функции

Разделим работу на независимые части: `countPassing` считает проходные результаты; `summarizeScores` вычисляет количество, сумму, среднее, минимум и максимум; `reviewStatus` преобразует готовую сводку в короткое текстовое объяснение. У каждой функции одна ясная ответственность и заданная сигнатура.

Для подсчёта нужно пройти по всем значениям и увеличить счётчик, когда балл не меньше 60. Граница существенна: ровно 60 — проходной балл. Если перепутать `>=` с `>`, участник ровно на границе будет ошибочно исключён.

Для суммы начните с нуля и добавляйте значение на каждой итерации. Для минимума и максимума пустого входа нельзя бездумно читать `scores[0]`. Сначала проверьте длину. Для непустого входа начальные min и max можно взять из первого элемента; затем цикл просмотрит остальные. Среднее вычисляйте как `float64(total) / float64(count)`, чтобы дробная часть не потерялась при целочисленном делении.

## Полная работающая программа

Следующий пример самодостаточен. Его можно сохранить как `main.go` и запустить кнопкой Run. Он не использует файлы или сеть.

```go
package main

import "fmt"

type ScoreSummary struct {
    Count     int
    Total     int
    Average   float64
    Minimum   int
    Maximum   int
    HasScores bool
}

func summarize(scores []int) ScoreSummary {
    summary := ScoreSummary{Count: len(scores)}
    if len(scores) == 0 {
        return summary
    }
    summary.HasScores = true
    summary.Minimum = scores[0]
    summary.Maximum = scores[0]
    for _, score := range scores {
        summary.Total += score
        if score < summary.Minimum {
            summary.Minimum = score
        }
        if score > summary.Maximum {
            summary.Maximum = score
        }
    }
    summary.Average = float64(summary.Total) / float64(summary.Count)
    return summary
}

func main() {
    result := summarize([]int{75, 60, 90})
    fmt.Println(result.Count, result.Total, result.Average, result.Minimum, result.Maximum)
}
```

Вывод: `3 225 75 60 90`. Структура (struct) собирает несколько связанных полей под одним типизированным именем. `ScoreSummary` сообщает не только числовые границы, но и `HasScores`, чтобы корректно обозначить пустой вход.

## Читаем цикл по шагам

Пусть вход `[75, 60, 90]`. Перед циклом количество равно 3, сумма равна 0, минимум и максимум равны 75. На первом проходе сумма становится 75, границы не меняются. На втором сумма 135, минимум становится 60. На третьем сумма 225, максимум становится 90. После цикла среднее равно 225 / 3 = 75.

Для пустого среза функция возвращает раньше: среднее остаётся 0, `HasScores` — false, min/max — 0. Ранний возврат упрощает тело основного цикла. Он не означает ошибку — это часть контракта.

## От формулировки к тестам

Проверяйте не только обычный случай. Набор полезных сценариев: пустой ввод; одно значение; только значения ниже 60; ровно 60; значения по обе стороны порога; одинаковые минимумы и максимумы; отрицательные числа, если тип допускает их контрактом. В реальных данных границы часто выявляют ошибку быстрее, чем длинный случай.

Для `countPassing` ожидания: `[]` даёт 0; `[59]` даёт 0; `[60]` даёт 1; `[59, 60, 61]` даёт 2. Для сводки `[10, 20]` число элементов 2, сумма 30, среднее 15, min 10, max 20. Для статуса условие должно назвать точную границу: в этой версии сводка считается успешной, когда среднее не меньше 60.

## Диагностика кода проекта

Если компилятор сообщает `undefined: ScoreSummary`, проверьте объявление типа и написание имени. `cannot use total (variable of type int) as float64` означает, что нужно преобразовать одно из значений перед вычислением дробного среднего. Если падает программа с индексом за границами, найдите чтение `[0]` до проверки пустоты. Если результат среднего неожиданно округлён, проверьте, не выполнено ли деление двух `int` до преобразования.

Ошибка компиляции и ошибка результата — разные вещи. Программа может собраться и давать неправильную границу. Для этого сравните каждый шаг с ручной трассировкой и добавьте вход, который проходит ровно по спорной ветке.

## Как устроены задания

### Простое — `countPassing`

Посчитай результаты `>= 60`. Возвращай число, не печатай. Пустой срез даёт ноль.

### Среднее — `summarizeScores`

Заполни тип `ScoreSummary` из каркаса: `Count`, `Total`, `Average`, `Minimum`, `Maximum`, `HasScores`. Правила для пустого ввода и среднего полностью перечислены в каркасе. Для непустых целых баллов вычисли все поля за проход или понятными небольшими шагами.

### Сложное — `reviewStatus`

Используя полученную сводку, верни статус по контракту: нет данных — `no data`; среднее не меньше 60 — `ready`; иначе — `review`. Функция не пересчитывает исходные оценки и не меняет структуру.

Не требуется помнить каждую функцию стандартной библиотеки наизусть. Важнее уметь найти подходящий инструмент, понять его контракт, проверить простой пример и заметить границу. До уровня Junior остаются новые темы; этот проект подтверждает только практику базовых понятий Zero.

## Точность контракта и типизированный результат

`Count` показывает количество входов, `Total` — сумму. Для непустого ввода `Average` равен сумме, делённой на количество. `Minimum` и `Maximum` берутся среди реально присутствующих значений. `HasScores` не позволяет трактовать нулевые поля пустого результата как реальные измерения. Структура собирает эти связанные данные в одно типизированное значение.

Для дробного среднего проверьте `[40, 41]`: ответ равен `40.5`. Если сначала выполнить `41 / 2` как целочисленное деление, а потом преобразовать результат, половина уже потеряна. Преобразование нужно выполнить до деления.

Для каждого поля запишите правило: количество равно длине; сумма накапливается; границы инициализируются первым элементом только после проверки пустоты; среднее вычисляется по преобразованным числам; признак данных истинен для непустого списка. Эта карта связывает условие с кодом и помогает локализовать ошибку.

Сигнатуры используют именованный тип и обычные `[]int`. Не меняйте имя типа или поля: проверяющий код ожидает этот контракт. В реальном проекте его обсуждают с потребителями API; в этом упражнении он задан заранее, чтобы сосредоточиться на алгоритме.

Во время проверки перечисляйте факты отдельно от предположений: какой вход передан, какое поле неверно, какой цикл мог его изменить и какая граничная проверка отсутствует. Сформулируйте ожидаемое значение, затем получите фактическое и найдите первый шаг расхождения.
