## Глоссарий

- **schema constraint (ограничение схемы)** — Условие данных, обеспечиваемое базой даже при нескольких конкурентных запросах.
- **state machine (машина состояний)** — Набор разрешённых состояний сущности и переходов между ними.
- **foreign key (внешний ключ)** — Связь, гарантирующая существование родительской записи.
- **transaction (транзакция)** — Группа операций, фиксируемая целиком или откатываемая целиком.
- **idempotency key (ключ идемпотентности)** — Стабильный ключ для распознавания повтора одной операции.

## Теория и границы применения

Схема данных фиксирует инварианты, которые должны сохраняться даже при конкурентных запросах и ошибках приложения. Для TaskFlow сначала определите сущности, их владельцев и связи: проект содержит задачи, задача принадлежит одному проекту, комментарий ссылается на существующую задачу. `NOT NULL`, внешние ключи, уникальные ограничения и CHECK выражают правила рядом с данными. Проверка только в handler недостаточна: два запроса могут одновременно пройти её и затем записать конфликтующее состояние.

Не храните в задаче произвольные копии полей проекта, если они должны изменяться согласованно. Используйте стабильные идентификаторы и явный tenant/project scope в запросах. Составной индекс под реальные фильтры может начинаться с `project_id`, но индекс не заменяет authorization. Для поиска по списку сначала ограничьте набор текущим project, а затем применяйте сортировку и пагинацию с устойчивым tie-breaker. Не загружайте глобальный список, чтобы фильтровать его в памяти.

Состояния задачи удобно описать конечным набором: `open`, `in_progress`, `done`, `cancelled`. Для каждого исходного состояния выпишите разрешённые переходы; неизвестное состояние и обратный переход по умолчанию запрещайте. Helper `TaskTransition` проверяет таблицу переходов, но не обеспечивает атомарность в базе. Если две команды меняют один объект, используйте условный UPDATE (`WHERE id=? AND state=? AND project_id=?`) и проверяйте число изменённых строк либо транзакцию с подходящей блокировкой. Отображайте конфликт как конкретный API ответ, не сообщая данные чужого проекта.

Миграции — тоже часть схемы. Держите изменения малыми, повторяемыми и совместимыми с порядком развёртывания: сначала расширение, затем код, который пишет новое поле, потом backfill и только после проверки возможное удаление старого. Тестируйте миграцию на пустой базе и на реалистичном предыдущем состоянии. Ошибка миграции не должна оставлять приложение в readiness, если обязательная схема не готова.

API validation и ограничения хранилища должны соглашаться о единицах. В этой главе заголовок ограничен 120 байтами UTF-8, потому что именно такое число проверяет `len(string)` в Go и может храниться в ограниченном поле. Это не 120 Unicode-кодовых точек и не 120 графем: например, 60 кириллических букв обычно занимают 120 байт. Проверьте пустое значение, 120 ASCII-байт, 121 ASCII-байт, 60 кириллических букв и 61 такую букву. Если продукту требуется ограничение по пользовательским символам, его надо сформулировать отдельно и одинаково реализовать во всех слоях.

Перед выводом о корректности проверяйте один путь целиком: запрос с авторизованным владельцем, запись в пределах его проекта, отказ при чужом ID, отсутствие побочного изменения и откат при нарушении уникальности. Сравнение двух project ID чистой функцией — полезный unit check, но не доказательство, что каждый SQL запрос ограничен нужным project или конкурентный переход атомарен.

Разберите пример эволюции: добавить к задаче необязательный `due_at`. Сначала проверьте, совместима ли новая колонка со старым приложением и нужна ли она старому клиенту. Создайте nullable поле и индекс только после проверки профиля запросов; разверните код, который умеет читать оба состояния; заполните значения ограниченными порциями; лишь затем решайте, можно ли вводить NOT NULL. При backfill определите возобновление после остановки и контрольные запросы на пропущенные строки. Миграция должна выдерживать повторный запуск или безопасно отказываться до изменения данных, а не оставлять неизвестную половину схемы. Для state transition запишите владельца каждого перехода: пользовательский handler, worker или административный процесс. Запретите переходы, которые вызываются только изменением произвольного поля в JSON. Проверяйте результат SQL по affected rows и отличайте конфликт версии от отсутствующего или чужого объекта. Именно этот контракт между API, транзакцией и схемой защищает данные; один `TaskTransition` его не реализует.

## Три самостоятельных запускаемых примера

### Пример 1: `TaskInput`

Контракт: projectID пуст→missing_project; затем пуст title→missing_title; длина в байтах UTF-8 >120→title_too_long; иначе valid.

```go
package main

import "fmt"

func TaskInput(projectID, title string) string {
	if projectID == "" { return "missing_project" }; if title == "" { return "missing_title" }; if len(title) > 120 { return "title_too_long" }; return "valid"
}

func main() {
	fmt.Println(TaskInput("p1", "Ship"))
}
```

Запуск: сохраните только этот блок в `main.go` и выполните `go run .`. Значения заданы в программе, поэтому результат детерминирован; программа не подключается к приложению и не проверяет внешние гарантии.

### Пример 2: `TaskTransition`

Контракт: Разрешены только open→in_progress/cancelled и in_progress→done/cancelled.

```go
package main

import "fmt"

func TaskTransition(from, to string) bool {
	switch from { case "open": return to=="in_progress" || to=="cancelled"; case "in_progress": return to=="done" || to=="cancelled"; default: return false }
}

func main() {
	fmt.Println(TaskTransition("open", "in_progress"))
}
```

Запуск: сохраните только этот блок в `main.go` и выполните `go run .`. Значения заданы в программе, поэтому результат детерминирован; программа не подключается к приложению и не проверяет внешние гарантии.

### Пример 3: `SameProject`

Контракт: true только для непустых равных project IDs; helper не выполняет authorization или SQL.

```go
package main

import "fmt"

func SameProject(taskProject, requestedProject string) bool {
	return taskProject != "" && requestedProject != "" && taskProject == requestedProject
}

func main() {
	fmt.Println(SameProject("p1", "p1"))
}
```

Запуск: сохраните только этот блок в `main.go` и выполните `go run .`. Значения заданы в программе, поэтому результат детерминирован; программа не подключается к приложению и не проверяет внешние гарантии.
