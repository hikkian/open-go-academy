# Пакеты, модули, документация и Git

## Что ты сделаешь

Ты напишешь три функции для разбора аргументов командной строки: `hasFlag` проверит, есть ли флаг, `ParseArgs` разберёт пары `--name` и `--limit` в настройки, `parseLimit` разберёт одно положительное число. По дороге разберёшься, что такое пакет и модуль, как читать документацию и как фиксировать изменения в Git.

## Пакеты и видимость имён

Пакет — единица, в которой собраны файлы с общими объявлениями. Программа начинается с пакета `main`. Имя, которое начинается с заглавной буквы, видно за пределами пакета; строчная буква оставляет его внутренним:

```go
package main

import "fmt"

type config struct {
    name string
}

func Describe(c config) string {
    return "name=" + c.name
}

func main() {
    fmt.Println(Describe(config{name: "ada"}))
}
```

Вывод: `name=ada`. Тип `config` и функция `Describe` в одном пакете видны друг другу, а внешний пакет увидел бы только имена с заглавной буквы.

> **Важно.** Видимость задаётся первой буквой имени, а не местом объявления. Заглавная буква делает имя экспортируемым из пакета.

## Модуль и документация

Модуль — набор пакетов с одним корнем и файлом `go.mod`, в котором записан путь модуля и версия Go. Документацию стандартной библиотеки читают командой `go doc`, например `go doc fmt.Println`: она показывает сигнатуру и комментарий. Так проверяют точное поведение функции, а не полагаются на память.

Документация отвечает на вопрос «что обещает функция», поэтому её читают до написания кода, а не после неожиданного результата.

## Разбор списка аргументов

Аргументы командной строки приходят срезом строк. Пара «флаг и значение» читается по индексам с шагом 2:

```go
package main

import "fmt"

func main() {
    args := []string{"--name", "Ada", "--limit", "3"}
    for i := 0; i+1 < len(args); i += 2 {
        fmt.Println(args[i], args[i+1])
    }
}
```

Вывод: `--name Ada` и `--limit 3`. Условие `i+1 < len(args)` не даёт выйти за конец среза, если пара неполная.

> **Типичная ошибка.** Цикл `i < len(args)` с обращением к `args[i+1]`: при нечётном числе аргументов последний флаг остаётся без значения, и программа падает с `index out of range`.

## Git: фиксировать изменения

Git хранит историю файлов. Типичная последовательность: `git status` показывает изменённые файлы, `git add` выбирает, что войдёт в коммит, `git commit -m "..."` сохраняет снимок с сообщением. Сообщение описывает, что изменилось и зачем, одной строкой в начале.

```sh
git status
git add parser.go
git commit -m "parse --name and --limit"
```

Этот блок показан для чтения: в редакторе курса команды не выполняются.

## Если что-то пошло не так

- `undefined: Describe` в другом пакете → имя начинается со строчной буквы и не экспортируется.
- `imported and not used` → импорт есть, а функции из него не вызваны.
- `index out of range` при разборе пар → цикл выходит за конец среза: проверь `i+1 < len(args)`.
- `declared and not used` → результат разбора не возвращается и не используется.

### Задание 1 · Найди флаг

**Цель.** Вернуть `true`, если аргумент `flag` стоит в `args` точно так же, иначе `false`.

**Ожидаемый вывод** — входы: срез `--help` с флагом `--help`, затем пустой срез с тем же флагом:

```text
true
false
```

**Шаги.**
1. Выбери задание «Найди флаг»: в файле есть `hasFlag` с `panic("TODO")`.
2. Пройди по `args` в цикле `for _, a := range args`.
3. Если `a == flag`, верни `true`.
4. Если цикл закончился без совпадения, верни `false`.
5. Нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Два значения: `true` и `false`; все три критерия зелёные.

**Если не принято.**
- Флаг `-x` находится по запросу `--x` → сравнение должно быть точным, без обрезки и преобразований.
- Закрытый пример с пустым флагом и пустыми аргументами не совпал → цикл по пустому срезу ничего не находит, поэтому `false`.

> **Подсказка.** Возврат `true` внутри цикла останавливает поиск сразу.

### Задание 2 · Разбери аргументы CLI

**Цель.** Разобрать пары `--name` и `--limit`. Имя не должно быть пустым, лимит — положительным числом. Любой лишний или неверный аргумент даёт нулевой `Config` и ошибку.

**Ожидаемый вывод** — входы: `--name Ada --limit 3`, затем пустой список аргументов. Результат печатается как объект с полями `Name`, `Limit` и `OK`:

```text
{"Name":"Ada","Limit":3,"OK":true}
{"Name":"","Limit":0,"OK":false}
```

**Шаги.**
1. Выбери задание «Разбери аргументы CLI»: в файле есть `Config` и `ParseArgs`, который пока возвращает `Config{}, nil`. Добавь импорты `"errors"`, `"strconv"` и `"strings"`, если используешь.
2. Пройди по парам аргументов с шагом 2, как в примере выше.
3. Для `--name` запиши значение в `Name`; для `--limit` разбери число через `strconv.Atoi`.
4. Любой другой флаг, пустое имя, отсутствующая пара или лимит не больше 0 — ошибка: верни `Config{}` и `errors.New(...)`.
5. Если обязательные поля не встретились, тоже верни ошибку.
6. Нажми «Запустить» и сравни с блоком выше.
7. Нажми «Проверить».

**Как проверить себя.** Два объекта: `{"Name":"Ada","Limit":3,"OK":true}` и `{"Name":"","Limit":0,"OK":false}`; все три критерия зелёные.

**Если не принято.**
- Неизвестный флаг принят → проверяй каждую пару: только `--name` и `--limit`.
- Лимит `0` принят → проверка «больше 0» стоит после разбора числа.
- Пустой список аргументов даёт `Name` с другим значением → при ошибке верни нулевой `Config`, а не частично заполненный.

> **Подсказка.** Сначала собери значения, потом проверь, что встретились оба обязательных флага.

### Задание 3 · Разбери числовой параметр

**Цель.** Разобрать положительное десятичное целое. Для всего остального вернуть `0` и ошибку.

**Ожидаемый вывод** — входы `3` и `x`. Результат печатается как объект с полями `Value` и `OK`:

```text
{"Value":3,"OK":true}
{"Value":0,"OK":false}
```

**Шаги.**
1. Выбери задание «Разбери числовой параметр»: в файле есть `parseLimit` с `panic("TODO")`. Добавь импорты `"errors"` и `"strconv"`, если используешь.
2. Разбери строку через `n, err := strconv.Atoi(s)`. Если ошибка, верни `0` и ошибку.
3. Если `n <= 0`, верни `0` и ошибку.
4. Иначе верни `n` и `nil`.
5. Нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Два объекта: `{"Value":3,"OK":true}` и `{"Value":0,"OK":false}`; все три критерия зелёные.

**Если не принято.**
- Ноль принят как число → проверка `n <= 0` должна стоять до возврата успеха.
- Отрицательное значение принято → отрицательные числа не проходят, как и ноль.
- Закрытый пример с числом 999 не совпал → большие положительные числа допустимы, если помещаются в `int`.

> **Подсказка.** Сначала ошибка разбора, потом знак числа.

## Итог

- Имена с заглавной буквы экспортируются из пакета; строчные остаются внутренними.
- Документация стандартной библиотеки проверяется `go doc` до написания кода.
- Разбор аргументов идёт парами по индексам; при ошибке результат нулевой, и ошибка возвращается явно.
