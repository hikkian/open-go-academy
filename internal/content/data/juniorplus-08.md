# Middleware

## Что ты сделаешь

Ты напишешь три обёртки над обработчиком: `WithRequestID` добавит идентификатор запроса из генератора, `RedactedAccessLog` запишет в журнал только метод и статус ответа, `LimitBody` ограничит тело запроса и передаст его дальше. Каждая обёртка вызывает следующий обработчик ровно один раз.

## Обёртка вокруг обработчика

Middleware — функция, которая принимает обработчик и возвращает обработчик с дополнительным поведением. Так обёртки складываются в цепочку: внешняя видит запрос первой и ответ последней. Порядок меняет результат:

```go
package main

import (
    "fmt"
    "net/http"
    "net/http/httptest"
)

func wrap(name string, next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        fmt.Println("enter", name)
        next.ServeHTTP(w, r)
        fmt.Println("leave", name)
    })
}

func main() {
    final := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        fmt.Println("handler")
    })
    h := wrap("outer", wrap("inner", final))
    h.ServeHTTP(httptest.NewRecorder(), httptest.NewRequest(http.MethodGet, "/", nil))
}
```

Вывод: `enter outer`, `enter inner`, `handler`, `leave inner`, `leave outer`. Внешняя обёртка начинает первой и заканчивает последней.

> **Важно.** Обёртка должна вызывать `next.ServeHTTP` ровно один раз. Два вызова дадут два ответа на один запрос.

## Request ID из генератора

Идентификатор запроса нужен для связи записей в журнале. Его берут из генератора сервера, а не из заголовка клиента: клиент может прислать чужой или пустой ID. Генератор передаётся извне функцией, чтобы его можно было подменить в тесте:

```go
package main

import "fmt"

func main() {
    ids := []string{"test-1", "test-2"}
    next := 0
    newID := func() string {
        id := ids[next]
        next++
        return id
    }
    fmt.Println(newID(), newID())
}
```

Вывод: `test-1 test-2`. Тест подставляет предсказуемый генератор, а сервер — настоящий.

## Журнал без секретов

Журнал нужен для диагностики: метод и статус отвечают на вопрос «что произошло». Путь с query-параметрами, заголовки `Authorization` и `Cookie` и тело запроса могут содержать токены и пароли. Поэтому в журнал пишут только безопасные поля:

```go
package main

import (
    "fmt"
    "net/http"
    "os"
)

func main() {
    r, _ := http.NewRequest(http.MethodGet, "http://example.test/x?token=secret", nil)
    fmt.Fprintf(os.Stdout, "method=%s status=%d\n", r.Method, http.StatusOK)
}
```

Вывод: `method=GET status=200`. Токен из query в журнал не попал: его в строку вывода не передавали.

> **Типичная ошибка.** Записать `r.URL.String()` целиком: там может оказаться `?token=...`. Пиши только поля, которые нужны для диагностики.

## Лимит тела: читать на один байт больше

Тело запроса читается с лимитом. Чтобы отличить тело ровно по лимиту от тела, которое его превышает, читают на один байт больше. Если прочитано больше лимита, это отказ:

```go
package main

import (
    "fmt"
    "io"
    "strings"
)

func main() {
    body := strings.NewReader("abcde")
    data, _ := io.ReadAll(io.LimitReader(body, 4+1))
    fmt.Println(len(data) > 4)
}
```

Вывод: `true`. Тело из пяти байт при лимите четыре превышает его.

## Если что-то пошло не так

- Обработчик отвечает дважды → `next.ServeHTTP` вызван больше одного раза.
- В журнале появился путь с секретом → запись использует `r.URL` целиком.
- Тело прочитано, и downstream получает пустое → восстанови `r.Body` из прочитанных байт.
- `undefined: io` → импорт не добавлен.

## Практика

Три задания. Обёртки проверяются на запросах из блока «Ожидаемый вывод»; закрытые примеры видны только в «Проверить».

### Задание 1 · Добавь request ID в ответ

**Цель.** Для каждого запроса вызвать генератор, установить заголовок `X-Request-ID` и ровно один раз передать запрос следующему обработчику. Клиентский заголовок не использовать.

**Ожидаемый вывод** — запросы с генератором, который вернул `test-1`, затем `test-2`. Каждый ответ печатается как объект с полями `Status` и `RequestID`:

```text
{"Status":204,"RequestID":"test-1"}
{"Status":204,"RequestID":"test-2"}
```

**Шаги.**
1. Выбери задание «Добавь request ID в ответ»: в файле есть `WithRequestID` с `panic("TODO")`. Импорт `"net/http"` уже есть.
2. Верни `http.HandlerFunc` с параметрами `w` и `r`.
3. Внутри вызови `newID()` и запиши результат в заголовок `X-Request-ID`.
4. Вызови `next.ServeHTTP(w, r)` ровно один раз.
5. Нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Два объекта с `RequestID`; все три критерия зелёные.

**Если не принято.**
- `RequestID` равен клиентскому значению → заголовок берётся из запроса, а не из генератора.
- Ответ записан дважды → `next` вызван больше одного раза.
- `RequestID` пустой → заголовок установлен после вызова `next`; ставь его до передачи ответа.

> **Подсказка.** Заголовок задаётся через `w.Header().Set` до вызова следующего обработчика.

### Задание 2 · Запиши только безопасный access log

**Цель.** Записать в `io.Writer` метод и итоговый статус ответа. Путь, query, заголовки, cookies и тело не писать. Обёртка ответа запоминает статус, который установил следующий обработчик.

**Ожидаемый вывод** — два запроса, для каждого следующий обработчик отвечает 201. Результат печатается как объект с полями `Status` и признаками утечек; все признаки `false`, кроме `HasMethod`:

```text
{"Status":201,"QueryLeak":false,"AuthLeak":false,"CookieLeak":false,"HasMethod":true}
{"Status":201,"QueryLeak":false,"AuthLeak":false,"CookieLeak":false,"HasMethod":true}
```

**Шаги.**
1. Выбери задание «Запиши только безопасный access log»: в файле есть `RedactedAccessLog` с `panic("TODO")`. Импорт `"fmt"` добавь, если используешь.
2. Заведи обёртку ответа: структуру со встроенным `http.ResponseWriter` и полем статуса. Переопредели `WriteHeader`, чтобы запомнить код.
3. Если статус не задан, считай его `200`.
4. После вызова `next` запиши в `dst` строку вида `method=... status=...`, используя метод запроса и статус из обёртки.
5. Нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Два объекта с `Status: 201`; все признаки утечек `false`; все три критерия зелёные.

**Если не принято.**
- В журнале появился путь или query → не используй `r.URL` в строке журнала.
- Статус в журнале всегда 200 → обёртка не переопределила `WriteHeader`.
- Журнал пуст → запись в `dst` должна быть сделана после вызова `next`.

> **Подсказка.** Встраивание `http.ResponseWriter` в структуру даёт все методы записи; переопредели только `WriteHeader`.

### Задание 3 · Ограничь чтение request body

**Цель.** Лимит должен быть от 1 до 1 MiB. Прочитать не больше `limit+1` байт. Больше лимита — 413 с текстом `request body too large`. Ошибка чтения — 400. Недопустимый лимит — 500 с текстом `invalid body limit`. Иначе восстановить тело и передать дальше.

**Ожидаемый вывод** — лимит 4 с телом из 3 байт и лимит 5 с телом из 5 байт. Следующий обработчик возвращает прочитанное тело:

```text
{"Status":200,"Body":"xxx"}
{"Status":200,"Body":"xxxxx"}
```

**Шаги.**
1. Выбери задание «Ограничь чтение request body»: в файле есть `LimitBody` с `panic("TODO")`. Добавь импорты `"bytes"` и `"io"`, если используешь.
2. Если `maxBytes` меньше 1 или больше 1048576, ответь 500 через `http.Error` с текстом `invalid body limit`.
3. Прочитай `io.ReadAll(io.LimitReader(r.Body, maxBytes+1))`. Ошибку чтения ответь 400.
4. Если прочитано больше `maxBytes`, ответь 413 с текстом `request body too large`.
5. Восстанови тело: `r.Body = io.NopCloser(bytes.NewReader(data))`.
6. Вызови `next.ServeHTTP(w, r)`.
7. Нажми «Запустить» и сравни с блоком выше.
8. Нажми «Проверить».

**Как проверить себя.** Два объекта с `Status: 200` и телом; все три критерия зелёные.

**Если не принято.**
- Тело размером 5 при лимите 4 принято → сравнение должно быть с `maxBytes`, а не с `maxBytes+1`.
- Лимит 0 даёт 413 → недопустимый лимит — это 500, а не превышение.
- Downstream получает пустое тело → `r.Body` не восстановлено после чтения.

> **Подсказка.** Читай ровно на один байт больше лимита, и ответ 413 придёт только тогда, когда лишний байт реально есть.

## Итог

- Middleware оборачивает обработчик; внешняя обёртка видит запрос первой и ответ последней.
- Request ID берётся из генератора сервера; журнал пишет метод и статус, но не секреты.
- Тело читается с лимитом на один байт больше; превышение — 413, после чтения тело восстанавливается.
