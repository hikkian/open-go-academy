# Клиент, сервер и путь HTTP

## Что ты сделаешь

Ты напишешь три функции, которые разбирают HTTP-обмен без сети: `ClassifyStatus` относит код ответа к семейству, `RequestSummary` собирает безопасную строку-снимок запроса, `ClassifyExchange` сверяет статус с заголовками и говорит, что произошло. Заодно научишься читать запрос и ответ по частям и проверять обработчик через `httptest`, не открывая ни одного порта.

## Клиент и сервер — роли в одном обмене

HTTP — формат сообщений между клиентом (client), который начинает запрос, и сервером (server), который его принимает и выбирает ответ. Это роли в одном обмене: сервис, отвечающий браузеру, сам может быть клиентом базы или другого сервиса.

```text
клиент                           сервер
  | ── запрос (request) ──────────▶ |
  | ◀── ответ (response) ────────── |
```

Стрелки показывают порядок, а не гарантию. Соединение может оборваться после того, как сервер всё сделал, но до того, как клиент получил ответ. Клиент тогда знает только, что ответа нет.

> **Важно.** Отправленный `POST` не доказывает, что запись создана. Повтор после тайм-аута иногда создаёт дубликат — это отдельный контракт идемпотентности, к нему вернёмся позже.

## Из чего состоит сообщение

У запроса четыре части: метод (намерение: `GET` читает, `POST` создаёт или обрабатывает), путь (`/links`), заголовки (headers — именованные метаданные вроде `Content-Type`) и необязательное тело (body — байты данных). У ответа три: код состояния (status code), заголовки и тело.

```text
POST /links HTTP/1.1
Host: example.test
Content-Type: application/json

{"alias":"go","target":"https://go.dev/"}

HTTP/1.1 201 Created
Content-Type: application/json
Location: /links/go

{"alias":"go","target":"https://go.dev/"}
```

Так сообщения выглядят для человека. В сети они закодированы байтами, и собирать их вручную в серверном коде не нужно: `net/http` разбирает протокол и отдаёт поля структурами.

> **Типичная ошибка.** Определять наличие тела по методу. У `GET` тело обычно пустое, но контракт задаёт это явно, а не метод.

## Пять семейств статусов

Код ответа — трёхзначное число, первая цифра задаёт семейство: `1xx` промежуточное, `2xx` успех, `3xx` перенаправление, `4xx` проблема запроса (клиент может исправить), `5xx` сбой сервера. Семейство помогает ориентироваться, но клиент опирается на конкретный код: `201 Created` и `204 No Content` — оба успех, а смысл разный.

```go
package main

import "fmt"

func family(code int) string {
    switch code / 100 {
    case 2:
        return "успех"
    case 3:
        return "перенаправление"
    case 4:
        return "ошибка запроса"
    case 5:
        return "сбой сервера"
    }
    return "вне диапазона"
}

func main() {
    fmt.Println(family(201), family(404), family(503), family(99))
}
```

Вывод:

```text
успех ошибка запроса сбой сервера вне диапазона
```

`code / 100` — целочисленное деление: 404 даёт 4. В заданиях ниже семейство задано границами (`>= 200 && < 300`), чтобы 600 не попал в «успех» по ошибке.

> **Типичная ошибка.** Отвечать `500` на неверный JSON в запросе. Это ошибка клиента, и он может её исправить, если получит `400`.

## Проверить обработчик без сети

`net/http/httptest` создаёт запрос и записывает ответ в памяти. Обработчик (handler) получает уже разобранный запрос и пишет ответ в `ResponseWriter`.

```go
package main

import (
    "fmt"
    "net/http"
    "net/http/httptest"
)

func main() {
    handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Content-Type", "text/plain; charset=utf-8")
        w.WriteHeader(http.StatusCreated)
        fmt.Fprintf(w, "%s %s", r.Method, r.URL.Path)
    })
    request := httptest.NewRequest(http.MethodPost, "/links", nil)
    recorder := httptest.NewRecorder()
    handler.ServeHTTP(recorder, request)
    fmt.Println(recorder.Code)
    fmt.Println(recorder.Header().Get("Content-Type"))
    fmt.Println(recorder.Body.String())
}
```

Вывод:

```text
201
text/plain; charset=utf-8
POST /links
```

Три наблюдения recorder — статус, заголовок, тело — это ровно то, что увидел бы клиент. Порядок в обработчике важен: заголовки и `WriteHeader` до первой записи тела, иначе `net/http` сам отправит `200`.

## Проверить JSON по полям, а не по байтам

Клиент сравнивает тело по смыслу: декодирует и смотрит поля. Порядок ключей и пробелы в JSON не обещаны.

```go
package main

import (
    "encoding/json"
    "fmt"
)

type Link struct {
    Alias  string `json:"alias"`
    Target string `json:"target"`
}

func main() {
    body := []byte(`{"target":"https://go.dev/","alias":"go"}`)
    var link Link
    if err := json.Unmarshal(body, &link); err != nil {
        panic(err)
    }
    fmt.Println(link.Alias, link.Target)
}
```

Вывод:

```text
go https://go.dev/
```

Ключи в теле идут не в том порядке, что поля структуры, и это нормально. Заголовок `Content-Type: application/json` не делает тело валидным JSON — валидность проверяет декодер.

## Как читать сбой по шагам

Порядок разбора, который не смешивает транспорт, синтаксис и бизнес-правила:

1. Кто отправил сообщение и кому: клиент или сервер.
2. Метод и путь: `GET /links` и `POST /links` — разные действия на одном пути.
3. Требуемые и фактические заголовки.
4. Статус: `404` «маршрут не найден» и `404` «запись не найдена» — два разных сценария, проверяй их отдельно.
5. Тело: декодируй и сравни поля; секреты и stack trace в ответ не попадают.

Меняй один вход за раз: тот же `POST /links` с корректным JSON и с пустым телом. Если поменять метод, путь и тело одновременно, причина не найдётся.

> **Зачем.** Таблица «ожидание / факт / что поменял» — это и есть тест: запиши её в `httptest`, и следующий рефакторинг проверит тот же контракт.

## Если что-то пошло не так

- `missing return at end of function` → добавь последний `return` для случая «ни одно условие не подошло».
- Красный закрытый пример при зелёных открытых → граница семейства: `300` уже перенаправление, `599` ещё сбой сервера, `600` — вне диапазона.
- `import … is not allowed` → в карточке сказано, какие импорты разрешены; `fmt` только там, где строка собирается форматированием.
- В «Получили» лишние пробелы или другой порядок полей → формат строки сравнивается буква в букву: `METHOD PATH host=… headers=… body=…`.
- `panic("TODO")` в «Результате» → стартовый код не заменён: функция должна вернуть значение.

## Практика

Три функции, без `main` и без печати. Среда вызывает их с входами и показывает результаты строками JSON; строки в кавычках.

### Задание 1 · Классифицируй HTTP status

**Цель.** Вернуть семейство кода: `success`, `redirect`, `client-error`, `server-error` или `other` для всего вне 200–599.

**Ожидаемый вывод** — для кодов 200 и 404:

```text
"success"
"client-error"
```

**Шаги.**
1. Выбери задание «Классифицируй HTTP status»: сигнатура `func ClassifyStatus(code int) string`. Импорты запрещены.
2. Замени `panic("TODO")` цепочкой условий по границам: `code >= 200 && code < 300` → `"success"`, затем 300–399, 400–499, 500–599.
3. Последней строкой верни `"other"`.
4. «Запустить», сравни. «Проверить» — закрытые примеры: 199, 300, 599, 600.

**Как проверить себя.** 199 и 600 дают `other`, 300 — `redirect`, 599 — `server-error`; все галочки зелёные.

**Если не принято.**
- Красный закрытый пример для 300 или 599 → нестрогая граница: нижняя включается (`>=`), верхняя нет (`< 400`).
- Красный для 600 → проверка `code >= 500` без верхней границы.
- `missing return` → нет последнего `return "other"`.

> **Подсказка.** Условия можно писать подряд с `return` в каждом — `else` не нужен, потому что `return` завершает функцию.

### Задание 2 · Составь безопасный снимок запроса

**Цель.** Вернуть строку `METHOD PATH host=HOST headers=N body=B`, а при пустом методе, пути или хосте либо отрицательном счётчике — `invalid`.

**Ожидаемый вывод** — для `("POST", "/links", "api.example.test", 2, 41)` и `("GET", "/health", "localhost", 0, 0)`:

```text
"POST /links host=api.example.test headers=2 body=41"
"GET /health host=localhost headers=0 body=0"
```

**Шаги.**
1. Выбери задание «Составь безопасный снимок запроса»: сигнатура `func RequestSummary(method, path, host string, headerCount, bodyBytes int) string`. Разрешён импорт `fmt`.
2. Первой проверкой верни `"invalid"`, если `method == "" || path == "" || host == "" || headerCount < 0 || bodyBytes < 0`.
3. Иначе верни `fmt.Sprintf("%s %s host=%s headers=%d body=%d", method, path, host, headerCount, bodyBytes)`.
4. «Запустить», сравни пробелы и знаки `=`. «Проверить» — закрытые примеры: `PATCH /links/x` с 4 заголовками, пустые метод и хост, `headers=-1`, `body=-1`.

**Как проверить себя.** Нули — допустимый вход (`headers=0 body=0`), отрицательные — нет; в строке нет ни тела, ни значений заголовков, только их число.

**Если не принято.**
- Красный «пример 2» → нули считаются ошибкой: проверяй `< 0`, не `<= 0`.
- Красный закрытый пример с пустым методом → проверка пустых строк неполная: нужны все три поля.
- Лишний пробел или `body:` вместо `body=` → сверь шаблон с ожидаемым выводом по символам.

> **Подсказка.** Снимок безопасен потому, что в нём нет содержимого: тело и значения заголовков могли бы содержать токены.

### Задание 3 · Сверь статус и заголовки ответа

**Цель.** По статусу, `Content-Type` и наличию `Location` вернуть `created`, `redirect`, `resource-missing`, `client-error`, `server-error` или `inconsistent`.

**Ожидаемый вывод** — для `(201, "application/json", true)` и `(404, "application/json", false)`:

```text
"created"
"resource-missing"
```

**Шаги.**
1. Выбери задание «Сверь статус и заголовки ответа»: сигнатура `func ClassifyExchange(status int, contentType string, hasLocation bool) string`. Разрешён импорт `strings`.
2. Правила по порядку: `201` и `contentType` начинается с `application/json` без учёта регистра (`strings.HasPrefix(strings.ToLower(contentType), "application/json")`) → `"created"`.
3. Статус 300–399: с `Location` → `"redirect"`, без него → `"inconsistent"`.
4. Ровно `404` → `"resource-missing"`; другие 400–499 → `"client-error"`; 500–599 → `"server-error"`.
5. Всё остальное, включая `200` и `201` без JSON, → `"inconsistent"`. «Запустить», «Проверить» — закрытые примеры: 302 с `Location` и без, 409, 500.

**Как проверить себя.** 302 без `Location` даёт `inconsistent`, 409 — `client-error`; порядок проверок: сначала 201, потом 3xx, потом 404, потом семейства.

**Если не принято.**
- Красный закрытый пример для 302 без `Location` → перенаправление без цели — противоречие, не `redirect`.
- Красный для 409 → проверка `404` стоит после общей ветки 4xx и не достигается.
- `201` с `text/html` вернул `created` → забыл условие на `Content-Type`.

> **Подсказка.** `inconsistent` — ответ по умолчанию: последний `return`, до которого доходит всё, что не описано правилами.

## Итог

- Обмен читается по частям: метод, путь, заголовки, тело запроса; статус, заголовки, тело ответа.
- `httptest` проверяет обработчик в памяти: статус, заголовок, тело — без порта и сети.
- Статус говорит о результате обмена, а не о состоянии данных: доказательства сохранения — отдельный контракт.
