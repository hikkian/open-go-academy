# SQL с нуля: таблицы и CRUD

## Что ты сделаешь

Ты напишешь три функции, которые описывают работу с таблицей `links` без подключения к базе: `ConstraintCategory` переведёт код ошибки PostgreSQL в категорию, `CreateLinkStatement` вернёт фиксированный SQL-запрос с параметрами, `LinkColumnAllowed` проверит имя столбца по списку разрешённых.

## Таблица, строка, столбец

Таблица хранит записи одного вида. Строка — одна запись, столбец — одно поле с типом. Таблица `links` описывает короткие ссылки: `id`, `owner_id`, `slug`, `target_url`, `enabled`, `created_at`. Ключ (`PRIMARY KEY`) однозначно указывает строку. Внешний ключ (`FOREIGN KEY`) требует, чтобы значение совпадало с существующей строкой другой таблицы, например `owner_id` с пользователем.

## Ограничения и коды ошибок

База отвергает запись, если нарушено ограничение. PostgreSQL сообщает о нарушении кодом SQLSTATE из пяти символов. Код `23505` означает уникальность (`UNIQUE`), `23503` — отсутствующую ссылку по внешнему ключу, `23514` — проверку (`CHECK`). Сравнивать нужно код, а не текст сообщения: текст зависит от языка и версии.

```go
package main

import "fmt"

func main() {
    codes := map[string]string{"23505": "unique_conflict", "23503": "missing_reference"}
    fmt.Println(codes["23505"], codes["23503"])
}
```

Вывод: `unique_conflict missing_reference`. Таблица соответствий — самый простой способ держать коды в одном месте.

> **Важно.** Ограничение в базе — последний рубеж. Уникальность slug всё равно проверяется в приложении, но гонка двух одинаковых запросов ловится только `UNIQUE`.

## Параметры вместо склейки

Значения пользователя передаются параметрами: `$1`, `$2`, `$3`. База отделяет запрос от данных, поэтому текст значения не становится частью SQL. Так работает `INSERT ... RETURNING`: вставка и возврат `id` в одном запросе:

```go
package main

import "fmt"

func main() {
    const insert = "INSERT INTO links(owner_id, slug, target_url) VALUES ($1, $2, $3) RETURNING id"
    fmt.Println(insert)
}
```

Вывод: строка запроса с тремя параметрами. Значения `owner_id`, `slug` и `target_url` передаются отдельно, не в текст.

> **Типичная ошибка.** Склеить запрос из кусков: `"... WHERE slug = '" + slug + "'"`. Кавычка внутри `slug` закроет строку, и запрос станет другим. Значения только параметрами.

## Идентификаторы: только из списка

Параметры работают для значений, но не для имён столбцов и таблиц. Если имя столбца приходит от пользователя, его выбирают из заранее заданного списка разрешённых имён:

```go
package main

import "fmt"

var sortable = map[string]bool{"created_at": true, "slug": true}

func main() {
    fmt.Println(sortable["slug"], sortable["slug DESC"])
}
```

Вывод: `true false`. Строка `slug DESC` не имя столбца, поэтому в списке её нет.

## Если что-то пошло не так

- `unknown column` в запросе → имя столбца не совпадает с таблицей; проверь написание.
- Ошибка `23505` видна пользователю как текст → клиенту нужна категория, а не текст ошибки базы.
- Запрос работает, но значения «ломаются» на кавычках → значения склеены в текст вместо параметров.
- `undefined: sortable` → карта не объявлена на уровне пакета.
