# TLS и безопасный транспорт

## Что ты сделаешь

Ты напишешь три функции, которые принимают решения о схеме адреса без подключения к серверу: `IsHTTPSOrigin` проверит, что адрес абсолютный и использует `https`, `TLSBoundary` классифицирует схему, а `RequireHTTPS` выберет безопасную схему или назовёт причину отказа. Сертификаты и доверие здесь не проверяются: это отдельная граница, о которой тоже пойдёт речь.

## Схема — это выбор транспорта

Адрес `https://api.example.test/v1` состоит из схемы (`https`), хоста и пути. Схема задаёт протокол: `https` означает, что соединение будет защищено TLS, `http` — что без шифрования. Стандартный пакет `net/url` разбирает такую строку по полям:

```go
package main

import (
    "fmt"
    "net/url"
)

func main() {
    u, err := url.Parse("https://api.example.test:8443/v1")
    fmt.Println(u.Scheme, u.Host, u.Port(), err)
}
```

Вывод: `https api.example.test:8443 8443 <nil>`. Поле `Scheme` — это то, что решает выбор транспорта.

> **Важно.** Схема `https` в адресе означает «ожидается TLS», но не доказывает, что сертификат настоящий. Проверка сертификата — отдельное наблюдение при подключении.

## Userinfo в адресе

Адрес может содержать логин и пароль перед хостом: `https://user:pass@example.test/`. Такой адрес небезопасно передавать дальше, потому что пароль попадает в журналы и историю. Поэтому политика может отказывать в адресах с `userinfo`:

```go
package main

import (
    "fmt"
    "net/url"
)

func main() {
    u, _ := url.Parse("https://user:pass@example.test/")
    fmt.Println(u.User != nil, u.Hostname())
}
```

Вывод: `true example.test`. `u.User` не `nil`, если в адресе есть `userinfo`. `Hostname` возвращает хост без порта.

## TLS: настройка без доверия всему подряд

Настройка TLS в Go задаётся структурой `tls.Config`. Минимальную версию протокола ставят явно, а не полагаются на значения по умолчанию в чужом коде:

```go
package main

import (
    "crypto/tls"
    "fmt"
)

func main() {
    cfg := &tls.Config{MinVersion: tls.VersionTLS12}
    fmt.Println(cfg.MinVersion == tls.VersionTLS12)
}
```

Вывод: `true`. Доверие к сертификату задаётся отдельно — набором корневых центров; в учебных тестах доверяют только сертификату тестового сервера, а не системе целиком.

> **Типичная ошибка.** Выключить проверку сертификата (`InsecureSkipVerify: true`), чтобы тест прошёл. Тест пройдёт, а защита исчезнет. Доверяй только тому сертификату, который создал сам для теста.

## Если что-то пошло не так

- `cannot use u (variable of type *url.URL)` → `url.Parse` возвращает два значения, а не одно: сохрани оба.
- `u.Scheme` пустое у относительного адреса → схема отсутствует, это не `https`.
- `imported and not used: crypto/tls` → импорт есть, а настройка не использована.
- Проверка проходит на адресе `https://` → пустой хост не означает защищённый адрес; проверяй `Host`.

## Практика

Три задания. Функции проверяются на входах из блока «Ожидаемый вывод»; закрытые примеры видны только в «Проверить». Сеть не используется, сертификаты не проверяются.

### Задание 1 · Проверь HTTPS-схему, не сертификат

**Цель.** Вернуть `true` только для абсолютного адреса со схемой `https` и непустым хостом. Соединение и сертификат не проверять.

**Ожидаемый вывод** — входы: `https://api.example.test/v1` и `http://api.example.test/`:

```text
true
false
```

**Шаги.**
1. Выбери задание «Проверь HTTPS-схему, не сертификат»: в файле есть `IsHTTPSOrigin` с `panic("TODO")`. Добавь импорт `"net/url"`.
2. Разбери строку через `url.Parse(raw)`. Если ошибка, верни `false`.
3. Проверь три условия: адрес абсолютный (`IsAbs`), схема равна `https`, хост не пустой.
4. Верни `true`, если все три выполнены, иначе `false`.
5. Нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Два значения: `true` и `false`; все три критерия зелёные.

**Если не принято.**
- Относительный адрес `/relative` принят → проверка `IsAbs` отсутствует.
- Адрес `https://` принят → пустой хост должен давать `false`.
- Адрес с логином и паролем отвергнут → `userinfo` для этой функции не запрещён: проверка касается только схемы и хоста.

> **Подсказка.** Три условия через `&&`, и первое из них — успешный разбор.

### Задание 2 · Отдели HTTPS transport от HTTP

**Цель.** Для точной схемы `https` вернуть `tls-required`, для `http` — `tls-not-used`. Любая другая строка — `unsupported-scheme`.

**Ожидаемый вывод** — входы `https` и `http`:

```text
"tls-required"
"tls-not-used"
```

**Шаги.**
1. Выбери задание «Отдели HTTPS transport от HTTP»: в файле есть `TLSBoundary` с `panic("TODO")`.
2. Сравни строку `scheme` с `"https"` точно, без приведения регистра.
3. Если совпало, верни `tls-required`.
4. Если равно `"http"`, верни `tls-not-used`.
5. Иначе верни `unsupported-scheme`.
6. Нажми «Запустить» и сравни с блоком выше.
7. Нажми «Проверить».

**Как проверить себя.** Две строки в кавычках: `"tls-required"` и `"tls-not-used"`; все три критерия зелёные.

**Если не принято.**
- `HTTPS` в верхнем регистре принят как `tls-required` → сравнение должно быть точным.
- Пустая схема даёт `tls-not-used` → пустая строка относится к другой ветке.

> **Подсказка.** Один `switch` с тремя ветками и значением по умолчанию.

### Задание 3 · Выбери безопасную URL scheme

**Цель.** Разобрать абсолютный URL. Для `https` с хостом без `userinfo` вернуть `https-selected`; для `http` с хостом без `userinfo` — `https-required`. Отсутствующая схема, пустой хост, `userinfo` или ошибка разбора дают `invalid-url`. Любая другая схема — `unsupported-scheme`.

**Ожидаемый вывод** — входы `https://api.example.test/a` и `http://example.test/`:

```text
"https-selected"
"https-required"
```

**Шаги.**
1. Выбери задание «Выбери безопасную URL scheme»: в файле есть `RequireHTTPS` с `panic("TODO")`. Добавь импорт `"net/url"`.
2. Разбери строку через `url.Parse`. Ошибка разбора — `invalid-url`.
3. Если схемы нет, хост пустой или есть `u.User`, верни `invalid-url`.
4. Для `https` верни `https-selected`, для `http` — `https-required`.
5. Иначе верни `unsupported-scheme`.
6. Нажми «Запустить» и сравни с блоком выше.
7. Нажми «Проверить».

**Как проверить себя.** Две строки в кавычках: `"https-selected"` и `"https-required"`; все три критерия зелёные.

**Если не принято.**
- Адрес `https://user:pass@example.test/` даёт `https-selected` → проверка `u.User` должна стоять до выбора схемы.
- Для `/relative` выходит `unsupported-scheme` → отсутствующая схема относится к `invalid-url`, а не к неподдерживаемой.
- Для `ftp://example.test/` выходит `invalid-url` → у этого адреса есть схема, хост и нет `userinfo`; это `unsupported-scheme`.

> **Подсказка.** Сначала отказы по форме адреса, потом выбор по схеме.
