# Интерфейсы и композиция

## Что ты сделаешь

Ты напишешь три функции, которые работают с источником данных и правилом проверки: `canRead` скажет, есть ли источник, `validateName` проверит имя по правилам и вернёт ошибку, `readAll` прочитает весь поток до конца. Каждая функция маленькая, и вместе они показывают композицию: большая программа собирается из простых частей.

## Интерфейс: поведение без привязки к типу

Интерфейс описывает набор методов. Тип удовлетворяет интерфейсу, если у него есть эти методы: объявлять «реализацию» не нужно. Стандартный `io.Reader` требует метод `Read`. Поэтому и строка, и файл, и сеть подходят под один и тот же параметр:

```go
package main

import (
    "fmt"
    "io"
    "strings"
)

func main() {
    var r io.Reader = strings.NewReader("Go")
    data, err := io.ReadAll(r)
    fmt.Println(string(data), err)
}
```

Вывод: `Go` и `nil` (ошибки нет). Функция `io.ReadAll` не знает, откуда пришли байты. Она работает только с тем, что обещает интерфейс.

> **Важно.** Проверка `r != nil` относится к самому интерфейсу. Нулевой интерфейс — это отсутствие источника, и он отличается от любого конкретного значения.

## Nil-интерфейс и типизированный nil

Интерфейс хранит пару «тип и значение». Пустой интерфейс — это пара из двух пустых частей. Если в интерфейс положить `nil`-указатель, тип уже задан, и интерфейс перестаёт быть пустым:

```go
package main

import (
    "fmt"
    "io"
    "strings"
)

func main() {
    var missing io.Reader
    var sr *strings.Reader
    var typed io.Reader = sr
    fmt.Println(missing == nil, sr == nil, typed == nil)
}
```

Вывод: `true true false`. Указатель `sr` равен `nil`, но интерфейс `typed` с этим указателем внутри — нет.

> **Типичная ошибка.** Вернуть `nil`-указатель как `error` или `io.Reader` и проверять результат на `nil`. Проверка пройдёт мимо, и дальше программа упадёт при первом обращении к значению.

## Композиция: маленькие части

Функции, которые принимают интерфейсы, легко соединять. Вот функция, которая не знает, что читает: она получает `io.Reader` и возвращает длину содержимого:

```go
package main

import (
    "fmt"
    "io"
    "strings"
)

func length(r io.Reader) (int, error) {
    data, err := io.ReadAll(r)
    return len(data), err
}

func main() {
    n, err := length(strings.NewReader("привет"))
    fmt.Println(n, err)
}
```

Вывод: `12` и `nil` (ошибки нет). `len` считает байты, а не символы: кириллица занимает два байта на букву. Об этом уже говорилось в главе про руны.

## Если что-то пошло не так

- `cannot use r (variable of type *strings.Reader) as io.Reader value` → у типа не хватает метода. Проверь, что передаёшь именно значение, которое реализует `Read`.
- Проверка `== nil` всегда ложна → в интерфейс положен `nil`-указатель. Проверяй интерфейс до присваивания конкретного типа.
- `imported and not used: io` → импорт есть, а тип из пакета не используется в сигнатуре или коде.
- `missing return` → в одной из веток функция не возвращает значение.

## Практика

Три задания. Функции проверяются на входах из блока «Ожидаемый вывод»; закрытые примеры видны только в «Проверить».

### Задание 1 · Подключи источник поведения

**Цель.** Вернуть `true`, если интерфейс `Reader` не `nil`, и `false` иначе.

**Ожидаемый вывод** — «Запустить» вызывает `canRead` с настоящим источником и с `nil`-интерфейсом:

```text
true
false
```

**Шаги.**
1. Выбери задание «Подключи источник поведения»: в файле есть `canRead` с `return false`.
2. Проверь сам интерфейс: `return r != nil`.
3. Нажми «Запустить» и сравни с блоком выше.
4. Нажми «Проверить».

**Как проверить себя.** Два значения: `true` и `false`; все три критерия зелёные.

**Если не принято.**
- Для настоящего источника выходит `false` → условие перевёрнуто или проверка не сделана.
- Закрытый пример с отсутствующим источником даёт `true` → проверяется не интерфейс, а значение внутри него.

> **Подсказка.** Один оператор сравнения с `nil` внутри функции.

### Задание 2 · Проверь имя по правилам

**Цель.** После `strings.TrimSpace` имя не должно быть пустым. Разрешены только буквы, цифры и пробельные символы внутри имени. Для нарушений вернуть ошибку.

**Ожидаемый вывод** — входы `Ada` и три пробела:

```text
true
false
```

`true` значит: имя проходит проверку, `false` — не проходит.

**Шаги.**
1. Выбери задание «Проверь имя по правилам»: в файле есть `validateName` с `panic("TODO")`. Замени тело функции.
2. Добавь нужные импорты: `"errors"`, `"strings"`, `"unicode"`, только если используешь.
3. Обрежь края: `strings.TrimSpace(s)`. Если результат пустой, верни ошибку.
4. Пройди по символам через `range` и для каждого символа проверь: это буква (`unicode.IsLetter`), цифра (`unicode.IsDigit`) или пробел (`unicode.IsSpace`). Иначе верни ошибку.
5. Иначе верни `nil`.
6. Нажми «Запустить» и сравни с блоком выше.
7. Нажми «Проверить».

**Как проверить себя.** `true` для `Ada` и `false` для трёх пробелов; все три критерия зелёные.

**Если не принято.**
- Имя `Ada!` проходит → знаки препинания не запрещены: проверь каждый символ.
- Имя из одних табуляций проходит → проверка пустоты должна идти после обрезки всех пробельных символов.
- Закрытый пример с буквами кириллицы не совпал → `unicode.IsLetter` понимает и кириллицу; дополнительных правил не нужно.

> **Подсказка.** Сначала обрежь края и проверь пустоту, потом перебирай символы.

### Задание 3 · Прочитай весь поток

**Цель.** Прочитать поток до конца и вернуть текст и `nil`, если чтение прошло без ошибки.

**Ожидаемый вывод** — входы: поток `Go` и пустой поток:

```text
"Go"
""
```

**Шаги.**
1. Выбери задание «Прочитай весь поток»: в файле есть `readAll` с `return "", nil`. Добавь импорт `"io"`, если его нет.
2. Прочитай всё: `data, err := io.ReadAll(r)`.
3. Верни `string(data)` и `err`.
4. Нажми «Запустить» и сравни с блоком выше.
5. Нажми «Проверить».

**Как проверить себя.** Две строки в кавычках: `"Go"` и `""`; все три критерия зелёные.

**Если не принято.**
- Для пустого потока выходит что-то другое → `io.ReadAll` возвращает пустой срез, а не ошибку: проверь, что не добавляешь текст сам.
- Ошибка чтения потеряна → верни `err` вместе со строкой, а не проверку опусти.

> **Подсказка.** `io.ReadAll` возвращает срез байтов: переведи его в строку через `string(data)`.

## Итог

- Интерфейс описывает поведение: тип подходит, если у него есть нужные методы, без объявления реализации.
- Проверка `== nil` относится к интерфейсу; `nil`-указатель внутри интерфейса даёт не `nil`.
- Маленькие функции с интерфейсами соединяются легко: `io.ReadAll` работает с любым источником.
