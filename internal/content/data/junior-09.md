# Алгоритмы и рост затрат

## Что ты сделаешь

Ты напишешь три функции поиска: `maxValue` найдёт максимум за один проход, `linearSearch` найдёт первое совпадение, перебирая срез по порядку, а `binarySearch` найдёт индекс в отсортированном срезе, отбрасывая половину на каждом шаге. Главный вопрос урока — как меняется работа при росте входа, а не только то, верен ли ответ.

## Рост затрат: сколько шагов на большом входе

Затраты описывают не секунды на одном входе, а то, как растёт работа при увеличении входа. Линейный проход по `n` элементам делает около `n` шагов. Если вход вырос вдвое, шагов стало вдвое больше:

```go
package main

import "fmt"

func countSteps(n int) int {
    steps := 0
    for i := 0; i < n; i++ {
        steps++
    }
    return steps
}

func main() {
    fmt.Println(countSteps(4), countSteps(8))
}
```

Вывод: `4 8`. Число шагов растёт вместе с входом.

> **Важно.** Один замер на маленьком входе скрывает рост. Программа, которая на тысяче элементов работает мгновенно, на миллионе может стать непригодной, хотя на маленьком входе она казалась быстрой.

## Деление пополам

Если каждый шаг отбрасывает половину входа, шагов нужно около `log2(n)`. Для 1024 элементов это 10 шагов, а не 1024:

```go
package main

import "fmt"

func halvings(n int) int {
    steps := 0
    for n > 1 {
        n /= 2
        steps++
    }
    return steps
}

func main() {
    fmt.Println(halvings(8), halvings(1024))
}
```

Вывод: `3 10`. Восемь делится на 4, 2 и 1 — три шага.

## Условие двоичного поиска

Деление пополам работает только по отсортированному срезу. По середине видно, с какой стороны может быть цель: если значение в середине меньше искомого, искать надо справа, иначе слева. Без порядка середина ничего не говорит о соседних элементах.

Отрезок поиска задают двумя границами `lo` и `hi`. Когда `lo` становится больше `hi`, отрезок пуст: значения в нём нет, и ответ `-1`.

> **Типичная ошибка.** Двоичный поиск по неотсортированному срезу. Он может пропустить значение, которое есть. Проверяй порядок входа, если контракт его гарантирует, или используй линейный поиск.

## Если что-то пошло не так

- `index out of range` при поиске → граница `hi` выходит за `len-1`; для пустого среза `hi` должен быть на единицу меньше длины.
- Бесконечный цикл в двоичном поиске → граница не сдвигается после сравнения: `lo` или `hi` должны меняться на единицу мимо середины.
- Линейный поиск возвращает последний индекс → цикл не останавливается на первом совпадении.
- `declared and not used` → переменная поиска осталась без использования: проверь, что ответ возвращается.

### Задание 1 · Найди максимум за проход

**Цель.** Найти максимум за один проход по срезу. Для пустого входа вернуть `0` и `false`.

**Ожидаемый вывод** — входы: срез `2, 7, 1`, затем пустой срез. «Запустить» печатает результат как объект с полями `Value` и `OK`:

```text
{"Value":7,"OK":true}
{"Value":0,"OK":false}
```

**Шаги.**
1. Выбери задание «Найди максимум за проход»: в файле есть `maxValue` с `panic("TODO")`.
2. Для пустого среза верни `0, false`.
3. Возьми первый элемент как начальный максимум.
4. Пройди по остальным элементам с индекса 1 и обнови максимум, если элемент больше.
5. Верни максимум и `true`.
6. Нажми «Запустить» и сравни с блоком выше.
7. Нажми «Проверить».

**Как проверить себя.** Два объекта: `{"Value":7,"OK":true}` и `{"Value":0,"OK":false}`; все три критерия зелёные.

**Если не принято.**
- Для отрицательных чисел максимум 0 → начальный максимум взят из нуля, а не из первого элемента.
- Пустой срез падает с паникой → проверка длины должна идти до обращения к `values[0]`.
- Закрытый пример с `[0, 0]` возвращает `OK` равное `false` → непустой срез даёт `true`, даже если все элементы нулевые.

> **Подсказка.** Один цикл с одним условием `if v > max`.

### Задание 2 · Найди в отсортированном срезе

**Цель.** В отсортированном по возрастанию срезе вернуть индекс найденного значения, иначе `-1`.

**Ожидаемый вывод** — входы: срез `1, 4, 8, 12` с целью `8`, затем срез `2, 5` с целью `3`:

```text
2
-1
```

**Шаги.**
1. Выбери задание «Найди в отсортированном срезе»: в файле есть `binarySearch` с `panic("TODO")`.
2. Задай границы отрезка: `lo := 0`, `hi := len(sorted) - 1`.
3. Пока `lo <= hi`, возьми середину `mid` и сравни её значение с целью.
4. Если нашёл, верни `mid`. Если значение в середине меньше цели, сдвинь `lo` вправо, иначе сдвинь `hi` влево.
5. Если отрезок опустел, верни `-1`.
6. Нажми «Запустить» и сравни с блоком выше.
7. Нажми «Проверить».

**Как проверить себя.** Два числа: `2` и `-1`; все три критерия зелёные.

**Если не принято.**
- Для пустого среза паника → при `len == 0` `hi` равен `-1`; цикл не должен начинаться.
- Цикл не заканчивается → на каждом шаге `lo` или `hi` должны сдвигаться за середину.
- Совпадение в конце среза не находится → проверь, что `hi` задан как `len - 1`, а не `len - 2`.

> **Подсказка.** Середину считай как `lo + (hi-lo)/2`: так не будет переполнения на очень больших индексах.

### Задание 3 · Сравни два поиска

**Цель.** Линейно перебрать срез и вернуть индекс первого совпадения. Если совпадения нет, вернуть `-1`.

**Ожидаемый вывод** — входы: срез `9, 2, 4` с целью `2`, затем срез `1` с целью `3`:

```text
1
-1
```

**Шаги.**
1. Выбери задание «Сравни два поиска»: в файле есть `linearSearch` с `panic("TODO")`.
2. Пройди по `values` по индексам: `for i := range values`.
3. Если `values[i] == target`, верни `i`: это первое совпадение.
4. Если цикл закончился, верни `-1`.
5. Нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Два числа: `1` и `-1`; все три критерия зелёные.

**Если не принято.**
- Для `[2, 2]` с целью 2 вернулся индекс 1 → цикл должен остановиться на первом совпадении.
- Пустой срез падает → цикл по пустому срезу не выполняется, проверка длины не нужна.
- Закрытый пример с нулевой целью не совпал → сравнивай значения, а не булевы флаги.

> **Подсказка.** Возврат из функции внутри цикла останавливает весь поиск сразу.

## Итог

- Рост затрат — то, как работа увеличивается при росте входа; один быстрый замер этого не показывает.
- Двоичный поиск отбрасывает половину на каждом шаге и требует порядка во входе.
- Линейный поиск проще и не требует порядка, но растёт вместе с входом.
