# Пароли, сессии и authentication

## Что ты сделаешь

Ты напишешь три проверки, которые относятся к безопасности входа: `PasswordKDFPolicy` проверит параметры хеширования пароля, `SessionExpired` решит, истекла ли сессия по переданному времени, `AllowCookieMutation` разрешит изменение данных только при доверенной политике. Функции не выполняют вход и не хешируют пароли: они проверяют конфигурацию и решения.

## Пароль хранят не как есть

Пароль нельзя хранить в базе как текст: при утечке он раскрывается сразу. Вместо него хранят результат медленной функции — производной ключа (KDF), например PBKDF2, с солью. Соль случайна и уникальна для каждого пароля, поэтому одинаковые пароли дают разные записи. Параметры (число итераций, длина соли, длина результата) сохраняют рядом с хешем, чтобы их можно было менять со временем.

Ниже пример проверки, что параметры не слишком слабые:

```go
package main

import "fmt"

func atLeast(value, minimum int) bool {
    return value >= minimum
}

func main() {
    fmt.Println(atLeast(600000, 600000), atLeast(15, 16))
}
```

Вывод: `true false`. Слишком короткая соль не проходит, даже если итераций достаточно.

> **Важно.** Проверка параметров — это конфигурация, а не доказательство безопасности. Она не заменяет выбор проверенного алгоритма.

## Сессия: срок и время

Сессия живёт до определённого момента. Истечение проверяют, передавая текущее время аргументом. Тогда тест подставляет любое время без ожидания:

```go
package main

import (
    "fmt"
    "time"
)

func main() {
    now := time.Date(2026, 10, 15, 10, 0, 0, 0, time.UTC)
    expires := now
    fmt.Println(!expires.After(now))
}
```

Вывод: `true`. Срок, который наступил ровно сейчас, уже истёк.

## Cookie и флаги

Токен сессии передают в cookie. Флаги задают границы: `HttpOnly` не даёт скрипту страницы прочитать cookie, `Secure` разрешает отправку только по HTTPS, `SameSite` ограничивает отправку с чужих сайтов:

```go
package main

import (
    "fmt"
    "net/http"
)

func main() {
    c := &http.Cookie{
        Name:     "session",
        Value:    "opaque",
        HttpOnly: true,
        Secure:   true,
        SameSite: http.SameSiteLaxMode,
        Path:     "/",
    }
    fmt.Println(c.HttpOnly, c.Secure, c.SameSite == http.SameSiteLaxMode)
}
```

Вывод: `true true true`. Значение cookie — непрозрачный токен, а не данные пользователя.

> **Типичная ошибка.** Класть в cookie роль или идентификатор пользователя. Клиент может подменить такое значение, поэтому сервер должен искать сессию по случайному токену.

## Изменение данных и CSRF

Аутентификация отвечает на вопрос «кто это». Защита от CSRF отвечает на другой вопрос: «запрос действительно сделан из нашего интерфейса». Cookie отправляются браузером автоматически, поэтому чужая страница может вызвать запрос от имени пользователя. Изменяющие методы (`POST`, `PUT`, `PATCH`, `DELETE`) требуют проверки CSRF-токена и доверенного `Origin`. Безопасные методы (`GET`, `HEAD`) данных не меняют и такой проверки не требуют.

## Если что-то пошло не так

- Пароль или его фрагмент попал в журнал → журнал не должен получать значения секретов; записывай только события.
- Сессия не истекает после выхода → revoke не удаляет или не помечает токен на сервере.
- Изменяющий запрос проходит без CSRF-токена → проверка токена отсутствует для метода.
- `undefined: http` → импорт `"net/http"` не добавлен.

Три задания. Функции проверяются на входах из блока «Ожидаемый вывод»; закрытые примеры видны только в «Проверить». Ни одна функция не хеширует и не проверяет токены.

### Задание 1 · Проверь параметры password KDF baseline

**Цель.** Вернуть `true`, если число итераций от 600000 до 1200000 включительно, соль не короче 16 байт, а результат ровно 32 байта.

**Ожидаемый вывод** — входы: 600000 итераций, соль 16 байт, результат 32 байта, затем 700000 итераций, соль 24 байта, результат 32 байта:

```text
true
true
```

**Шаги.**
1. Выбери задание «Проверь параметры password KDF baseline»: в файле есть `PasswordKDFPolicy` с `panic("TODO")`.
2. Проверь, что `iterations` не меньше 600000 и не больше 1200000.
3. Проверь, что `saltBytes` не меньше 16.
4. Проверь, что `outputBytes` равно 32 точно.
5. Верни `true`, если все три условия выполнены, иначе `false`.
6. Нажми «Запустить» и сравни с блоком выше.
7. Нажми «Проверить».

**Как проверить себя.** `true` и `true`; все три критерия зелёные.

**Если не принято.**
- 1200001 итераций принято → верхняя граница включительна до 1200000.
- Результат 33 байта принят → длина результата проверяется точно, а не минимумом.
- Соль 15 байт принята → нижняя граница 16 включительно.

> **Подсказка.** Три отдельных условия через `&&`; каждое соответствует строке контракта.

**Ожидаемый вывод** — входы: срок через минуту после `now`, затем срок равный `now`. Время в формате RFC 3339:


**Шаги.**
1. Выбери задание «Проверь expiry с injected clock»: в файле есть `SessionExpired` с `panic("TODO")`. Импорт `"time"` уже есть.

4. Верни результат сравнения.
5. Нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** `false` и `true`; все три критерия зелёные.

**Если не принято.**
- Срок ровно в момент `now` даёт `false` → граница включительна: равенство означает истечение.
- Срок, прошедший на секунду, даёт `false` → сравнение идёт по времени, а не по минутам.
- Время с часовым поясом сравнивается неверно → сравнивай значения `time.Time` напрямую, без текста.

> **Подсказка.** `expiresAt.After(now)` — истина, пока сессия жива; её отрицание даёт истечение.

## Итог

- Пароль хранят как результат медленной KDF с солью; параметры сохраняются рядом, чтобы их можно было обновлять.
- Срок сессии проверяется по переданному времени; истечение наступает, когда срок не позже текущего момента.
- Изменяющие методы требуют CSRF-токена и доверенного `Origin`; безопасные методы данные не меняют.
