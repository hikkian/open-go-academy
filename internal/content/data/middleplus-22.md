# Canary rollout, остановка и rollback

## Что ты сделаешь

Ты разберёшь, как выпускать новую версию на малую долю трафика и принимать решение «расширить, держать, остановить, откатить» по заранее заданному правилу, а не по ощущению от графика. Поймёшь, почему отсутствие ошибок на десяти запросах ничего не доказывает, почему откат готовят до выпуска и что делать, когда отката нет. Три функции урока — `RolloutAction`, `CanaryDecision`, `ContinueRollout` — применяют политику к снимку; трафик они не переключают и откат не запускают.

## Зачем нужна эта граница

Канареечный выпуск (canary rollout) направляет ограниченную долю запросов или выбранную группу пользователей на новую версию, пока её сигналы сравниваются с текущей. Решение имеет смысл только при трёх условиях: порог записан до выпуска; телеметрия новой версии работает; выборка достаточна, чтобы порог вообще можно было проверить. Нет метрик — не «ошибок нет», а «ничего не известно»; десять запросов без ошибок при пороге один процент — тоже ничего не известно.

Сравнивают одинаковые индикаторы в сопоставимых окнах: ошибки, задержку, насыщение ресурсов — у новой версии и у текущей, на одинаковом трафике. Если новая версия меняет схему данных или уже записанные данные, откат должен быть совместим с этим состоянием — иначе «откат» сам станет инцидентом. Поэтому готовность отката — входное условие выпуска, а не действие после.

```go group=action mode=run
package main

import "fmt"

func rolloutAction(errorPercent, threshold, sampleCount, minimumSample int, evidenceReady bool) string {
    if errorPercent < 0 || errorPercent > 100 || threshold < 0 || threshold > 100 || sampleCount < 0 || minimumSample <= 0 {
        return "invalid"
    }
    if !evidenceReady || sampleCount < minimumSample {
        return "hold"
    }
    if errorPercent > threshold {
        return "rollback"
    }
    return "expand"
}

func main() {
    fmt.Println(rolloutAction(1, 5, 120, 100, true), rolloutAction(1, 5, 99, 100, true), rolloutAction(6, 5, 100, 100, true))
    fmt.Println(rolloutAction(5, 5, 100, 100, true), rolloutAction(1, 5, 100, 100, false), rolloutAction(1, 5, 100, 0, true))
}
```

Вывод:

```text
expand hold rollback
expand hold invalid
```

Ошибки ровно на пороге — ещё `expand`: граница включительная, и она записана в политике, а не выбрана после. Недостаточная выборка и отсутствие телеметрии дают одно и то же — `hold`: ждём данных, не расширяем и не откатываем. Минимальная выборка ноль — некорректная политика: «достаточно» не бывает при нуле.

> **Важно.** `hold` — не бездействие, а решение с ограничением по времени: если за отведённый срок выборка не набралась, причина — слишком малая доля трафика или сломанная телеметрия, и обе требуют действия.

## Когда откат невозможен

Превышение порога при готовом откате — откат. Но откат бывает не готов: миграция данных необратима, предыдущая версия уже удалена, откат не проверен на стенде. Тогда решение — остановить расширение и держать текущую долю, пока откат не подготовят или проблему не исправят вперёд. Это отдельный исход, `stop`, и его не следует маскировать под `hold`: причины разные, действия разные.

```go group=decision mode=run
package main

import "fmt"

func canaryDecision(errorPercent, threshold, sampleCount, minimumSample int, evidenceReady, rollbackReady bool) string {
    if errorPercent < 0 || errorPercent > 100 || threshold < 0 || threshold > 100 || sampleCount < 0 || minimumSample <= 0 {
        return "invalid"
    }
    if !evidenceReady || sampleCount < minimumSample {
        return "insufficient"
    }
    if errorPercent > threshold {
        if rollbackReady {
            return "rollback"
        }
        return "stop"
    }
    return "expand"
}

func main() {
    fmt.Println(canaryDecision(1, 5, 120, 100, true, true), canaryDecision(6, 5, 100, 100, true, true), canaryDecision(6, 5, 100, 100, true, false))
    fmt.Println(canaryDecision(1, 5, 99, 100, true, true), canaryDecision(5, 5, 100, 100, true, true), canaryDecision(101, 5, 100, 100, false, true))
}
```

Вывод:

```text
expand rollback stop
insufficient expand invalid
```

Порядок проверок: валидность, достаточность свидетельств, порог, готовность отката. Некорректный процент — `invalid` даже при отсутствии телеметрии: ошибку входа не прячут за «недостаточно данных».

> **Типичная ошибка.** Расширять выпуск при превышении порога, «потому что откат не готов и всё равно ничего не сделать». Остановка — действие: она не увеличивает радиус поражения.

## Инвариант расширения

Расширять долю можно только при полном наборе условий одновременно: входы корректны, телеметрия есть, откат готов, выборка не меньше минимума, ошибки не выше порога. Любой пробел — не расширять. Это инвариант, который проверяют автоматикой перед каждым шагом выпуска, и он строже политики: `CanaryDecision` может сказать `expand` без готового отката, инвариант — нет.

```go group=invariant mode=run
package main

import "fmt"

func continueRollout(errorPercent, threshold, sampleCount, minimumSample int, evidenceReady, rollbackReady bool) bool {
    if errorPercent < 0 || errorPercent > 100 || threshold < 0 || threshold > 100 || sampleCount < 0 || minimumSample <= 0 {
        return false
    }
    return evidenceReady && rollbackReady && sampleCount >= minimumSample && errorPercent <= threshold
}

func main() {
    fmt.Println(continueRollout(1, 5, 120, 100, true, true), continueRollout(5, 5, 100, 100, true, false), continueRollout(6, 5, 100, 100, true, true))
    fmt.Println(continueRollout(1, 5, 99, 100, true, true), continueRollout(0, 0, 1, 1, true, true), continueRollout(100, 100, 1, 1, true, true))
}
```

Вывод:

```text
true false false
false true true
```

Второй случай: ошибки на пороге, но откат не готов — расширять нельзя. Последние два — крайние значения политики: порог ноль с нулём ошибок и порог сто со ста процентами ошибок формально проходят; это показывает, что инвариант проверяет политику, а не здравый смысл порога — порог выбирает человек.

> **Зачем.** Автоматический выпуск — это цикл «шаг → наблюдение → инвариант → следующий шаг»; инвариант, записанный как функция, не даст пропустить шаг «наблюдение», когда все торопятся.

## Выборка, окно и доля трафика

Минимальная выборка следует из порога: чтобы увидеть один процент ошибок, нужны сотни запросов, чтобы отличить один процент от полутора — тысячи. Доля трафика на канарейку и длительность шага выбирают так, чтобы выборка набралась за разумное время: один процент трафика при десяти запросах в секунду даёт минимальную выборку в сотню за семнадцать минут. Окно сравнения у канарейки и у текущей версии одно и то же, иначе разница окон объяснит любую разницу в ошибках.

Отдельно оценивают, что канарейка видит репрезентативный трафик: если новая версия получает только внутренних пользователей или только один регион, её метрики не говорят о производственной нагрузке. И помнят про долгие эффекты: утечка памяти или рост очереди проявляются через часы, а не через первую минуту шага.

## Откат как отдельный выпуск

Откат — тоже изменение в production, и к нему применяют те же правила: он должен быть проверен на стенде, совместим с данными, записанными новой версией, и наблюдаем теми же индикаторами. Самая частая ловушка — миграция схемы: новая версия добавила колонку и начала её заполнять, старая версия её не знает; откат кода без отката данных работает, откат данных теряет записи. Поэтому миграции делают в два шага — расширение схемы совместимо с обеими версиями, сужение откладывают до тех пор, пока старая версия не станет ненужной, — и признак «откат готов» означает, что оба шага проверены.

## Практическая процедура

Запиши для выпуска: индикаторы и порог; минимальную выборку и расчёт, откуда она; долю трафика и длительность шага; признак готовности телеметрии и как он проверяется; признак готовности отката и что входит в его проверку; действия для каждого исхода — расширить, держать с предельным сроком, остановить, откатить — и кто их выполняет. Затем проверь таблицей входов функции урока на крайних значениях: ошибки ровно на пороге, выборка ровно минимальная, откат не готов при превышении.

## Типичные ошибки

- Порог выбран после первых метрик: любой результат «в норме».
- Отсутствие телеметрии принято за отсутствие ошибок.
- Выборка в десятки запросов при пороге в проценты.
- Откат не проверен до выпуска; миграция необратима.
- Расширение при превышении порога из-за неготового отката.
- Разные окна или нерепрезентативный трафик у канарейки.

## Самостоятельная лаборатория

Собери две версии учебного сервиса, одна из которых отвечает ошибкой на два процента запросов, и шлюз, который делит трафик по доле. Реализуй цикл выпуска по функциям урока: шаг, набор выборки, решение, следующий шаг или откат. Запусти с порогом один процент и покажи, что выпуск откатывается только после набора минимальной выборки, а не на первой ошибке; затем с порогом три процента — что расширяется. Выключи телеметрию новой версии и убедись, что цикл держит долю, а не расширяет. Удали стенд.

## Если что-то пошло не так

- `rollback` при ошибках на пороге → граница включительная: `>` для отката.
- `hold` при проценте 101 → валидность проверяется первой.
- `expand` без телеметрии → свидетельства проверяются до порога.
- `rollback` при неготовом откате в задании 2 → нужен `stop`.
- `true` в задании 3 без готового отката → инвариант требует все условия.
- `import … is not allowed` → импорты запрещены.

## Практика

Три функции без `main` и печати; среда показывает результаты строками в кавычках и `bool`. Входы — снимок выпуска; функции не переключают трафик и не запускают откат.

### Задание 1 · Easy: canary rollout, остановка и rollback — классификация

**Цель.** Проценты вне `[0, 100]`, `sampleCount < 0` или `minimumSample ≤ 0` → `invalid`; нет свидетельств или выборка меньше минимума → `hold`; `errorPercent > threshold` → `rollback`; иначе `expand`.

**Ожидаемый вывод** — для `(1, 5, 120, 100, true)` и `(1, 5, 99, 100, true)`:

```text
"expand"
"hold"
```

**Шаги.**
1. Выбери задание «Easy»: сигнатура `func RolloutAction(errorPercent int, threshold int, sampleCount int, minimumSample int, evidenceReady bool) string`. Импорты запрещены.
2. Валидность → `hold` → `rollback` → `expand`.
3. «Запустить», «Проверить» — закрытые примеры: 6 при пороге 5 → `rollback`; 5 при 5 → `expand`; нет телеметрии → `hold`; `minimumSample = 0` → `invalid`; порог 0 с нулём ошибок и порог 100 со ста → `expand`.

**Как проверить себя.** Равенство порогу допускает расширение; недостаточная выборка и отсутствие телеметрии неразличимы для этой функции — оба `hold`.

**Если не принято.**
- `rollback` при равенстве → `>=` вместо `>`.
- `hold` для `minimumSample = 0` → ноль — некорректная политика.

> **Подсказка.** Четыре `return` в порядке условия; обе границы процентов включительные.

### Задание 2 · Medium: canary rollout, остановка и rollback — политика

**Цель.** После проверки диапазонов: нет свидетельств или выборка меньше минимума → `insufficient`; превышение порога → `rollback` при готовом откате, иначе `stop`; в пределах порога → `expand`.

**Ожидаемый вывод** — для `(1, 5, 120, 100, true, true)` и `(6, 5, 100, 100, true, true)`:

```text
"expand"
"rollback"
```

**Шаги.**
1. Выбери задание «Medium»: сигнатура `func CanaryDecision(errorPercent int, threshold int, sampleCount int, minimumSample int, evidenceReady bool, rollbackReady bool) string`. Импорты запрещены.
2. Валидность как в задании 1; `insufficient`; затем при превышении — развилка по `rollbackReady`; иначе `expand`.
3. «Запустить», «Проверить» — закрытые примеры: превышение без отката → `stop`; выборка 99 из 100 → `insufficient`; процент 101 без телеметрии → `invalid`.

**Как проверить себя.** `stop` появляется только при превышении порога и неготовом откате; некорректный вход не маскируется отсутствием данных.

**Если не принято.**
- `rollback` при `rollbackReady = false` → развилка пропущена.
- `insufficient` при проценте 101 → валидность должна быть первой.

> **Подсказка.** Задание 1 с переименованным `hold` и одной развилкой внутри ветки превышения.

### Задание 3 · Hard: canary rollout, остановка и rollback — проверка инварианта

**Цель.** `true` только если входы корректны, `evidenceReady`, `rollbackReady`, `sampleCount ≥ minimumSample > 0` и `errorPercent ≤ threshold`; любой пробел → `false`.

**Ожидаемый вывод** — для `(1, 5, 120, 100, true, true)` и `(5, 5, 100, 100, true, false)`:

```text
true
false
```

**Шаги.**
1. Выбери задание «Hard»: сигнатура `func ContinueRollout(errorPercent int, threshold int, sampleCount int, minimumSample int, evidenceReady bool, rollbackReady bool) bool`. Импорты запрещены.
2. Диапазоны → `false`; затем одно выражение из четырёх условий через `&&`.
3. «Запустить», «Проверить» — закрытые примеры: превышение → `false`; выборка 99 → `false`; нет телеметрии или отката → `false`; крайние пороги 0/0 и 100/100 → `true`.

**Как проверить себя.** Инвариант строже политики: без готового отката расширять нельзя даже в пределах порога.

**Если не принято.**
- `true` без готового отката → условие пропущено.
- `false` при ошибках на пороге с готовым откатом → нужно `<=`.

> **Подсказка.** Инвариант не выбирает действие — он только разрешает или запрещает следующий шаг.

## Итог

- Канареечный выпуск — цикл шагов с заранее записанными порогом, минимальной выборкой, окном и готовностью отката.
- Порядок решения: валидность, достаточность свидетельств, порог, готовность отката; `hold` и `stop` — разные исходы с разными причинами.
- Инвариант расширения требует всех условий сразу и проверяется автоматикой перед каждым шагом.
