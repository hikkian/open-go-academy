# Generics, обзор и проект P1 CLI Toolkit

## Что ты сделаешь

Ты напишешь три функции с параметрами типа: `identity` вернёт значение того же типа, `ApplyDiscount` посчитает цену со скидкой и вернёт ошибку при неверном проценте, `clampInt` ограничит значение диапазоном. Затем посмотришь, как главы этого курса собираются в проект P1 — небольшую программу командной строки.

## Параметр типа

Обычная функция работает с одним типом. Функция с параметром типа описывает поведение для нескольких типов сразу. В квадратных скобках объявляется параметр `T`, а вызывающая сторона подставляет настоящий тип:

```go
package main

import "fmt"

func first[T any](items []T) (T, bool) {
    var zero T
    if len(items) == 0 {
        return zero, false
    }
    return items[0], true
}

func main() {
    fmt.Println(first([]string{"go", "rust"}))
    fmt.Println(first([]int{}))
}
```

Вывод: `go true` и `0 false`. Тип `T` связывает вход и результат: для строк вернулась строка, для чисел — число. `var zero T` даёт нулевое значение нужного типа.

> **Важно.** `any` означает «любой тип», то есть внутри функции нельзя складывать или сравнивать значения. Если операция нужна, тип ограничивают.

## Ограничения типа

Ограничение (constraint) перечисляет типы, которые допустимы для `T`. Запись `~int | ~int64` разрешает целые типы и любые их именованные варианты. С таким ограничением оператор `+` уже работает:

```go
package main

import "fmt"

type Number interface {
    ~int | ~int64
}

func Sum[T Number](values []T) T {
    var total T
    for _, v := range values {
        total += v
    }
    return total
}

func main() {
    fmt.Println(Sum([]int{1, 2, 3}), Sum([]int64{}))
}
```

Вывод: `6 0`. Пустой список даёт нулевое значение `T` — то же самое, что и для обычного `int`.

> **Типичная ошибка.** Использовать generic там, где хватает обычной функции. Если логика работает только с одним типом, конкретный тип понятнее.

## Целочисленное деление и граница

Для целого `T` деление округляет вниз: `1250 * 80 / 100` даёт `1000` ровно, а `99 * 90 / 100` даёт `89`, без дробной части. Значение, которое выходит за допустимый диапазон, надо отвергать явно: скидка больше 100 процентов не имеет смысла.

## Если что-то пошло не так

- `T does not satisfy` или `operator + not defined` → ограничение не включает нужный тип или оператор. Добавь тип в ограничение.
- `cannot use zero (variable of type T)` → возвращаемый тип и тип значения должны совпадать.
- `imported and not used: errors` → импорт есть, а ошибка не создаётся.
- Результат со скидкой неожиданно целый → это целое деление, а не ошибка: дробной части у целого типа нет.

## Практика

Три задания. Функции проверяются на входах из блока «Ожидаемый вывод»; закрытые примеры видны только в «Проверить».

### Задание 1 · Примени готовый generic helper

**Цель.** Вернуть то же значение типа `T` без изменений. Generic должен сохранять тип.

**Ожидаемый вывод** — входы: число `1` и строка `"Go"` (в кавычках внутри), печатаются как JSON:

```text
1
"\"Go\""
```

**Шаги.**
1. Выбери задание «Примени готовый generic helper»: в файле есть функция `identity` с параметром типа `T` и `panic("TODO")`.
2. Замени тело функции на `return value`.
3. Нажми «Запустить» и сравни с блоком выше.
4. Нажми «Проверить».

**Как проверить себя.** Два значения; все три критерия зелёные.

**Если не принято.**
- Вместо значения возвращается нулевое значение → `return value`, а не `var zero T`.
- Закрытый пример с `null` или вложенным списком не совпал → функция не должна ничего преобразовывать: вернуть вход как есть.

> **Подсказка.** Одна строка `return value`: типы совпадают сами собой.

### Задание 2 · Реализуй ApplyDiscount

**Цель.** Для неотрицательной цены и процента от 0 до 100 вернуть `price * (100 - percent) / 100` с округлением вниз. Процент вне диапазона — нулевое значение и ошибка.

**Ожидаемый вывод** — входы: цена `1250` с процентом `20`, затем цена `100` с процентом `100`. Результат печатается как объект с полями `Value` и `OK`, где `OK` означает отсутствие ошибки:

```text
{"Value":1000,"OK":true}
{"Value":0,"OK":true}
```

**Шаги.**
1. Выбери задание «Реализуй ApplyDiscount»: в файле есть функция с ограничением `~int | ~int64` и `var zero T`. Добавь импорт `"errors"`, если используешь.
2. Если `percent < 0` или `percent > 100`, верни `zero` и ошибку.
3. Иначе верни `price * (100 - percent) / 100` и `nil`.
4. Нажми «Запустить» и сравни с блоком выше.
5. Нажми «Проверить».

**Как проверить себя.** Два объекта: `{"Value":1000,"OK":true}` и `{"Value":0,"OK":true}`; все три критерия зелёные.

**Если не принято.**
- Для процента 100 выходит не 0 → формула должна давать `100 - percent` без лишних множителей.
- Процент вне диапазона даёт число вместо ошибки → проверку границ делай до вычисления.
- Целое деление даёт неожиданное значение → оно округляет вниз, и это правило контракта.

> **Подсказка.** Проверка диапазона идёт первой, вычисление — после неё.

### Задание 3 · Сравни generic и typed решение

**Цель.** Ограничить `value` диапазоном от `low` до `high`, при условии что `low <= high`. Если значение ниже — вернуть `low`, выше — `high`, иначе само значение.

**Ожидаемый вывод** — входы: значение `5` в диапазоне `0..10`, затем значение `-1` в том же диапазоне:

```text
5
0
```

**Шаги.**
1. Выбери задание «Сравни generic и typed решение»: в файле есть `clampInt` с `return value`.
2. Если `value < low`, верни `low`.
3. Если `value > high`, верни `high`.
4. Иначе верни `value`.
5. Нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Два числа: `5` и `0`; все три критерия зелёные.

**Если не принято.**
- Значение выше диапазона возвращается как есть → проверка `value > high` отсутствует или стоит после возврата.
- Отрицательные границы дают неверный результат → сравнения работают с любыми целыми, дополнительных ветвей не нужно.

> **Подсказка.** Порядок проверок: сначала нижняя граница, потом верхняя.

## Проект P1: CLI Toolkit

Проект P1 собирает главы курса в программу командной строки: разбор аргументов из главы про пакеты, валидация записей и ошибки с обёрткой из главы про ошибки, чтение и запись JSON из главы про файлы. Тесты таблицами и граничные случаи из главы про тесты остаются обязательными. Проект проверяется автоматически по функциям и отдельно по качеству ревью: зелёная проверка не заменяет ручную оценку структуры и документации.
