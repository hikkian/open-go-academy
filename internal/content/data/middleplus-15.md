# Глубина очереди, возраст и задержка

## Что ты сделаешь

Ты научишься читать очередь не по одному числу: глубина говорит, сколько задач ждут, возраст самого старого элемента — как долго, а скорости входа и выхода — растёт ли ожидание. Три функции урока — `QueueBand`, `QueuePressure`, `QueueAction` — классифицируют снимок очереди с явным приоритетом сигналов; к реальной очереди они не подключены и временных отметок не собирают.

## Зачем нужна эта граница

Глубина очереди (queue depth) — моментальный счёт ожидающих элементов. Сама по себе она не говорит, как долго они ждут: пять коротких задач и пять задач, заблокированных на внешней зависимости, — одинаковая глубина и разный опыт пользователя. Возраст старейшего элемента добавляет время, а входящая и завершаемая скорости показывают направление: растёт очередь или рассасывается.

До чтения метрики определи точку учёта: входят ли в глубину задачи, уже взятые исполнителем; когда удаляется завершённая задача; относится ли предел к числу элементов, к памяти или к обоим. Одна средняя глубина за минуту скрывает и короткий пик, и давно зависший элемент — название метрики без границы и окна недостаточно.

```go group=band mode=run
package main

import "fmt"

func band(depth, capacity int) string {
    if depth < 0 || capacity <= 0 {
        return "invalid"
    }
    if depth == 0 {
        return "empty"
    }
    if depth >= capacity {
        return "full"
    }
    return "queued"
}

func main() {
    fmt.Println(band(0, 4), band(1, 4), band(4, 4), band(5, 4), band(-1, 4), band(0, 0))
}
```

Вывод:

```text
empty queued full full invalid invalid
```

Глубина выше вместимости — всё ещё `full`, а не ошибка: снимок мог быть снят, когда лимит уже превышен из-за гонки между проверкой и постановкой. Это сигнал посмотреть на реализацию границы, но не повод отвергать измерение.

> **Важно.** Глубина — число, возраст — время. Из одного нельзя вывести другое без скорости обработки, а скорость меняется.

## Возраст старейшего элемента

Возраст (age) самого старого ожидающего элемента — время с момента его постановки. Если возраст растёт при постоянной глубине, исполнители остановились; если глубина растёт при малом возрасте, всплеск входа, который пока разгребается. Порог возраста берут из контракта задержки: задача, прождавшая дольше срока вызывающего, уже бесполезна, и очередь, где такие задачи есть, в состоянии `stale`.

```go group=pressure mode=run
package main

import "fmt"

func pressure(depth, capacity, oldestSeconds, maxAgeSeconds int) string {
    if depth < 0 || capacity <= 0 || oldestSeconds < 0 || maxAgeSeconds <= 0 {
        return "invalid"
    }
    if depth == 0 {
        return "empty"
    }
    if depth >= capacity {
        return "full"
    }
    if oldestSeconds >= maxAgeSeconds {
        return "stale"
    }
    return "normal"
}

func main() {
    fmt.Println(pressure(1, 4, 59, 60), pressure(1, 4, 60, 60), pressure(4, 4, 1, 60), pressure(0, 4, 60, 60), pressure(4, 4, 60, 60))
}
```

Вывод:

```text
normal stale full empty full
```

Порядок сигналов фиксирован: пустая очередь не имеет возраста, поэтому `empty` раньше всего; заполненность важнее возраста — переполнение требует действия на входе, а старение — на выходе, и при обоих сразу сначала закрывают вход. Порог возраста включительный: шестьдесят секунд при пределе шестьдесят — уже `stale`.

> **Типичная ошибка.** Считать возраст по времени последнего завершения. Если исполнители стоят, завершений нет, и такая метрика застывает вместо того, чтобы расти.

## Пауза потребителя

Потребитель может быть остановлен намеренно — выкладка новой версии, ручная пауза при инциденте, ожидание восстановления зависимости. В этом состоянии рост глубины и возраста ожидаем и не означает перегрузку; поэтому `paused` проверяется раньше остальных сигналов, кроме валидности входа. Пропущенная проверка паузы даёт ложные алерты «очередь стареет» при каждой выкладке.

```go group=action mode=run
package main

import "fmt"

func action(depth, capacity, oldestSeconds, maxAgeSeconds int, consumerPaused bool) string {
    if depth < 0 || capacity <= 0 || oldestSeconds < 0 || maxAgeSeconds <= 0 {
        return "invalid"
    }
    if consumerPaused {
        return "paused"
    }
    if depth == 0 {
        return "empty"
    }
    if depth >= capacity {
        return "full"
    }
    if oldestSeconds >= maxAgeSeconds {
        return "stale"
    }
    return "normal"
}

func main() {
    fmt.Println(action(0, 4, 100, 60, true), action(1, 4, 1, 60, true), action(-1, 4, 60, 60, true), action(2, 4, 10, 60, false))
}
```

Вывод:

```text
paused paused invalid normal
```

Пауза при пустой очереди — всё равно `paused`: состояние потребителя важнее состояния очереди для того, кто читает метрику. Но некорректный снимок остаётся `invalid` и при паузе: ошибку измерения не прячут за режимом.

## Скорости входа и выхода

Две скорости — поступление и завершение за одно окно — отвечают на вопрос «что будет дальше». Если вход больше выхода, очередь растёт, и время до заполнения равно свободному месту, делённому на разницу скоростей; если выход больше, можно оценить время рассасывания. Обе скорости считают за короткое окно — секунды, не минуты, — иначе всплеск усреднится в ноль. Для разнородных задач добавляют распределение времени обслуживания: средняя скорость завершения скроет одну задачу, занявшую исполнителя на минуту.

> **Зачем.** Глубина и возраст описывают прошлое, скорости — будущее. Алерт по глубине срабатывает, когда проблема уже есть; алерт по разнице скоростей — когда она только начинается.

## Очередь как буфер, а не как хранилище

Очередь сглаживает короткие всплески: вход на секунду выше выхода — очередь подросла и рассосалась. Но если вход выше выхода систематически, очередь — не буфер, а склад невыполненной работы, и чем он больше, тем дольше каждая новая задача ждёт. Поэтому у очереди два предела: вместимость по числу элементов (прошлый урок, обратное давление на входе) и предел по возрасту (этот урок, бесполезность на выходе). Задачу, прождавшую дольше срока вызывающего, честнее отбросить при взятии из очереди, чем выполнить: результат никому не нужен, а исполнитель занят.

Отбрасывание по возрасту на выходе — это ещё один счётчик, который должен быть виден: если он растёт, исполнители тратят время на просроченную работу, и помогает не увеличение очереди, а уменьшение её или ускорение обработки.

## Какую метрику выводить в алерт

Для дежурного важны три сигнала с разной срочностью. Разница скоростей входа и выхода за короткое окно — ранний сигнал: очередь ещё в норме, но уже растёт. Возраст старейшего элемента выше порога — сигнал, что контракт задержки нарушен для хотя бы одного вызывающего. Заполненность — сигнал, что обратное давление уже работает и часть вызывающих получает отказы. Алерт только по глубине приходит последним и ничего не говорит о причине; алерт по возрасту при паузе потребителя — ложный, поэтому состояние паузы входит в условие.

## Практическая процедура

Нарисуй жизненный цикл одного элемента: поступил, принят в очередь, взят исполнителем, завершён или отклонён. Отметь, какие состояния входят в глубину, а какие — в возраст ожидания. Для каждого счётчика запиши единицу, источник, окно и поведение при отсутствии данных: «возраст неизвестен» — не ноль. Затем задай порог возраста из контракта задержки и порог глубины из ёмкости и допустимого ожидания, как в прошлых уроках, и проверь таблицей входов, что порядок сигналов даёт ожидаемую метку в случаях, когда срабатывают два условия сразу.

В отчёте об очереди, как и о ёмкости, цифры идут с контекстом: «глубина 340 из 500, старейший элемент 12 с при пороге 30, вход 110/с, выход 95/с за последние 10 с, потребитель активен». По такой строке дежурный видит, что очередь растёт на 15 задач в секунду и заполнится примерно через десять секунд, — и это полезнее любой из цифр по отдельности.

## Типичные ошибки

- Алерт по одной глубине без возраста: не отличить всплеск от остановки.
- Возраст по последнему завершению вместо постановки старейшего элемента.
- Порог возраста «из головы», а не из контракта задержки вызывающего.
- Пауза потребителя не учтена: ложные алерты при каждой выкладке.
- Скорости за минуту: всплески усредняются в ноль.
- Глубина сверх вместимости принята за ошибку измерения вместо сигнала о гонке на границе.

Отдельно оговори, что считается элементом: сообщение, пакет сообщений или запрос с несколькими подзадачами. Если потребитель берёт из очереди пакеты по сто, глубина в элементах и глубина в пакетах различаются на два порядка, и порог, записанный в одних единицах, бессмыслен в других.

## Самостоятельная лаборатория

Собери очередь на буферизованном канале с исполнителем фиксированной скорости и экспортируй три метрики: глубину, возраст старейшего элемента (храни время постановки рядом с элементом) и скорости входа и выхода за секунду. Подай поток ниже ёмкости, выше ёмкости и затем останови исполнителя на десять секунд; запиши, как ведёт себя каждая метрика в каждом режиме и какая из них первой показала проблему. Классифицируй снимки функцией `action` из примера и сравни с тем, что ты видел глазами. Удали стенд.

## Если что-то пошло не так

- `queued` при `depth == capacity` → заполненность проверяется `>=`.
- `stale` при пустой очереди → `empty` стоит раньше возраста: пустая очередь не имеет возраста.
- `normal` при `oldestSeconds == maxAgeSeconds` → порог включительный.
- `full` при паузе потребителя → `paused` проверяется раньше всех сигналов, кроме валидности.
- `paused` при отрицательной глубине → валидность первой.
- `import … is not allowed` → импорты запрещены.

## Практика

Три функции без `main` и печати; среда показывает результаты строками в кавычках. Входы — снимок очереди; возраст относится к старейшему ожидающему элементу, пустая очередь возраста не имеет.

### Задание 1 · Easy: очередь по глубине

**Цель.** `depth < 0` или `capacity ≤ 0` → `invalid`; `depth = 0` → `empty`; `depth ≥ capacity` → `full`; иначе `queued`.

**Ожидаемый вывод** — для `(depth=0, capacity=4)`:

```text
"empty"
```

**Шаги.**
1. Выбери задание «Easy»: сигнатура `func QueueBand(depth int, capacity int) string`. Импорты запрещены.
2. Валидность → `empty` → `full` → `queued`, в этом порядке.
3. «Запустить», «Проверить» — закрытые примеры: `(1,4)` → `queued`; `(4,4)` и `(5,4)` → `full`; `(-1,4)` и `(0,0)` → `invalid`.

**Как проверить себя.** Глубина сверх вместимости — `full`, не ошибка; возраст и задержку из глубины не выводят.

**Если не принято.**
- `queued` для `(4,4)` → строгое сравнение.
- `invalid` для `(5,4)` → превышение вместимости — допустимый снимок.

> **Подсказка.** Четыре ветки, порядок как в условии.

### Задание 2 · Medium: глубина и возраст

**Цель.** Некорректные входы → `invalid`; `depth = 0` → `empty`; `depth ≥ capacity` → `full`; `oldest ≥ maxAge` → `stale`; иначе `normal`.

**Ожидаемый вывод** — для `(depth=0, capacity=4, oldestSeconds=0, maxAgeSeconds=60)`:

```text
"empty"
```

**Шаги.**
1. Выбери задание «Medium»: сигнатура `func QueuePressure(depth int, capacity int, oldestSeconds int, maxAgeSeconds int) string`. Импорты запрещены.
2. `depth < 0`, `oldestSeconds < 0`, `capacity <= 0` или `maxAgeSeconds <= 0` → `"invalid"`.
3. Затем `empty`, `full`, `stale` (включительно), `normal`.
4. «Запустить», «Проверить» — закрытые примеры: возраст 59 при пороге 60 → `normal`; 60 → `stale`; полная очередь с малым возрастом → `full`; пустая с большим возрастом → `empty`; полная и старая → `full`.

**Как проверить себя.** Глубина и возраст — независимые сигналы; заполненность важнее возраста; порог возраста включительный.

**Если не принято.**
- `stale` для `(4,4,60,60)` → заполненность проверяется после возраста.
- `empty` не возвращается при большом возрасте → порядок правил нарушен.

> **Подсказка.** Это задание 1 плюс одна проверка между `full` и последним `return`.

### Задание 3 · Hard: pause-aware queue policy

**Цель.** Как в задании 2, плюс `consumerPaused` → `paused` сразу после проверки диапазонов.

**Ожидаемый вывод** — для `(depth=0, capacity=4, oldestSeconds=0, maxAgeSeconds=60, consumerPaused=false)`:

```text
"empty"
```

**Шаги.**
1. Выбери задание «Hard»: сигнатура `func QueueAction(depth int, capacity int, oldestSeconds int, maxAgeSeconds int, consumerPaused bool) string`. Импорты запрещены.
2. Диапазоны → `"invalid"`; `consumerPaused` → `"paused"`; дальше правила задания 2.
3. «Запустить», «Проверить» — закрытые примеры: пауза при пустой очереди → `paused`; пауза при отрицательной глубине → `invalid`; остальные как в задании 2.

**Как проверить себя.** Пауза выше пустой очереди, заполненность выше возраста; это классификация снимка, не распределение задержки и не управление потребителем.

**Если не принято.**
- `empty` при паузе → `paused` стоит после `empty`.
- `paused` при некорректных диапазонах → валидность первой.

> **Подсказка.** Единственное отличие от задания 2 — одна проверка на втором месте; та же схема, что в уроке о допуске.

## Проверь себя

- Почему одна глубина не говорит о задержке?
- Как считать возраст старейшего элемента и почему не по последнему завершению?
- Почему заполненность важнее возраста в порядке сигналов?
- Почему пауза потребителя проверяется раньше пустой очереди?
- Что показывают скорости входа и выхода, чего не показывают глубина и возраст?

## Итог

- Глубина — сколько ждут, возраст — как долго, скорости — что будет дальше; у каждой метрики единица, окно и точка учёта.
- Порядок сигналов — политика: валидность, пауза, пустая, полная, старая, нормальная.
- Пороги берутся из контракта задержки и ёмкости, а не из удобных чисел; «неизвестно» — не ноль.
