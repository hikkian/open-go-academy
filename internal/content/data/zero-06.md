# Редактор, Go и диагностика

## Что ты сделаешь

Ты напишешь три функции, которые разбирают текст сообщения об ошибке: первая относит сообщение к этапу (инструмент, путь или код), вторая выбирает следующий безопасный шаг, третья объясняет этап. Функции получают готовый текст и ничего не запускают и не читают файлы.

## Где запускать программу

Уроки проходятся в браузере: код пишется в редакторе справа, кнопка «Запустить» исполняет программу и показывает вывод. Локальная установка Go не нужна; о ней — в конце урока.

Файл — сохранённый текст, папка группирует файлы. Путь (path) указывает место: `lessons/hello/main.go` — это файл `main.go` внутри `hello`, который лежит в `lessons`. Относительный путь отсчитывается от текущей папки (working directory): та же команда из другой папки может не найти файл.

```go
package main

import "fmt"

func square(value int) int {
    return value * value
}

func main() {
    fmt.Println(square(5))
}
```

Вывод: `25`.

> **Важно.** Сообщение «no such file» говорит, что инструмент не нашёл файл. Оно не доказывает, что код написан неверно: сначала проверь путь и сохранение.

## Инструменты Go

Инструментарий (toolchain) — программы, которые форматируют, проверяют, собирают и запускают код. В локальном терминале обычно используют `go version` (какая версия установлена), `go fmt main.go` (форматирование по общему стилю) и `go run main.go` (проверка, сборка и запуск). В браузере те же действия — кнопки «Форматировать» и «Запустить».

Форматирование меняет только расположение пробелов и скобок. Оно не исправляет алгоритм и не угадывает намерение: если скобка пропущена, сначала нужно исправить синтаксис.

## Этапы сообщения

Инструмент сначала ищет файлы (этап path), затем проверяет, что нужная команда доступна (tool), и наконец разбирает сам код: синтаксис, имена и типы (source). Поэтому сообщения делятся на три группы:

- `command not found` — инструмент не найден в системе (этап tool);
- `no such file` или `cannot find` — путь или имя файла неверны (этап path);
- `undefined: ...`, `syntax error`, `cannot use ... as int value` — ошибка в самом коде (этап source).

```text
main.go:8:14: undefined: squre
```

Формат: файл, строка, позиция, причина. Здесь `squre` — опечатка в имени `square`: исправь имя в указанной строке и запусти снова.

> **Типичная ошибка.** Исправлять последнюю строку сообщения вместо первой. Одна ошибка часто порождает следующие, поэтому начинай с первой.

## Безопасный порядок

1. Прочитай первое сообщение.
2. Проверь путь, имя файла и что изменения сохранены.
3. Перейди к строке из сообщения; при `syntax error` проверь скобки и кавычки выше неё.
4. Исправь одну причину и запусти снова.

Не вставляй в редактор и терминал случайные команды из интернета и не клади пароли или ключи в код и сообщения. Установка Go необязательна: официальная инструкция — [go.dev/doc/install](https://go.dev/doc/install). После установки открой новый терминал и проверь `go version`.

## Если что-то пошло не так

- `command not found` → инструмент не найден: проверь установку и открой новый терминал.
- `no such file or directory` → неверный путь или имя файла: проверь папку и сохранение.
- `syntax error: unexpected EOF` → не закрыта скобка: проверь `{}` и `()` сверху вниз.

## Практика

Три задания. Функции проверяются на входах из блока «Ожидаемый вывод»; закрытые примеры видны только в «Проверить».

### Задание 1 · Определи этап ошибки

**Цель.** Вернуть `tool`, `path` или `source` по фразе в тексте сообщения.

**Ожидаемый вывод** — «Запустить» вызывает функцию на входах `go: command not found` и `stat main.go: no such file or directory`:

```text
"tool"
"path"
```

**Шаги.**
1. Выбери задание «Определи этап ошибки»: в файле есть `classifyDiagnostic` с `return ""`.
2. Добавь импорт `"strings"` после `package main`.
3. Приведи сообщение к нижнему регистру: `strings.ToLower(message)`.
4. Если в нём есть `command not found`, верни `tool`; если `no such file` или `cannot find`, верни `path`; иначе верни `source`.
5. Нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** В «Результате» два слова в кавычках: `"tool"` и `"path"`; все три критерия зелёные.

**Если не принято.**
- Для `Cannot Find file` выходит `source` → сравнение должно идти без учёта регистра: переводи сообщение в нижний регистр до проверки.
- Красная «пример 2» → проверь, что фраза `no such file` проверяется раньше, чем ветка «иначе».
- `imported and not used` → импорт есть, но функции из него не вызваны.

> **Подсказка.** Проверяй по одной фразе за раз: `if strings.Contains(lower, "command not found") { ... }`.

### Задание 2 · Выбери безопасный следующий шаг

**Цель.** Вернуть один из четырёх шагов: `check_install`, `check_path`, `read_first_error` или `save_and_rerun`.

**Ожидаемый вывод** — входы `go: command not found` и `stat main.go: no such file or directory`:

```text
"check_install"
"check_path"
```

**Шаги.**
1. Выбери задание «Выбери безопасный следующий шаг»: в файле есть `nextSafeStep` с `return ""`.
2. Добавь импорт `"strings"` и приведи сообщение к нижнему регистру.
3. `command not found` → `check_install`; `no such file` → `check_path`; `syntax error` или `undefined` → `read_first_error`; всё остальное → `save_and_rerun`.
4. Нажми «Запустить» и сверь два значения с блоком выше.
5. Нажми «Проверить».

**Как проверить себя.** Два шага в кавычках; все три критерия зелёные.

**Если не принято.**
- `SYNTAX ERROR` даёт `save_and_rerun` → сравнение не учитывает регистр; переведи сообщение в нижний регистр.
- `build failed` даёт `read_first_error` → эта фраза не относится к синтаксису: она попадает в ветку «всё остальное».
- Красная «закрытый пример» на `undefined: total` → проверь, что `undefined` ведёт к `read_first_error`.

> **Подсказка.** Функция возвращает первый подходящий шаг, поэтому сначала проверяй конкретные фразы, а общий случай — последним.

### Задание 3 · Объясни диагностику по этапу

**Цель.** Вернуть объяснение для этапа `path` или `tool`; для любого другого этапа — «Прочитай первую ошибку и указанную строку».

**Ожидаемый вывод** — входы: сообщение `file missing` на этапе `path` и сообщение `command absent` на этапе `tool`:

```text
"Проверь папку и имя файла"
"Проверь установку и открой новый терминал"
```

**Шаги.**
1. Выбери задание «Объясни диагностику по этапу»: в файле есть `explainDiagnostic(message string, stage string)`.
2. Для `stage == "path"` верни `Проверь папку и имя файла`.
3. Для `stage == "tool"` верни `Проверь установку и открой новый терминал`.
4. Во всех остальных случаях верни `Прочитай первую ошибку и указанную строку`. Сообщение в этом задании не разбирается: его текст важен только для этапа.
5. Нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** В «Результате» две строки на русском; все три критерия зелёные.

**Если не принято.**
- Для этапа `tool` вернулось объяснение про папку → проверь, что сравнение идёт со строкой `"tool"`, а кавычки — часть литерала.
- Закрытый пример с этапом `other` не совпал → для любого этапа, кроме `path` и `tool`, верни объяснение про первую ошибку.

> **Подсказка.** `switch stage { case "path": ... case "tool": ... }`; ветка `default` покрывает все остальные этапы.

## Итог

- Путь и текущая папка — разные вещи: относительный путь зависит от того, откуда запущена команда.
- Этап сообщения (tool, path, source) задаёт первое действие: проверить установку, путь или код.
- Читай первую ошибку и меняй одну вещь за раз; локальная установка Go необязательна.
