# IP, TCP, DNS и порты

## Что ты сделаешь

Ты напишешь три функции, которые работают с адресами без сети: `ParseEndpoint` разберёт `host:port`, включая IPv6 в квадратных скобках, `NextNetworkStage` назовёт первую неуспешную границу, `JoinEndpoint` соберёт адрес обратно и отвергнет неверные значения. Ни одна функция не открывает соединение и не выполняет поиск имени.

## Адрес состоит из двух частей

Сетевой адрес для клиента — это пара «хост и порт». Хост бывает именем (`api.example.test`), адресом IPv4 (`127.0.0.1`) или IPv6 (`::1`). Порт — число от 1 до 65535. Так как IPv6 содержит двоеточия, при записи вместе с портом его берут в квадратные скобки:

```go
package main

import (
    "fmt"
    "net"
)

func main() {
    host, port, err := net.SplitHostPort("[::1]:443")
    fmt.Println(host, port, err)
}
```

Вывод: `::1 443 <nil>`. Стандартная функция `net.SplitHostPort` сама снимает скобки. Если двоеточий слишком много без скобок, она вернёт ошибку.

> **Важно.** Разбор строки и поиск имени — разные шаги. `SplitHostPort` не обращается к DNS и не проверяет, что хост существует.

## Обратная сборка

`net.JoinHostPort` делает обратную работу: для IPv6 ставит скобки, для остальных хостов просто склеивает через двоеточие:

```go
package main

import (
    "fmt"
    "net"
)

func main() {
    fmt.Println(net.JoinHostPort("::1", "443"))
    fmt.Println(net.JoinHostPort("example.test", "80"))
}
```

Вывод: `[::1]:443` и `example.test:80`.

> **Типичная ошибка.** Склеивать адрес вручную через `host + ":" + port` для IPv6. Получится `::1:443`, и разобрать его обратно уже нельзя: непонятно, где адрес, а где порт.

## Отличить адрес от имени

`net.ParseIP` возвращает `nil`, если строка не является IP-адресом. Так отличают числовой адрес от имени, которое ещё надо разрешить через DNS:

```go
package main

import (
    "fmt"
    "net"
)

func main() {
    fmt.Println(net.ParseIP("127.0.0.1") != nil, net.ParseIP("example.test") != nil)
}
```

Вывод: `true false`. Имя `example.test` не адрес, пока DNS не вернул его IP.

## Путь диагностики

Сетевое подключение проходит четыре границы по порядку: разрешение имени (DNS), установка TCP-соединения, согласование TLS, обмен HTTP-запросом и ответом. Если первая граница не пройдена, следующие даже не начинаются. Поэтому при сбое первый неуспешный этап и есть место для расследования.

## Если что-то пошло не так

- `undefined: net` → не добавлен импорт `"net"`.
- `imported and not used: strconv` → импорт есть, а `strconv.Atoi` не вызван.
- `missing return` → в одной из веток функция не возвращает значение.
- Порт `0` или `65536` принят → проверка диапазона должна стоять после разбора числа.

### Задание 1 · Разбери endpoint без DNS

**Цель.** Разобрать `host:port`, включая IPv6 в скобках. Порт — от 1 до 65535. Поиск имени не делать.

**Ожидаемый вывод** — входы `127.0.0.1:8080` и `[::1]:443`. Результат печатается как объект с полями `Endpoint` и `OK`:

```text
{"Endpoint":{"Host":"127.0.0.1","Port":8080},"OK":true}
{"Endpoint":{"Host":"::1","Port":443},"OK":true}
```

**Шаги.**
1. Выбери задание «Разбери endpoint без DNS»: в файле есть `ParseEndpoint` с `panic("TODO")`. Добавь импорты `"net"` и `"strconv"`.
2. Раздели строку через `net.SplitHostPort(address)`. Если ошибка, верни пустой `Endpoint` и `false`.
3. Преобразуй порт через `strconv.Atoi`. Если ошибка или порт вне 1..65535, верни пустой `Endpoint` и `false`.
4. Иначе верни `Endpoint{Host: host, Port: port}` и `true`.
5. Нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Два объекта с полями `Endpoint` и `OK`; все три критерия зелёные.

**Если не принято.**
- Для `[::1]:443` выходит ошибка → скобки снимает `SplitHostPort`, а не ваш код: не делай лишних проверок до него.
- Порт `0` принят → диапазон проверяется после преобразования и должен начинаться с 1.
- Адрес `::1:443` без скобок принят → `SplitHostPort` возвращает ошибку для неоднозначной записи; верни `false`.

> **Подсказка.** Пустой результат при ошибке — тот же `Endpoint{}`, что и отсутствие значения.

### Задание 3 · Собери адрес host:port

**Цель.** Собрать адрес из хоста и порта. IPv6 берётся в скобки. Пустой хост, пробелы, слэш, двоеточие в имени и порт вне 1..65535 — отказ.

**Ожидаемый вывод** — входы: `127.0.0.1` с портом `8080` и `api.example.test` с портом `443`. Результат печатается как объект с полями `Address` и `OK`:

```text
{"Address":"127.0.0.1:8080","OK":true}
{"Address":"api.example.test:443","OK":true}
```

**Шаги.**
1. Выбери задание «Собери адрес host:port»: в файле есть `JoinEndpoint` с `panic("TODO")`. Добавь импорты `"net"`, `"strconv"`, `"strings"`, если используешь.
2. Проверь порт: от 1 до 65535. Иначе верни пустую строку и `false`.
3. Проверь хост: он не пустой и не содержит пробелов, слэшей и двоеточий, если это имя, а не IP. Иначе — пустую строку и `false`.
4. Собери адрес через `net.JoinHostPort(host, strconv.Itoa(port))`.
5. Верни адрес и `true`, нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Два объекта с полями `Address` и `OK`; все три критерия зелёные.

**Если не принято.**
- Для `2001:db8::1` адрес без скобок → собирай через `net.JoinHostPort`, а не вручную.
- Пустой хост принят → проверка пустоты стоит до сборки.
- Хост `bad host` принят → пробел в имени запрещён; проверяй символы до сборки адреса.

> **Подсказка.** Сначала проверки порта и хоста, потом одна строка сборки.

## Итог

- Адрес делится на хост и порт; IPv6 в записи с портом заключается в скобки.
- Разбор и сборка адреса выполняются без сети: DNS, TCP и TLS — отдельные границы, которые проверяются по порядку.
