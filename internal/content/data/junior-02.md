# Карты, множества и порядок данных

## Что ты сделаешь

Ты напишешь три функции: `lookup` найдёт значение по ключу и скажет, был ли ключ, `unique` уберёт повторы из списка, сохранив порядок первого появления, а `mergeMax` объединит две карты по правилу максимума. По дороге разберёшься, почему порядок обхода карты нельзя считать контрактом.

## Карта: чтение и признак наличия

Карта (`map[K]V`) хранит пары ключ–значение. Чтение отсутствующего ключа не аварийно останавливает программу: возвращается нулевое значение типа `V`. Поэтому одно число `0` не говорит, был ключ или нет.

```go
package main

import "fmt"

func main() {
    m := map[string]int{"ada": 0}
    a, okA := m["ada"]
    b, okB := m["bob"]
    fmt.Println(a, okA, b, okB)
}
```

Вывод: `0 true 0 false`. Вторая переменная в форме `значение, ok := m[ключ]` отвечает на вопрос «ключ был?». Так ключ со значением `0` отличается от отсутствующего ключа.

> **Важно.** Проверяй наличие второй переменной, а не сравнивай значение с нулём: нуль может быть настоящим значением.

## Порядок обхода не задан

`for k, v := range m` обходит пары в произвольном порядке, и он может меняться от запуска к запуску: Go намеренно не задаёт порядок обхода карты. Если результат должен идти в фиксированном порядке, собери ключи в срез и отсортируй его:

```go
package main

import (
    "fmt"
    "sort"
)

func main() {
    m := map[string]int{"b": 2, "a": 1, "c": 3}
    keys := make([]string, 0, len(m))
    for k := range m {
        keys = append(keys, k)
    }
    sort.Strings(keys)
    for _, k := range keys {
        fmt.Println(k, m[k])
    }
}
```

Вывод: `a 1`, `b 2`, `c 3`, каждая строка на своей строке.

> **Типичная ошибка.** Печатать карту через `range` и считать, что порядок будет тем же при следующем запуске. Тест, который так проверяет, может упасть без изменения кода.

## Множество и порядок первого появления

В Go нет отдельного типа «множество». Его строят картой с пустым значением `struct{}`: такой тип не занимает памяти под значение, а `struct{}{}` — самое короткое значение.

Чтобы убрать повторы и сохранить порядок, нужны две вещи: карта для проверки «уже видели» и срез для результата. Порядок в срезе задаёт сам обход, а не карта:

```go
package main

import "fmt"

func main() {
    words := []string{"go", "go", "rust", "go", "zig"}
    seen := make(map[string]struct{})
    var first []string
    for _, w := range words {
        if _, ok := seen[w]; ok {
            continue
        }
        seen[w] = struct{}{}
        first = append(first, w)
    }
    fmt.Println(first, len(seen))
}
```

Вывод: `[go rust zig] 3`. Карта отвечает на вопрос «видели ли», срез хранит результат.

## nil-карта и пустой срез

`var m map[string]int` создаёт nil-карту. Её можно читать: `m["x"]` вернёт `0`. Записывать в неё нельзя: запись в nil-карту аварийно останавливает программу. Поэтому карту, в которую будешь писать, создают через `make` или литерал.

```go
package main

import "fmt"

func main() {
    var m map[string]int
    fmt.Println(m["x"], len(m), m == nil)
}
```

Вывод: `0 0 true`.

> **Типичная ошибка.** `var out map[string]int` и сразу `out["a"] = 1`. Программа остановится с сообщением `assignment to entry in nil map`. Создай карту через `make(map[string]int)`.

Пустой срез устроен похоже: `var s []int` даёт nil-срез, который печатается как `null`, а `[]int{}` — пустой срез, печатается как `[]`. Если контракт требует `[]`, возвращай пустой срез явно.

## Если что-то пошло не так

- `assignment to entry in nil map` → карта не создана. Используй `make` или литерал перед записью.
- Результат печатается как `null` вместо `[]` → вернулся nil-срез. Создай его через `[]int{}`.
- Порядок ключей в выводе «прыгает» → обход карты не задаёт порядок. Сортируй ключи перед печатью.
- `declared and not used` для второй переменной `ok` → значит, проверка наличия не сделана.

## Практика

Три задания. Функции проверяются на входах из блока «Ожидаемый вывод»; закрытые примеры видны только в «Проверить».

### Задание 1 · Найди значение по ключу

**Цель.** Вернуть значение и `true`, если ключ есть; иначе — `0` и `false`.

**Ожидаемый вывод** — «Запустить» вызывает `lookup` на входах: ключ `Ada` в карте с `Ada: 0`, и ключ `nobody` в пустой карте:

```text
[0,true]
[0,false]
```

**Шаги.**
1. Выбери задание «Найди значение по ключу»: в файле есть `lookup` с `return 0, false`.
2. Прочитай значение и признак наличия: `value, ok := scores[name]`.
3. Верни `value, ok`.
4. Нажми «Запустить» и сравни обе строки с блоком выше.
5. Нажми «Проверить».

**Как проверить себя.** Два результата в квадратных скобках: `[0,true]` и `[0,false]`; все три критерия зелёные.

**Если не принято.**
- Для ключа `Ada` выходит `[0,false]` → второе значение потеряно: верни `ok`, а не константу.
- Красная «закрытый пример» с отрицательным значением → не заменяй найденное значение нулём.
- Пустой вход даёт панику → карта `nil`: чтение из неё безопасно, проверь, что не пишешь в неё.

> **Подсказка.** Форма `value, ok := scores[name]` возвращает два значения сразу.

### Задание 2 · Уникальные значения с порядком первого появления

**Цель.** Вернуть каждое число один раз, в порядке его первого появления.

**Ожидаемый вывод** — входы `[3, 1, 3, 2, 1]` и пустой срез:

```text
[3,1,2]
[]
```

**Шаги.**
1. Выбери задание «Уникальные значения с порядком первого появления»: в файле есть `unique` с `return nil`.
2. Создай карту `seen := make(map[int]struct{})`.
3. Создай результат как пустой срез `out := []int{}`, а не через `nil`.
4. Пройди по `values`: если значения нет в `seen`, запиши его в `seen` и добавь в `out`.
5. Верни `out`, нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Два списка: `[3,1,2]` и `[]`; все три критерия зелёные.

**Если не принято.**
- Пустой вход печатается как `null` → результат был nil-срезом: создай его через `[]int{}`.
- Порядок `[1,2,3]` вместо `[3,1,2]` → результат собирается в порядке ключей карты, а не обхода входа.
- Закрытый пример с нулём и отрицательным значением не совпал → проверка наличия должна идти до добавления.

> **Подсказка.** Добавляй значение в результат только тогда, когда его нет в `seen`.

### Задание 3 · Объедини карты по правилу максимума

**Цель.** Вернуть новую карту с ключами обоих входов; при совпадении ключа взять большее значение.

**Ожидаемый вывод** — входы: `{"a": 2}` и `{"a": 5, "b": 1}`, затем две пустые карты:

```text
{"a":5,"b":1}
{}
```

Печать JSON выводит ключи по алфавиту: это свойство печати, а не порядок обхода карты.

**Шаги.**
1. Выбери задание «Объедини карты по правилу максимума»: в файле есть `mergeMax` с `return nil`.
2. Создай результат через `out := make(map[string]int)`.
3. Перепиши все пары из `left` в `out`.
4. Для каждой пары из `right`: если ключа нет в `out` или её значение больше, запиши значение в `out`.
5. Верни `out` (он не должен быть `nil`), нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Два JSON-объекта: `{"a":5,"b":1}` и `{}`; все три критерия зелёные.

**Если не принято.**
- Результат печатается как `null` → карта не создана через `make`.
- Паника `assignment to entry in nil map` → записи идут в `nil`-карту: создай `out` до записи.
- Значение `2` вместо `5` для ключа `a` → при совпадении нужно сравнивать и брать большее.

> **Подсказка.** Сначала перепиши `left` целиком, потом обходи `right` и сравнивай значения.

## Итог

- Признак наличия даёт вторая переменная `value, ok := m[k]`, а не сравнение с нулём.
- Порядок обхода карты не задан: для фиксированного порядка сортируй ключи или держи срез.
- Карта для записи создаётся через `make`; nil-карта читается, но не записывается, а nil-срез печатается как `null`.
