# Срезы: общий массив, копирование и владение

## Что ты сделаешь

Ты напишешь три функции над срезами: `safeAt` безопасно достаёт элемент по индексу, `sum` складывает числа и замечает переполнение, `keepAtLeast` отбирает элементы в новый срез, не трогая исходный. По дороге разберёшься, почему два среза могут делить одну память, когда копия настоящая и чем пустой срез отличается от отсутствующего.

## Срез — это карточка с тремя полями

Срез (slice) — не сама последовательность, а маленький заголовок: адрес первого элемента, длина `len` и ёмкость `cap`. Элементы лежат в базовом массиве (backing array). Присваивание `b := a` копирует заголовок, а не элементы, поэтому оба имени смотрят на одни ячейки.

```go
package main

import "fmt"

func main() {
    source := []int{10, 20, 30, 40}
    view := source[1:3]
    view[0] = 99
    fmt.Println("source:", source)
    fmt.Println("view:", view, "len:", len(view), "cap:", cap(view))
}
```

Вывод:

```text
source: [10 99 30 40]
view: [99 30] len: 2 cap: 3
```

Запись через `view` видна через `source`: это совместное использование (aliasing). Ёмкость 3 — потому что от позиции 1 до конца массива три ячейки. Индексы, доступные для чтения, ограничены `len`, а не `cap`.

> **Важно.** Если функция получила срез и изменила его элемент, вызывающая сторона это увидит. Обещание «вход не меняется» надо выполнять самому.

## Копия, которая не делит память

Настоящая копия — новый базовый массив. Два способа: `make` нужной длины плюс `copy`, или `append` к пустому срезу.

```go
package main

import "fmt"

func main() {
    source := []int{1, 2, 3}
    independent := make([]int, len(source))
    copy(independent, source)
    independent[0] = -1
    fmt.Println(source, independent)

    var absent []int
    empty := []int{}
    fmt.Println(len(absent), absent == nil, len(empty), empty == nil)
}
```

Вывод:

```text
[1 2 3] [-1 2 3]
0 true 0 false
```

Вторая половина примера — про два вида «ничего». `absent` — nil-срез: базового массива нет. `empty` — пустой срез: массив есть, элементов ноль. Для `len` и цикла они одинаковы, но среда показывает их по-разному: nil печатается как `null`, пустой — как `[]`.

> **Типичная ошибка.** Вернуть `nil` там, где контракт требует пустой срез. Код компилируется, цикл работает, а проверка видит `null` вместо `[]`.

## Границы индекса

Читать можно индексы от 0 до `len-1`. Выход за границу — паника времени выполнения, программа падает. Поэтому безопасная функция сначала проверяет индекс, потом читает. Для nil-среза `len` равен 0, так что проверка `index >= len(values)` закрывает и этот случай без отдельного условия.

```go
package main

import "fmt"

func at(values []int, index int) (int, bool) {
    if index < 0 || index >= len(values) {
        return 0, false
    }
    return values[index], true
}

func main() {
    fmt.Println(at([]int{4, 8}, 1))
    fmt.Println(at(nil, 0))
}
```

Вывод:

```text
8 true
0 false
```

Второй результат `bool` отвечает на вопрос «значение было?». Без него ноль из пустого среза не отличить от настоящего нуля в данных.

## Переполнение int

У `int` конечный диапазон. Если сумма вылезает за него, Go молча «перекручивает» число, и ответ становится неверным без ошибки. Поэтому проверка должна стоять **до** сложения. Наибольшее значение `int` можно получить без импортов: `maxInt := int(^uint(0) >> 1)`, наименьшее — `minInt := -maxInt - 1`.

```go
package main

import "fmt"

func main() {
    maxInt := int(^uint(0) >> 1)
    total := maxInt
    v := 1
    if v > 0 && total > maxInt-v {
        fmt.Println("переполнение до сложения")
    }
    fmt.Println(maxInt + v)
}
```

Вывод:

```text
переполнение до сложения
-9223372036854775808
```

Правило: для положительного `v` переполнение будет, если `total > maxInt - v`; для отрицательного — если `total < minInt - v`. Обе части вычисляются без переполнения.

## Если что-то пошло не так

- `panic: runtime error: index out of range` → читаешь элемент без проверки `index < len`.
- В «Получили» `null`, а ждали `[]` → вернул nil-срез; создай пустой через `make([]int, 0)` или `[]int{}`.
- Исходный срез изменился после вызова → ты писал в `values[i]` или сделал `append` поверх входа; собирай результат в новый срез.
- Сумма больших чисел отрицательная → переполнение; проверяй до `total += v`.
- `import … is not allowed` → в карточке сказано, что разрешено; `math` в этом уроке недоступен, граница `int` считается вручную.

## Практика

Три функции, без `main` и без печати. Среда вызывает их с готовыми срезами и показывает результаты строками JSON: пара `[8,true]`, число с `null` вместо отсутствующей ошибки, срез как `[5,5]`.

### Задание 1 · Безопасный индекс

**Цель.** Вернуть элемент по индексу и `true`, а для nil, пустого среза, отрицательного индекса или индекса ≥ len — `0` и `false`.

**Ожидаемый вывод** — для `([4, 8], 1)`, `([], 0)`, `([-2], -1)`:

```text
[8,true]
[0,false]
[0,false]
```

**Шаги.**
1. Выбери задание «Безопасный индекс»: сигнатура `func safeAt(values []int, index int) (int, bool)`. Импорты запрещены.
2. Первой строкой проверь `index < 0 || index >= len(values)` и верни `0, false`.
3. Иначе верни `values[index], true`.
4. «Запустить», сравни три строки. «Проверить» — закрытые примеры включают nil-срез, индекс ровно `len` и срез из одного элемента.

**Как проверить себя.** Три строки как в блоке; закрытые примеры зелёные; в коде нет отдельной ветки для nil — её покрывает проверка длины.

**Если не принято.**
- Красный закрытый пример при зелёных открытых → граница: индекс `len` недопустим (`>=`, а не `>`).
- Ошибка `index out of range` в «Результате» → проверка стоит после чтения или отсутствует.
- `[0,false]` вместо `[8,true]` → условие перепутано: при допустимом индексе нужно вернуть значение.

> **Подсказка.** Вся функция — одно условие и два `return`.

### Задание 2 · Сумма с проверкой переполнения

**Цель.** Сложить все числа и вернуть сумму и `nil`; если сумма не помещается в `int`, вернуть `0` и ошибку; вход не менять.

**Ожидаемый вывод** — для `[2, 3, -1]` и `[]`; `null` означает «ошибки нет»:

```text
[4,null]
[0,null]
```

**Шаги.**
1. Выбери задание «Сумма с проверкой переполнения»: сигнатура `func sum(values []int) (int, error)`. Разрешён импорт `errors`.
2. Вычисли `maxInt := int(^uint(0) >> 1)` и `minInt := -maxInt - 1`.
3. Заведи `total := 0` и пройди `for _, v := range values`: перед сложением проверь переполнение (`v > 0 && total > maxInt-v` или `v < 0 && total < minInt-v`) и при нём верни `0, errors.New("overflow")`.
4. После цикла верни `total, nil`. «Запустить», «Проверить» — закрытые примеры: `[maxInt, 1]`, `[minInt, -1]`, `[10, -10, 4]`, `[7]`.

**Как проверить себя.** Для пустого среза `[0,null]` без ошибки; при переполнении среда покажет `[0,"overflow"]`; закрытый пример `[10, -10, 4]` даёт `[4,null]` — промежуточная сумма уходила в минус, но не переполнялась.

**Если не принято.**
- Красный закрытый пример 1 или 2 → проверки до сложения нет или она только для положительных чисел.
- Красный закрытый пример 3 → ты считаешь ошибкой любое отрицательное промежуточное значение; ошибка — только выход за диапазон.
- Отказ из-за импорта → `math` недоступен, границы считай через `^uint(0) >> 1`.

> **Подсказка.** Сравнивай не `total + v` с границей (это уже переполнение), а `total` с `maxInt - v`.

### Задание 3 · Отфильтруй в независимом срезе

**Цель.** Вернуть новый срез только из значений ≥ `minimum`, сохранив порядок и повторы; вход не менять; при пустом результате вернуть пустой срез, не nil.

**Ожидаемый вывод** — для `([5, 1, 5, 2], 3)` и `([], 0)`:

```text
[5,5]
[]
```

**Шаги.**
1. Выбери задание «Отфильтруй в независимом срезе»: сигнатура `func keepAtLeast(values []int, minimum int) []int`. Импорты запрещены.
2. Создай результат заранее пустым и не-nil: `out := make([]int, 0, len(values))`.
3. Пройди `for _, v := range values` и добавляй `out = append(out, v)` при `v >= minimum`.
4. Верни `out`. «Запустить», «Проверить» — закрытые примеры: `([1, 2], 3)` → `[]`, `([4, 3, 4], 4)` → `[4,4]`, `([0, -1], -1)` → `[0,-1]`, `([6], 6)` → `[6]`.

**Как проверить себя.** Второй открытый пример показывает `[]`, не `null`; повторы (две пятёрки) сохранены в исходном порядке; граница `>=` включает число, равное `minimum`.

**Если не принято.**
- В «Получили» `null` → результат объявлен как `var out []int` и остался nil; используй `make` или `[]int{}`.
- Пропало число, равное `minimum` → сравнение `>` вместо `>=`.
- Красный закрытый пример `[0,-1]` → отрицательный `minimum` не особый случай; не добавляй проверок на знак.

> **Подсказка.** `append` к срезу, созданному через `make([]int, 0)`, никогда не трогает исходный `values`.

- Почему `append` нужно присваивать обратно переменной?

## Итог

- Срез — заголовок над базовым массивом: копия заголовка делит элементы, настоящая копия — это `make` + `copy` или `append` в новый срез.
- Читать можно только индексы `< len`; проверка границы стоит до чтения, а второй результат `bool` говорит, было ли значение.
- Переполнение `int` проверяют до сложения, а пустой результат возвращают как `[]`, не как `nil`.
