# Файлы, JSON и интерфейсы ввода-вывода

## Что ты сделаешь

Ты напишешь три функции для записей `Item` с полями `Name` и `Quantity`: `isValidItem` проверит одну запись, `ReadItems` прочитает JSON-массив из потока и отвергнет некорректный ввод, `encodeItems` закодирует только валидные записи обратно в JSON. Правило проверки одно и то же на входе и на выходе.

## JSON: теги и поля

Поля структуры связывают с ключами JSON тегами в обратных кавычках. Тег `json:"name"` говорит, что поле `Name` в JSON называется `name`. Без тега ключ совпал бы с именем поля, и это легко перепутать:

```go
package main

import (
    "encoding/json"
    "os"
)

type Item struct {
    Name     string `json:"name"`
    Quantity int    `json:"quantity"`
}

func main() {
    enc := json.NewEncoder(os.Stdout)
    enc.Encode([]Item{{Name: "pen", Quantity: 2}})
}
```

Вывод: `[{"name":"pen","quantity":2}]` и перевод строки. `json.Encoder` пишет значение в поток и завершает его переводом строки.

> **Важно.** Пустой срез и nil-срез в JSON различаются: `[]` и `null`. Для контракта, который требует список, пустой срез надо создавать явно.

## Чтение из потока

`json.NewDecoder` читает из `io.Reader` по мере необходимости. Это удобно для файла, сети или строки. После `Decode` видно, что стоит дальше, и можно убедиться, что вход закончился:

```go
package main

import (
    "encoding/json"
    "fmt"
    "io"
    "strings"
)

func main() {
    dec := json.NewDecoder(strings.NewReader(`[1] trailing`))
    var v []int
    fmt.Println(dec.Decode(&v), v)
    _, err := dec.Token()
    fmt.Println(err == io.EOF)
}
```

Вывод: `<nil> [1]` и `false`. Массив прочитан, но после него остался лишний текст: `Token` вернул ошибку, а не конец потока.

> **Типичная ошибка.** Проверить только `Decode`. Он не скажет о хвосте: `[] мусор` тогда пройдёт, хотя контракт его отвергает.

## Одно правило на входе и на выходе

Запись годна, если имя после `strings.TrimSpace` не пустое и количество больше нуля. Это правило нужно и тогда, когда данные читаются, и тогда, когда пишутся: иначе можно записать то, что потом не пройдёт проверку при чтении.

## Если что-то пошло не так

- `cannot use items (variable of type []Item) ... as string value` → в `encodeItems` кодируется срез, а результат должен быть строкой: используй буфер и `buf.String()`.
- `undefined: io` или `undefined: json` → импорт не добавлен.
- Ошибочный JSON доходит до вызывающей стороны как частичные данные → при ошибке верни `nil`, а не разобранную часть.
- `imported and not used` → импорт есть, а функция из пакета не вызывается.

**Ожидаемый вывод** — входы: массив с одной записью `pen` и пустой массив. Результат печатается как объект с полями `Items` и `OK`:


2. Создай декодер: `dec := json.NewDecoder(r)`.

4. Проверь каждую запись правилом из первого задания. Невалидная запись — ошибка.

> **Подсказка.** Пустой массив `[]` — валидный вход: после декодирования срез пуст, но ошибки нет.

### Задание 3 · Закодируй валидные записи

**Цель.** Если все записи валидны, закодировать срез в JSON через `json.Encoder`, включая перевод строки в конце. Если хотя бы одна невалидна, вернуть пустую строку и ошибку.

**Ожидаемый вывод** — входы: одна запись `pen` с количеством 2, затем пустой список. Результат печатается как объект с полями `JSON` и `OK`:

```text

{"JSON":"[]\n","OK":true}
```

**Шаги.**
1. Выбери задание «Закодируй валидные записи»: в файле есть `encodeItems` с `panic("TODO")`. Добавь импорты `"bytes"`, `"encoding/json"`, `"errors"`, если используешь.
2. Проверь каждую запись правилом из первого задания. Невалидная — верни `""` и ошибку.
3. Если `items` равен `nil`, замени его на `[]Item{}`: пустой список должен кодироваться как `[]`.
4. Создай буфер `var buf bytes.Buffer` и `enc := json.NewEncoder(&buf)`.
5. Закодируй: `enc.Encode(items)`. Ошибку верни.
6. Верни `buf.String()` и `nil`.
7. Нажми «Запустить» и сравни с блоком выше.

**Как проверить себя.** Две строки: `"[{\"name\":\"pen\",\"quantity\":2}]\n"` и `"[]\n"`, оба с `OK` равным `true`; все три критерия зелёные.

**Если не принято.**
- Пустой список печатается как `null` → nil-срез закодирован как `null`: замени его на `[]Item{}`.
- Перевода строки в конце нет → строка берётся не из `json.Encoder`, а собирается вручную.
- Закрытый пример с количеством 0 принят → проверка записи должна стоять до кодирования.

> **Подсказка.** `json.Encoder` сам добавляет перевод строки после значения.

## Итог

- `json.NewDecoder` читает из `io.Reader` и позволяет проверить, что после значения ничего не осталось.
- Пустой список и отсутствие значения в JSON различаются: `[]` и `null`.
- Одно правило валидации применяется и при чтении, и при записи: данные, которые пишутся, должны читаться обратно.
