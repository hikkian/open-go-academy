# Валидация и HTTP ошибки

## Что ты сделаешь

Ты напишешь три проверки входных данных: `ValidateAlias` проверит короткое имя ресурса, `ValidateTarget` проверит адрес назначения, `ValidateCreateJSON` разберёт тело запроса и вызовет обе проверки. Каждая функция возвращает код ошибки или пустую строку при успехе. Код — это контракт: клиент может на него опереться, а внутренние детали остаются внутри сервера.

## Формат раньше действия

Сначала проверяется форма данных: длина, допустимые символы, структура JSON. Только потом проверяются правила предметной области, например уникальность имени или допустимость адреса. Форма отвечает на вопрос «похоже ли это на правильный ввод», правило — «допустимо ли это здесь». Смешивать их нельзя: синтаксически неверный ввод не должен доходить до бизнес-логики.

Длину проверяют до разбора. Иначе большой ввод успеет занять память, прежде чем его отвергнут.

## Ошибка — стабильный код

Ошибка для клиента — это короткий код, а не текст внутреннего исключения. Текст `err.Error()` может содержать путь к файлу, имя таблицы или фрагмент запроса. Поэтому наружу уходит код из заранее согласованного набора:

```go
package main

import "fmt"

func codeFor(status int) string {
    switch status {
    case 400:
        return "invalid_request"
    case 409:
        return "conflict"
    }
    return "internal"
}

func main() {
    fmt.Println(codeFor(400), codeFor(409))
}
```

Вывод: `invalid_request conflict`. Для неизвестного статуса код тоже стабилен: `internal`.

> **Важно.** Конфликт (409) — не ошибка формы. Запрос корректен, но противоречит состоянию ресурса. Поэтому у него свой код.

## Ограничение тела до разбора

Тело запроса читается из потока. Чтобы не принять гигабайт, читают не больше допустимого размера. `io.LimitReader` ограничивает поток: здесь лимит 4 байта, и лишнее не попадает в память:

```go
package main

import (
    "fmt"
    "io"
    "strings"
)

func main() {
    r := io.LimitReader(strings.NewReader("abcdef"), 4)
    data, _ := io.ReadAll(r)
    fmt.Println(string(data), len(data))
}
```

Вывод: `abcd 4`. Чтобы отличить «ровно лимит» от «больше лимита», читают на один байт больше.

## Один объект, а не два

`json.Decoder` читает один JSON-объект. Если после него в потоке остался ещё текст, это лишние данные. Проверка `Token` покажет, что поток закончился:

```go
package main

import (
    "encoding/json"
    "fmt"
    "io"
    "strings"
)

func main() {
    dec := json.NewDecoder(strings.NewReader(`{"a":1} {"b":2}`))
    var v map[string]int
    fmt.Println(dec.Decode(&v) == nil)
    _, err := dec.Token()
    fmt.Println(err == io.EOF)
}
```

Вывод: `true` и `false`. Второй объект остался в потоке.

> **Типичная ошибка.** Вернуть клиенту `err.Error()` из декодера. Текст вроде `invalid character` раскрывает детали разбора и меняется от версии к версии. Возвращай код.

## Если что-то пошло не так

- `imported and not used: io` → импорт есть, а `LimitReader` не использован.
- Тело большого размера читается целиком → лимит задан после `io.ReadAll`; ограничивай поток до чтения.
- Клиенту уходит внутренний текст ошибки → замени его на код из набора контракта.
- `undefined: strings` → импорт не добавлен.

## Практика

Три задания. Функции проверяются на входах из блока «Ожидаемый вывод»; закрытые примеры видны только в «Проверить». Пустая строка в ответе означает успех.

### Задание 1 · Отклони отсутствующий alias

**Цель.** Alias — от 1 до 24 символов из строчных латинских букв, цифр и дефиса. Пустой alias или неверные символы — `invalid_alias`. Длина больше 24 — `alias_too_long`. Успех — пустая строка.

**Ожидаемый вывод** — входы `go-2026` и `green`:

```text
""
""
```

Пустые строки в кавычках означают успех.

**Шаги.**
1. Выбери задание «Отклони отсутствующий alias»: в файле есть `ValidateAlias` с `panic("TODO")`. Импорты `"strings"` и `"unicode/utf8"` добавь, если используешь.
2. Если alias пустой, верни `invalid_alias`.
3. Посчитай руны через `utf8.RuneCountInString`. Больше 24 — `alias_too_long`.
4. Пройди по символам через `range`: каждый должен быть строчной латинской буквой, цифрой или дефисом. Иначе — `invalid_alias`.
5. Иначе верни пустую строку.
6. Нажми «Запустить» и сравни с блоком выше.
7. Нажми «Проверить».

**Как проверить себя.** Две пустые строки; все три критерия зелёные.

**Если не принято.**
- Пробел в alias принят → проверка символов должна стоять до успеха.
- Заглавная буква принята → проверяются только строчные латинские буквы.
- Длинный alias даёт `invalid_alias` → сначала проверка длины, потом символов.

> **Подсказка.** Один цикл с условием на каждый символ; длина — отдельная проверка до него.

### Задание 2 · Проверь target URL

**Цель.** Разрешить абсолютный адрес со схемой `http` или `https` и хостом, без `userinfo` и без фрагмента, длиной до 2048 байт. Иные ошибки: `invalid_target`, `target_too_long`, `unsupported_scheme`. Успех — пустая строка.

**Ожидаемый вывод** — входы `https://go.dev/` и `http://example.test/docs`:

```text
""
""
```

**Шаги.**
1. Выбери задание «Проверь target URL»: в файле есть `ValidateTarget` с `panic("TODO")`. Добавь импорт `"net/url"`.
2. Если строка длиннее 2048 байт, верни `target_too_long`.
3. Разбери строку через `url.Parse`. Ошибка разбора — `invalid_target`.
4. Если схема пустая, адрес относительный — `invalid_target`.
5. Если схема не `http` и не `https`, — `unsupported_scheme`.
6. Если хост пустой, есть `userinfo` или фрагмент, — `invalid_target`.
7. Иначе верни пустую строку.
8. Нажми «Запустить» и сравни с блоком выше.
9. Нажми «Проверить».

**Как проверить себя.** Две пустые строки; все три критерия зелёные.

**Если не принято.**
- `javascript:alert(1)` даёт `invalid_target` → сначала проверяется схема, потом хост.
- Адрес с `#frag` принят → фрагмент отвергается отдельно.
- Адрес `https://u:p@example.test/` принят → `userinfo` запрещён.

> **Подсказка.** Порядок проверок важен: форма, потом схема, потом хост и детали.

## Проверь себя

- Чем проверка формы отличается от проверки правила предметной области?
- Почему ошибка для клиента — код, а не текст внутреннего исключения?
- Зачем читать тело через `LimitReader` до декодирования?
- Почему после одного JSON-объекта проверяют хвост потока?
- Чем 409 отличается от 400 по смыслу?

## Итог

- Сначала проверяется форма, потом правила; длина проверяется до разбора.
- Ошибка — стабильный код из набора контракта; внутренний текст не уходит клиенту.
- Тело читается с лимитом и разбирается ровно как один объект.
