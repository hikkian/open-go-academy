# Повторы, шум и статистическая неопределённость

## Что ты сделаешь

Ты научишься обращаться с повторными измерениями так, чтобы не обмануть себя: хранить выборку целиком, считать медиану и размах, сравнивать размер эффекта с шумом и не выбирать «удобный» прогон. Три функции урока — `Median`, `ValidBenchmarkSample`, `RelativeSpreadPercent` — это самые простые сводки выборки, которые ты будешь применять к выводу `go test -bench -count=N` из прошлого урока.

## Измерение — это выборка из меняющейся среды

Время выполнения зависит от прогрева процессора, фоновых процессов, частоты CPU, сборки мусора, состояния кеша, соседнего контейнера и его квоты. Go не превращает машину в лабораторный прибор. Несколько повторов показывают разброс, но не гарантируют независимость: близкие запуски делят общее состояние машины. Поэтому сохраняй порядок запусков и условия, а для сравнения двух вариантов чередуй их, чтобы временной дрейф не совпал целиком с одним из них.

```go group=order mode=run
package main

import "fmt"

func main() {
    naive := []string{"A", "A", "A", "B", "B", "B"}
    interleaved := []string{"A", "B", "B", "A", "A", "B"}
    fmt.Println("серия:", naive)
    fmt.Println("чередование:", interleaved)
}
```

Вывод:

```text
серия: [A A A B B B]
чередование: [A B B A A B]
```

Если машина постепенно греется и замедляется, в серии всё замедление достанется варианту B, и он проиграет незаслуженно. Чередование распределяет дрейф между вариантами; порядок при этом фиксируется и записывается, чтобы его можно было воспроизвести.

> **Важно.** Выбор «лучшего» прогона — не оптимизация, а систематическое смещение. Самый быстрый повтор говорит о том, что машина однажды была свободна, а не о том, что код стал быстрее.

## Медиана, среднее и хвост

Среднее чувствительно к одному большому выбросу; медиана — центральное значение упорядоченной выборки — устойчива к нему, но ничего не говорит о хвосте. Квантили описывают границы доли наблюдений, но требуют достаточно большой выборки. Ни одна сводка не заменяет исходный набор чисел: сначала сохраняется выборка, потом считается что угодно.

```go group=median mode=run
package main

import "fmt"

func median(values []int) int {
    v := append([]int(nil), values...)
    for i := 1; i < len(v); i++ {
        for j := i; j > 0 && v[j] < v[j-1]; j-- {
            v[j], v[j-1] = v[j-1], v[j]
        }
    }
    n := len(v)
    if n%2 == 1 {
        return v[n/2]
    }
    return (v[n/2-1] + v[n/2]) / 2
}

func main() {
    runs := []int{612, 598, 605, 1890, 601}
    sum := 0
    for _, r := range runs {
        sum += r
    }
    fmt.Println("среднее:", sum/len(runs), "медиана:", median(runs))
    fmt.Println("исходный порядок сохранён:", runs)
}
```

Вывод:

```text
среднее: 861 медиана: 605
исходный порядок сохранён: [612 598 605 1890 601]
```

Один прогон в 1890 наносекунд поднял среднее почти в полтора раза; медиана осталась около типичного значения. Но именно этот выброс — повод спросить, что случилось: фоновый build, сборка мусора, другое число итераций. Медиана скрывает вопрос, а не отвечает на него. Функция сортирует копию, потому что исходная выборка с порядком запусков — тоже данные.

> **Типичная ошибка.** Удалить крайнее наблюдение «потому что оно портит картину». Исключать можно только по правилу, записанному до прогона и подтверждённому технической причиной в логе; исключённая точка остаётся в архиве с причиной.

## Размер эффекта против шума

Разница на доли процента может быть меньше естественного разброса, а устойчивое небольшое улучшение на дорогом пути — ценным. Универсального «порога 5 %» не существует: сначала опиши, какая практическая значимость нужна, потом оцени, достаточно ли наблюдений. Грубая мера шума — размах относительно минимума: насколько самый медленный повтор отличается от самого быстрого.

```go group=spread mode=run
package main

import "fmt"

func spreadPercent(values []int) int {
    lo, hi := values[0], values[0]
    for _, v := range values {
        if v < lo {
            lo = v
        }
        if v > hi {
            hi = v
        }
    }
    return (hi - lo) * 100 / lo
}

func main() {
    before := []int{100, 110, 120}
    after := []int{97, 108, 118}
    fmt.Println("разброс до:", spreadPercent(before), "% после:", spreadPercent(after), "%")
    fmt.Println("эффект по минимуму:", before[0]-after[0], "нс при размахе", before[2]-before[0], "нс")
}
```

Вывод:

```text
разброс до: 20 % после: 21 %
эффект по минимуму: 3 нс при размахе 20 нс
```

Эффект в три наносекунды при размахе в двадцать — это шум, и честный вывод здесь «данных недостаточно», а не «ускорение на три процента». Размах чувствителен к выбросам и не моделирует распределение; его польза в том, что он быстро показывает, когда сравнивать пока нечего.

> **Зачем.** `benchstat` сравнивает выводы benchmark и оценивает значимость различий, но не исправит несопоставимый workload, скрытую смену среды или выбор только выгодных запусков. Инструмент работает с тем, что ему дали.

## Если результат нестабилен

Увеличь число повторов или упрости эксперимент, а не округляй до желаемого вывода. Более длинный прогон иногда снижает относительный шум, но меняет воздействие на систему и может включить накопительный эффект — кеш, рост кучи, очередь сборщика мусора. Сравнение ограничивают по времени и ресурсам заранее. Редкие события в хвосте, например p99, требуют на порядки больше наблюдений, чем среднее поведение: малая выборка не даёт о них судить. Для настоящего SLO нужны данные из потока, похожего на production, которого учебные функции не создают.

В отчёте о сравнении указывай четыре вещи рядом: число повторов каждого варианта, медианы, размахи и сам вывод. Читатель должен видеть, что эффект сравнивали с шумом, а не только итоговую строчку «быстрее на N %». Если выборки разного размера или сняты в разные дни, это тоже часть отчёта, а не примечание мелким шрифтом.

Рандомизация порядка полезна при скрытом временном тренде, но seed и порядок должны быть воспроизводимы. И не округляй до сравнения: округлённая таблица может скрыть различие в величине шума. Точность отображения и точность знания — разные вещи, и обе указываются отдельно.

## Сколько повторов нужно

Готового числа нет; есть рассуждение. Эффект, который ты ищешь, и размах, который видишь, задают масштаб: если ожидаемое улучшение сравнимо с размахом трёх повторов, трёх недостаточно, и каждый новый повтор снижает неопределённость медленно. Если эффект в несколько раз больше размаха, уже пять-десять повторов дадут устойчивую картину. Запиши число повторов до прогона и не увеличивай его «пока не получится».

Первые итерации часто медленнее из-за прогрева кеша и роста кучи; обвязка Go частично это сглаживает, но при коротком `-benchtime` прогрев остаётся заметным. Поэтому фиксируй `-benchtime` и `-count` в команде и не сравнивай прогоны с разными режимами. Общее время эксперимента ограничь заранее: десять повторов двух вариантов по секунде — двадцать секунд, и это уже сопоставимо с фоновыми задачами машины, которые тоже попадут в выборку.

> **Зачем.** Число повторов — часть манифеста baseline из первого урока: без него другой человек не воспроизведёт ни разброс, ни вывод.

## Типичные ошибки

- Отбор самого быстрого повтора как результата: смещение, а не измерение.
- Среднее по выборке с выбросом как единственная сводка: один прогон меняет вывод.
- Исключение точки без заранее записанного правила: выборка подогнана под ответ.
- Серия A, затем серия B без чередования: дрейф машины достаётся одному варианту.
- Эффект меньше размаха, объявленный улучшением: шум, выданный за сигнал.
- Оценка p99 по десяти прогонам: хвост не наблюдался, судить не о чем.

Выпиши обе выборки в таблицу с колонками `run`, `variant`, `ns/op`, `note`. Посчитай медиану и размах каждой руками по функциям из примеров, затем сравни эффект по медианам с размахом. Сформулируй один из двух выводов: «эффект больше размаха, повторить с другим входом» или «данных недостаточно, увеличить повторы до N». ## Если что-то пошло не так

- `import "sort" is not allowed` → импорты в заданиях запрещены: отсортируй копию простой вставкой, как в примере.
- Исходный срез изменился после вызова → сортируешь `values` на месте; копируй через `append([]int(nil), values...)`.
- Красный пример для `[1, 3, 5, 7]` → для чётной длины нужно целочисленное среднее двух центральных: `(3 + 5) / 2 = 4`.
- `-1` вместо `0` для всех нулей → порядок проверок: нулевой минимум при нулевом максимуме — нулевой размах, не ошибка.
- `true` для пустой выборки в задании 2 → проверка длины `>= 3` отсутствует.

## Практика

Три функции без `main` и печати; среда вызывает их с готовыми срезами и показывает результаты числами и `bool`.

### Задание 1 · Easy: найди медиану повторов

**Цель.** Вернуть медиану целочисленной выборки: отсортировать копию, для чётной длины взять целочисленное среднее двух центральных; для пустого среза — `0`.

**Ожидаемый вывод** — для `[9, 1, 5]` и `[1, 3, 5, 7]`:

```text
5
4
```

**Шаги.**
1. Выбери задание «Easy»: сигнатура `func Median(values []int) int`. Импорты запрещены, `sort` недоступен.
2. При `len(values) == 0` верни `0`. Скопируй срез и отсортируй копию сортировкой вставками (как в примере).
3. Для нечётной длины верни `v[n/2]`; для чётной — `(v[n/2-1] + v[n/2]) / 2`.
4. «Запустить», «Проверить» — закрытые примеры: `[-3, -1, 2]` → `-1`, `[1]` → `1`.

**Как проверить себя.** Исходный срез после вызова не изменился; отрицательные значения сортируются правильно; одна точка — сама себе медиана.

**Если не принято.**
- Красный закрытый пример `[-3, -1, 2]` → сортировка сравнивает неверно или пропускает отрицательные.
- `4` вместо `5` для `[9, 1, 5]` → взято среднее вместо центрального элемента.
- Отказ из-за импорта → убери `sort`, напиши вставку руками.

> **Подсказка.** Для огромных чисел `(a + b) / 2` может переполниться; эталон считает `a/2 + b/2 + (a%2 + b%2)/2`. В закрытых примерах таких чисел нет, но запомни приём.

### Задание 2 · Medium: проверь пригодность выборки ns/op

**Цель.** Считать выборку пригодной для учебного сравнения, если в ней не меньше трёх измерений и каждое положительно.

**Ожидаемый вывод** — для `[12, 14, 13]`:

```text
true
```

**Шаги.**
1. Выбери задание «Medium»: сигнатура `func ValidBenchmarkSample(values []int) bool`. Импорты запрещены.
2. Если `len(values) < 3` — `false`. Пройди по значениям: любое `<= 0` — `false`.
3. Иначе `true`. «Запустить», «Проверить» — закрытые примеры: `[]` → `false`, `[12, -1, 13]` → `false`.

**Как проверить себя.** Три повтора — условие задания, не универсальная рекомендация; функция проверяет форму выборки, а не статистическую достаточность.

**Если не принято.**
- `true` для пустого среза → нет проверки длины.
- `true` при отрицательном значении → условие `< 0` вместо `<= 0`: ноль наносекунд тоже невозможен.

> **Подсказка.** Это два условия: длина и знак каждого элемента; порядок проверок не важен для результата, но длину проверить первой дешевле.

### Задание 3 · Hard: оцени диапазон повтора относительно минимума

**Цель.** Вернуть `floor((max − min) · 100 / min)` для непустой выборки неотрицательных чисел; пустая выборка или нулевой минимум при положительном максимуме → `−1`; все нули → `0`.

**Ожидаемый вывод** — для `[100, 110, 120]`:

```text
20
```

**Шаги.**
1. Выбери задание «Hard»: сигнатура `func RelativeSpreadPercent(values []int) int`. Импорты запрещены.
2. Пустой срез → `-1`. Найди минимум и максимум; любое отрицательное значение → `-1`.
3. Если минимум равен нулю: максимум тоже ноль → `0`, иначе → `-1`.
4. Иначе верни `(max - min) * 100 / min` — целочисленное деление уже округляет вниз. «Запустить», «Проверить» — закрытые примеры: `[50, 50, 50]` → `0`, `[]` → `-1`.

**Как проверить себя.** Для одинаковых значений размах нулевой; деление на нулевой минимум не выполняется никогда; ответ — целые проценты без дробей.

**Если не принято.**
- `panic: integer divide by zero` → проверка нулевого минимума стоит после деления.
- `-1` для `[50, 50, 50]` → нулевой размах принят за ошибку.
- `0` для пустого среза → пустая выборка — ошибка входа, не «нулевой разброс».

> **Подсказка.** Эталон дополнительно защищается от переполнения: если `max − min` больше `MaxInt / 100`, возвращает `-1`. Добавь это, если хочешь честный ответ на любых числах.

## Проверь себя

- Почему нельзя отбирать только самый быстрый повтор?
- Что показывает медиана и чего она не показывает?
- Когда допустимо исключить запуск?
- Что означает слишком малый эффект относительно разброса?
- Почему редкий p99 требует большой выборки?

## Итог

- Выборка хранится целиком и в порядке запусков; сводки считаются по копии.
- Медиана устойчива к выбросу, но не объясняет его; размах быстро показывает, когда эффект тонет в шуме.
- Чередуй варианты, записывай правило исключения до прогона и не выдавай шум за ускорение.
