# Транзакции и миграции

## Что ты сделаешь

Ты напишешь три функции, которые принимают решения вокруг транзакции и миграций: `ShouldRollback` решает, нужна ли отмена, `MigrationVersionAllowed` проверяет версию миграции, `RetryableSQLState` решает, можно ли повторить операцию. Ни одна функция не открывает транзакцию: проверяется правило, по которому её открывают и закрывают.

## Транзакция — группа, которая проходит целиком или не проходит вовсе

Транзакция объединяет несколько изменений в одну единицу. `COMMIT` фиксирует все изменения, `ROLLBACK` отменяет те, что ещё не зафиксированы. После `COMMIT` откат уже ничего не отменяет: изменения стали постоянными.

Граница транзакции проходит по операции, а не по строке. Если перевод денег меняет два счёта, и второе изменение упало, первое нельзя оставить: иначе деньги исчезнут. Поэтому откат решается до фиксации.

Шаблон Go для этого — откат по умолчанию, который отменяется только после успешного `Commit`:

```go
package main

import "fmt"

type tx struct {
    done bool
}

func (t *tx) Rollback() {
    if !t.done {
        fmt.Println("rollback")
    }
}

func (t *tx) Commit() {
    t.done = true
    fmt.Println("commit")
}

func work(fail bool) {
    t := &tx{}
    defer t.Rollback()
    if fail {
        return
    }
    t.Commit()
}

func main() {
    work(true)
    work(false)
}
```

Вывод: `rollback`, затем `commit`. Если работа упала, откат сработал. Если зафиксировано — откат молчит.

> **Важно.** Откат после `COMMIT` не нужен и ничего не отменит. Решение о нём принимается по тому, была ли фиксация.

## Миграции — история схемы

Миграция меняет структуру базы: добавляет таблицу или индекс. Миграции нумеруют и применяют строго по порядку, каждая ровно один раз. Версия — точный идентификатор, например `0001_init`. Произвольная строка или путь к файлу как версия недопустимы: по ним нельзя восстановить порядок.

```go
package main

import "fmt"

func main() {
    migrations := []string{"0001_init", "0002_link_index"}
    for _, m := range migrations {
        fmt.Println("apply", m)
    }
}
```

Вывод: `apply 0001_init` и `apply 0002_link_index`. Порядок списка и есть история.

## Повтор только с границей

Не всякую ошибку надо повторять. Конфликт сериализации (`40001`) и взаимная блокировка (`40P01`) означают, что другой запрос мешал, и повтор имеет смысл. Ошибка нарушения ограничения (`23505`) повторится снова, потому что данные те же. Повтор ограничивают числом попыток:

```go
package main

import "fmt"

func main() {
    attempts := 0
    for attempts < 3 {
        attempts++
        if attempts == 2 {
            break
        }
    }
    fmt.Println(attempts)
}
```

Вывод: `2`. Цикл прервался на второй попытке, потому что условие успеха выполнилось.

> **Типичная ошибка.** Повторять запрос без лимита. Если ошибка постоянная, цикл повторов никогда не завершится и заберёт ресурсы базы.

## Если что-то пошло не так

- Данные частично изменились после ошибки → откат не выполнен или фиксация стоит раньше проверки.
- Миграция применилась дважды → нет записи о применённой версии; проверяй её перед запуском.
- Повтор не останавливается → нет числа попыток или условия выхода.
- `undefined: tx` → тип объявлен в другом файле или не объявлен.

## Итог

- Транзакция проходит целиком или не проходит; решение об откате принимается до фиксации.
- Миграции — точные версии в порядке применения; каждая применяется один раз.
- Повтор разрешён только для ошибок конкуренции и ограничен числом попыток.
