# Массивы, срезы и простые данные

## Зачем хранить несколько значений

Когда известны семь измерений за неделю, создавать семь отдельных переменных неудобно. Коллекция (collection, набор) хранит последовательность элементов одного типа. Массив и срез дают доступ к элементу по индексу, а циклы позволяют обработать каждый элемент одним правилом.

Массив (`array`) имеет фиксированную длину, входящую в его тип. `[3]int` и `[4]int` — разные типы. Срез (`slice`) — удобное представление последовательности элементов массива: он имеет длину и ёмкость и обычно используется, когда размер данных меняется.

```go
package main

import "fmt"

func main() {
    temperatures := [3]int{18, 20, 17}
    week := temperatures[:]
    fmt.Println(len(temperatures), len(week), cap(week))
}
```

Обе длины равны 3, ёмкость среза тоже 3. Запись `temperatures[:]` создаёт срез поверх того же массива; копирования элементов здесь нет.

## Индекс начинается с нуля

Первый элемент имеет индекс `0`, следующий — `1`. Для среза длины `n` допустимы индексы от `0` до `n-1`. Обращение к `values[len(values)]` выходит за границу (out of bounds) и приводит к панике во время выполнения. Сначала проверьте длину, прежде чем читать конкретный индекс.

```go
package main

import "fmt"

func first(values []int) int {
    if len(values) == 0 {
        return 0
    }
    return values[0]
}

func main() {
    fmt.Println(first([]int{7, 9}))
    fmt.Println(first(nil))
}
```

Контракт примера выбрал `0` для пустого среза. Это не универсальный ответ: иногда лучше вернуть дополнительный `bool` или ошибку. Важен явный выбор, чтобы вызывающая сторона знала, что значит отсутствие элемента.

## Длина и ёмкость

`len(slice)` — количество элементов, доступных сейчас. `cap(slice)` — сколько элементов помещается в текущем базовом массиве, начиная с первого элемента среза, до необходимости выделять больший массив. Всегда верно `0 <= len(s) <= cap(s)`.

```go
package main

import "fmt"

func main() {
    values := make([]int, 2, 4)
    fmt.Println(len(values), cap(values))
    values[0] = 5
    values[1] = 8
    values = append(values, 13)
    fmt.Println(values, len(values), cap(values))
}
```

Сначала длина 2, ёмкость 4. После `append` длина становится 3. Ёмкость может остаться равной 4, потому что место есть. Если добавлять дальше и места не хватает, `append` выделит новый базовый массив и скопирует элементы. Не полагайтесь на конкретную стратегию роста ёмкости: она является деталью реализации.

Нельзя записывать в `values[2]`, пока длина остаётся 2, даже если `cap(values)` равна 4. Ёмкость показывает потенциал расширения через `append`, а не число сразу доступных индексов. Чтобы получить третий доступный элемент, используйте `append` или сформируйте срез большей длины.

## append возвращает срез

Функция `append` может вернуть срез с новой длиной и даже новым массивом. Поэтому результат надо присвоить: `values = append(values, 10)`. Если проигнорировать возвращённый срез, переменная не начнёт ссылаться на добавленный элемент, а при выделении нового массива добавление будет потеряно для этого значения.

```go
package main

import "fmt"

func main() {
    scores := []int{70, 80}
    scores = append(scores, 95)
    fmt.Println(scores)
}
```

Вызов добавляет элемент в конец среза и возвращает актуальный срез. `append` не превращает срез в отдельную независимую коллекцию и сам по себе не гарантирует копию всех прежних элементов.

## Перебор через range

Цикл `for range` проходит по последовательности. В форме `for index, value := range values` переменная `index` получает позицию, а `value` — копию текущего значения элемента. Если позиция не нужна, используйте `_`: `for _, value := range values`. Для обычных целых не изменяйте сам срез через переменную `value`, ожидая изменения исходного элемента: это локальная копия. Для записи используйте индекс.

```go
package main

import "fmt"

func sum(values []int) int {
    total := 0
    for _, value := range values {
        total += value
    }
    return total
}

func main() {
    fmt.Println(sum([]int{4, 6, 10}))
}
```

Программа выводит `20`. У пустого среза цикл выполняется ноль раз, поэтому сумма остаётся нулём. Это хороший пример функции, чей контракт естественно определён и для пустого ввода.

## Срезы могут разделять массив

Значение-срез хранит ссылку на область базового массива, длину и ёмкость. Копирование самого значения среза копирует эту небольшую информацию, но не обязательно элементы. Поэтому два среза могут смотреть на одну память.

```go
package main

import "fmt"

func main() {
    original := []int{2, 4, 6}
    view := original[:2]
    view[0] = 99
    fmt.Println(original)
}
```

Вывод `[99 4 6]`: оба среза видят один базовый массив. Такая общая память называется aliasing (совместный доступ через псевдонимы). Она может быть полезна и может удивить. Если нужна независимая копия, заранее выделите новый срез и вызовите `copy(destination, source)`.

```go
package main

import "fmt"

func main() {
    source := []int{2, 4, 6}
    clone := make([]int, len(source))
    copied := copy(clone, source)
    clone[0] = 99
    fmt.Println(copied, source, clone)
}
```

`copy` передаёт элементы, а не связь с массивом; изменение `clone` не меняет `source`. Число `copied` сообщает, сколько элементов скопировано: минимум из длин источника и назначения. Если destination короче, копируются только элементы, для которых есть место.

## nil и пустой срез

Нулевой срез `var values []int` имеет `len` и `cap` равные нулю и не указывает на выделенный массив. Литерал `[]int{}` также имеет нулевую длину, но это не nil. Для перебора, `len` и `append` оба варианта обычно подходят. Не сравнивайте срезы через `==` с другим срезом: разрешено сравнение только с `nil`.

При добавлении в nil-срез `append` создаёт необходимое место и возвращает срез. Поэтому суммирование, фильтрацию в новый срез и обычный `range` можно безопасно начинать с nil значения. Условие задачи должно отдельно решить, важна ли разница между nil и пустым срезом в JSON или API; пока такие системы мы не изучаем.

## Частые ошибки и проверка границ

Проверьте: индекс не равен длине; длина не равна ёмкости; `append` надо присваивать обратно; перебор по значению не меняет исходный элемент; короткое присваивание среза не копирует элементы. При каждом цикле задайте три вопроса: что происходит для пустого входа, где заканчивается допустимый индекс и изменяется ли исходная последовательность?

В заданиях сначала посмотрите на тип входа. Не преобразуйте неизвестные JSON-значения к пустому интерфейсу: задача имеет фиксированный `[]int`. Обрабатывайте именно типизированный контракт. В браузере можно запускать сколько угодно небольших проверок до отправки.

## Практика

### Простое — `sumSlice`

Сложи целочисленные элементы среза. Пустой и nil срез дают 0. Используй `range`; функция возвращает значение и не печатает.

### Среднее — `countAbove`

Посчитай элементы строго больше порога, который в упражнении передаётся аргументом. Равный порогу элемент не входит. Пустой срез даёт 0. В трассировке для каждого элемента отметь сравнение и текущее количество.

### Сложное — `appendCopy`

Создай независимую копию входа, добавь к ней одно значение и верни новую последовательность. Не изменяй срез вызывающего кода. Проверь nil-вход и повторяющиеся значения.

## Предсказание среза на бумаге

Возьмите `base := [5]int{10, 20, 30, 40, 50}` и `view := base[1:4]`. Длина view равна трём, потому что доступны элементы 1, 2 и 3. Ёмкость равна четырём: от позиции 1 до конца массива остаются четыре элемента. Если выполнить `view[0] = 99`, изменится `base[1]`. Проверьте ответы маленькой программой.

Вызов `append(view, 60)` может затронуть общий массив, если у view есть свободная ёмкость. Если места не хватает, Go может выделить новый массив. Не стройте корректность на предположении, что любой append изолирует данные. Когда нужна копия, `make` и `copy` явно показывают намерение.

Переменная `var values []int` безопасна для `len`, `cap`, `range` и `append`, но индексировать `values[0]` нельзя. Это удобно: функцию можно начать собирать с nil-среза, добавляя подходящие элементы.

Для фильтрации заведите `result := []int{}` или nil-срез, пройдите исходную последовательность через range и добавляйте подходящие элементы. Не присваивайте исходный срез в result, если обещали независимый список: они могут разделять массив. Цель операции определяет выбор между представлением, копированием и новым результатом.
