# Тесты, таблицы и отладка

## Что ты сделаешь

Ты напишешь три функции и проверишь каждую на нескольких входах: `isPassing` сравнит фактическое значение с ожидаемым, `minMax` найдёт минимум и максимум и скажет, есть ли вообще числа, `countMatches` посчитает точные совпадения. Главное умение урока — выбрать входы, которые ломают код, а не только те, на которых он прав.

## Таблица случаев

Проверка одного входа доказывает мало. Удобнее держать список случаев: каждая строка — входы, ожидаемый результат, а цикл сравнивает фактический результат с ожидаемым:

```go
package main

import "fmt"

func double(n int) int {
    return n * 2
}

func main() {
    cases := []struct {
        in, want int
    }{
        {1, 2},
        {0, 0},
        {-3, -6},
    }
    for _, c := range cases {
        got := double(c.in)
        fmt.Println(c.in, got == c.want)
    }
}
```

Вывод: `1 true`, `0 true`, `-3 true`. Сравнение `got == c.want` даёт однозначный ответ: совпало или нет, без угадывания по глазам.

> **Важно.** В таблицу обязательно входят граничные случаи: ноль, пустой срез, минимальное и максимальное значение. Именно на них код чаще всего ломается.

## Граница: пустой вход

Пустой срез — типичная граница. Минимума у пустого набора нет, поэтому функция должна сказать об этом явно:

```go
package main

import "fmt"

func first(values []int) (int, bool) {
    if len(values) == 0 {
        return 0, false
    }
    return values[0], true
}

func main() {
    fmt.Println(first(nil))
    fmt.Println(first([]int{5}))
}
```

Вывод: `0 false` и `5 true`. Второе значение говорит, есть ли настоящий результат, и вызывающая сторона не принимает нули за данные.

> **Типичная ошибка.** Проверка только на обычных входах: `[3, 1, 2]` проходит, а пустой срез падает с `index out of range`. Таблица без границ даёт ложное чувство безопасности.

## Отладка: минимальное воспроизведение

Когда результат непонятен, не меняй код наугад. Сначала уменьши вход до самого маленького, на котором ошибка ещё видна. Затем выпиши промежуточные значения и проверь гипотезу: например, цикл пропускает последний элемент или индекс выходит за границу.

Временная печать помогает: `fmt.Println` внутри цикла покажет, какие значения проходят через код. После проверки такую печать убирают, чтобы она не осталась в решении.

## Если что-то пошло не так

- `panic: runtime error: index out of range [0] with length 0` → обращение к первому элементу без проверки длины.
- Результат верный на одном входе и неверный на другом → проверь граничные входы таблицы.
- Проверка проходит, а задание не принято → вероятно, код работает на тестовых входах, но не на закрытых: попробуй пустой и отрицательный вход.
- `declared and not used` → переменная из отладки осталась в коде: удали её.

## Практика

Три задания. Функции проверяются на входах из блока «Ожидаемый вывод»; закрытые примеры видны только в «Проверить».

### Задание 1 · Напиши первую проверку

**Цель.** Вернуть `true`, если фактическое значение `got` равно ожидаемому `want`; иначе `false`.

**Ожидаемый вывод** — входы `3` и `3`, затем `3` и `4`:

```text
true
false
```

**Шаги.**
1. Выбери задание «Напиши первую проверку»: в файле есть `isPassing` с `panic("TODO")`. Замени тело функции.
2. Сравни два целых числа: `return got == want`.
3. Нажми «Запустить» и сравни с блоком выше.
4. Нажми «Проверить».

**Как проверить себя.** Два значения: `true` и `false`; все три критерия зелёные.

**Если не принято.**
- Для `0` и `0` выходит `false` → сравнение написано с другим оператором или переменные перепутаны.
- Закрытый пример с отрицательным числом не совпал → сравнивай значения напрямую, без модуля или других преобразований.

> **Подсказка.** Одна строка `return` с оператором `==`.

### Задание 2 · Реализуй minMax

**Цель.** Для непустого среза вернуть минимум, максимум и `true`. Для пустого или `nil` — `0`, `0` и `false`.

**Ожидаемый вывод** — входы: срез `3, -1, 8`, затем пустой срез. «Запустить» печатает три результата как объект с полями `Min`, `Max` и `OK`:

```text
{"Min":-1,"Max":8,"OK":true}
{"Min":0,"Max":0,"OK":false}
```

**Шаги.**
1. Выбери задание «Реализуй minMax»: в файле есть `minMax` с `return 0, 0, false`.
2. Для `len(values) == 0` оставь этот ответ: пустой вход не даёт минимума.
3. Возьми первый элемент как начальный минимум и максимум.
4. Пройди по остальным элементам с индекса 1 и обновляй минимум и максимум.
5. Верни минимум, максимум и `true`.
6. Нажми «Запустить» и сравни с блоком выше.
7. Нажми «Проверить».

**Как проверить себя.** Два объекта: `{"Min":-1,"Max":8,"OK":true}` и `{"Min":0,"Max":0,"OK":false}`; все три критерия зелёные.

**Если не принято.**
- Для `[3, -1, 8]` минимум 0 → начальное значение взято из нуля, а не из первого элемента.
- Пустой срез падает с паникой → проверка длины должна стоять до обращения к `values[0]`.
- Закрытый пример со всеми отрицательными значениями даёт неверный максимум → начальный максимум должен быть первым элементом, а не нулём.

> **Подсказка.** Первый элемент задаёт начальные минимум и максимум, поэтому нулевое значение не мешает.

### Задание 3 · Посчитай совпадения

**Цель.** Посчитать элементы, точно равные `target`. Исходный срез не меняй. Пустой срез даёт 0.

**Ожидаемый вывод** — входы: срез `1, 2, 2` с целью `2`, затем пустой срез с целью `1`:

```text
2
0
```

**Шаги.**
1. Выбери задание «Посчитай совпадения»: в файле есть `countMatches` с `panic("TODO")`.
2. Заведи счётчик `count := 0`.
3. Пройди по `values` и для каждого элемента, равного `target`, увеличь счётчик на 1.
4. Верни `count`, нажми «Запустить» и сравни с блоком выше.
5. Нажми «Проверить».

**Как проверить себя.** Два числа: `2` и `0`; все три критерия зелёные.

**Если не принято.**
- Для `[1, 2, 2]` выходит 1 → второй элемент не проверен, либо счётчик обновляется не на каждом совпадении.
- Закрытый пример с нулевой целью и нулями в срезе не совпал → сравнивай элементы с `target` без особых условий.
- Закрытый пример с `-2` в срезе не совпал → отрицательные значения сравниваются так же, как положительные.

> **Подсказка.** Один цикл и одно условие внутри него: `if v == target`.

## Итог

- Таблица случаев выбирает входы и ожидаемые результаты; граничные значения входят обязательно.
- Пустой вход проверяется явно: флаг `false` отличает отсутствие результата от настоящего нуля.
- Отладка начинается с минимального входа и проверки гипотезы, а не с правок наугад.
