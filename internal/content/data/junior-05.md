# Целые числа, переполнение и точность денег

## Что ты сделаешь

Ты напишешь три функции для денежных сумм, которые хранятся в копейках: `formatTotal` превратит копейки в строку «`12.34`», `discounted` посчитает скидку без переполнения, `addMoney` сложит две суммы и вернёт ошибку, если результат не помещается в `int64`.

## Целые числа имеют предел

`int64` хранит значения от `-9223372036854775808` до `9223372036854775807`. Выйдя за предел, число не превращается в ошибку: оно «перекручивается» и становится противоположным по знаку. Программа при этом продолжает работать.

```go
package main

import (
    "fmt"
    "math"
)

func main() {
    var x int64 = math.MaxInt64
    x++
    fmt.Println(x)
}
```

Вывод: `-9223372036854775808`. Ни ошибки, ни паники: ответ просто неверен.

> **Важно.** Переполнение целых чисел в Go не проверяется автоматически. Проверку надо писать самому, и делать её нужно до операции, пока результат ещё можно сравнить с границей.

## Деньги в минимальных единицах

Дробные числа `float64` не умеют точно представлять десятичные дроби. Сумма `0.1 + 0.2` даёт не `0.3`, а число, которое печатается с хвостом. Для денег поэтому хранят целое количество минимальных единиц: копейки, центы.

```go
package main

import "fmt"

func main() {
    a, b := 0.1, 0.2
    price := a + b
    cents := int64(10 + 20)
    fmt.Println(price, cents)
}
```

Вывод: `0.30000000000000004 30`. Целые копейки складываются точно, а перевод в «рубли и копейки» делается только при показе.

## Знак и модуль без переполнения

Чтобы напечатать `-5` копеек как `-0.05`, нужно взять модуль числа. Для `int64` он не всегда помещается в `int64`: модуль `-9223372036854775808` равен `9223372036854775808`, а это уже больше предела. Поэтому модуль берут в `uint64` и заранее сдвигают отрицательное число:

```go
package main

import "fmt"

func main() {
    var cents int64 = -5
    var abs uint64
    if cents < 0 {
        abs = uint64(-(cents + 1)) + 1
    } else {
        abs = uint64(cents)
    }
    fmt.Println(abs/100, abs%100)
}
```

Вывод: `0 5`. Сначала берём `-(cents+1)`, которое всегда помещается в `int64`, затем добавляем единицу уже в беззнаковом типе.

> **Типичная ошибка.** Писать `-cents` для отрицательных сумм. Для самого маленького `int64` это переполнение: результат остаётся отрицательным, и печать становится неверной.

## Проверка до операции

Чтобы узнать, поместится ли сумма, сравни одно слагаемое с оставшимся местом до предела. Например, если `right` положительное, сумма переполнит `int64`, когда `left` больше `MaxInt64 - right`. Такая проверка делается до сложения, а не после: после переполнения результат уже не вернуть.

Умножение устроено так же: `price*percent` может переполниться раньше, чем результат станет «большим» по смыслу. Поэтому проверяй диапазон входов заранее.

## Если что-то пошло не так

- Сумма «прыгает» в отрицательные числа → переполнение. Проверь границы до операции.
- Печать суммы с копейками выводит `-0.5` вместо `-0.05` → не добавлена ведущая часть или ноль: копейки всегда двузначные.
- `cannot use ... (untyped int constant) as int64` → константа вне диапазона или не того типа; для больших чисел используй `math.MaxInt64`.
- `declared and not used` → переменная `abs` не используется: проверь ветки.

## Практика

Три задания. Функции проверяются на входах из блока «Ожидаемый вывод»; закрытые примеры видны только в «Проверить».

### Задание 1 · Отформатируй minor units

**Цель.** Вернуть строку вида `[-]целая.две_цифры` для копеек в диапазоне `int64`, включая самое маленькое значение.

**Ожидаемый вывод** — входы `12345` и `-5`:

```text
"123.45"
"-0.05"
```

**Шаги.**
1. Выбери задание «Отформатируй minor units»: в файле есть `formatTotal` с `return ""`. Добавь импорт `"fmt"` после `package main`.
2. Возьми модуль в `uint64`, как в примере выше: для отрицательного числа сдвигай на единицу.
3. Раздели модуль на 100: целая часть и остаток — две цифры.
4. Собери строку через `fmt.Sprintf`: знак, целая часть, точка, две цифры остатка.
5. Нажми «Запустить» и сравни обе строки с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Две строки в кавычках: `"123.45"` и `"-0.05"`; все три критерия зелёные.

**Если не принято.**
- Для `-5` выходит `0.-5` или похожая строка → знак ставится перед целой частью, а не после.
- Закрытый пример с нулём печатается как `0.0` → остаток всегда двузначный: используй `%02d`.
- Самое маленькое значение даёт неверный знак → не используй `-cents` для отрицательного числа.

> **Подсказка.** `fmt.Sprintf("%s%d.%02d", sign, whole, frac)` печатает ведущий ноль в остатке.

### Задание 2 · Проверь процент скидки безопасно

**Цель.** Для цены от 0 и процента от 0 до 100 вернуть цену минус скидку, округлённую вниз. Для недопустимых входов — ошибку `invalid` и 0.

**Ожидаемый вывод** — входы: цена `1000` с процентом `10`, затем цена `-1` с процентом `10`:

```text
[900,null]
[0,"invalid"]
```

Ошибка печатается своим текстом, а при её отсутствии — `null`.

**Шаги.**
1. Выбери задание «Проверь процент скидки безопасно»: в файле есть `discounted` с `return 0, nil`. Добавь импорт `"errors"` и создай ошибку через `errors.New("invalid")`.
2. Проверь диапазон: цена не меньше 0, процент от 0 до 100. Иначе верни `0` и ошибку `invalid`.
3. Посчитай скидку так, чтобы не умножать большие цены целиком: сначала раздели цену на 100, затем умножь на процент и учти остаток от деления.
4. Верни `price - discount` и `nil`, нажми «Запустить» и сравни с блоком выше.
5. Нажми «Проверить».

**Как проверить себя.** Две строки: `[900,null]` и `[0,"invalid"]`; все три критерия зелёные.

**Если не принято.**
- Для цены `MaxInt64` выходит неверное значение → умножение переполнилось: раздели цену на 100 до умножения.
- Цена `-1` даёт не ошибку → проверка диапазона должна идти до вычислений.
- Для процента 0 результат не равен цене → скидка должна быть 0, а не пустой строкой.

> **Подсказка.** Сначала проверка входов, потом вычисление. Целое деление округляет вниз, и это правило контракта.

### Задание 3 · Сложи деньги с обнаружением переполнения

**Цель.** Сложить две суммы в минимальных единицах. Если результат не помещается в `int64`, вернуть `0` и ошибку `overflow`.

**Ожидаемый вывод** — входы `120` и `-20`, затем `10` и `15`:

```text
[100,null]
[25,null]
```

**Шаги.**
1. Выбери задание «Сложи деньги с обнаружением переполнения»: в файле есть `addMoney` с `return 0, nil`. Добавь импорт `"errors"` и две константы: `const maxInt64 = 1<<63 - 1` и `const minInt64 = -1 << 63`.
2. Если `right > 0` и `left > maxInt64 - right`, сумма не помещается: верни `0` и ошибку `errors.New("overflow")`.
3. Если `right < 0` и `left < minInt64 - right`, тоже верни `0` и эту же ошибку.
4. Иначе верни `left + right` и `nil`.
5. Нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Две строки: `[100,null]` и `[25,null]`; все три критерия зелёные.

**Если не принято.**
- `MaxInt64 + 1` возвращает отрицательное число → проверка для положительного `right` не сработала.
- `MinInt64 + (-1)` даёт ошибку, но не `overflow` → проверь отрицательную границу отдельно.
- Закрытый пример `-5 + 5` не совпал → сумма нулевая и без переполнения; не возвращай ошибку.

> **Подсказка.** Сравнивай с `maxInt64 - right` и `minInt64 - right` до сложения: проверять результат уже поздно.

## Итог

- Переполнение `int64` не даёт ошибки: проверку пишешь сам и делаешь до операции.
- Деньги хранят в минимальных единицах целыми числами; показ с точкой — отдельный шаг.
- Модуль отрицательного числа берут в `uint64` после сдвига на единицу, иначе `MinInt64` ломает печать.
