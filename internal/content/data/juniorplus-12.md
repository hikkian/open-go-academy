# PostgreSQL из Go через pgx

## Что ты сделаешь

Ты напишешь три функции, которые описывают границу между базой и приложением без подключения: `OptionalValue` различит отсутствующее значение и пустое, `RepositoryOutcome` переведёт код состояния в результат репозитория, `RetryableSQLState` решит, можно ли повторить запрос. Каждая функция — правило, которое в реальном коде сработает после `Scan` или ошибки драйвера.

## Пул соединений — ресурс приложения

Драйвер `pgx` открывает соединения с базой. Соединение дорогое, поэтому его держат в пуле (`pgxpool`) и переиспользуют. Пул создаётся один раз при старте приложения и закрывается при остановке. Каждый запрос получает соединение из пула и возвращает его обратно.

Пул — это ресурс, а не глобальная переменная, которую можно создавать в каждом обработчике. Поэтому он передаётся в repository аргументом или полем структуры.

## Context проходит через всю цепочку

Каждый запрос к базе принимает `context.Context`. Если клиент ушёл или истёк срок, context отменяется, и драйвер прерывает запрос. Поэтому context передаётся дальше по цепочке и не подменяется `context.Background()`.

```go
package main

import (
    "context"
    "errors"
    "fmt"
    "time"
)

func main() {
    ctx, cancel := context.WithTimeout(context.Background(), time.Nanosecond)
    defer cancel()
    <-ctx.Done()
    fmt.Println(errors.Is(ctx.Err(), context.DeadlineExceeded))
}
```

Вывод: `true`. Срок истёк, и ошибка узнаётся через `errors.Is`.

## NULL и пустое значение

В базе поле может быть `NULL`: значения нет вообще. Пустая строка — это значение, которое есть. Различие сохраняют указателем или отдельным признаком наличия. Если его потерять, пустое значение и отсутствующее станут одинаковыми:

```go
package main

import "fmt"

func main() {
    var nickname *string
    empty := ""
    fmt.Println(nickname == nil, empty == "")
}
```

Вывод: `true true`. `nil`-указатель означает `NULL`, а `""` — существующее пустое значение.

## Repository — граница с данными

Repository знает про SQL и ошибки базы, но не знает про HTTP. Он возвращает значение или понятную ошибку. Отсутствие строки — отдельная ошибка, которую проверяют через `errors.Is`, а не по тексту:

```go
package main

import (
    "errors"
    "fmt"
)

var ErrNotFound = errors.New("not found")

func find(id int) (string, error) {
    if id != 1 {
        return "", fmt.Errorf("find %d: %w", id, ErrNotFound)
    }
    return "ada", nil
}

func main() {
    _, err := find(2)
    fmt.Println(err, errors.Is(err, ErrNotFound))
}
```

Вывод: `find 2: not found true`. Текст понятен человеку, а признак ошибки проверяется надёжно.

> **Типичная ошибка.** Возвращать клиенту `err.Error()` из repository. Текст может раскрыть имя таблицы или запрос; наружу уходит категория.

## Если что-то пошло не так

- `no rows in result set` → запрос вернул ноль строк; это отдельный случай, а не ошибка сервера.
- Соединения исчерпаны → не закрывают `rows` после `Query`; закрывай через `defer`.
- Значение `NULL` попало в `string` и упало → поле в Go должно быть указателем или признаком наличия.
- Запрос не отменяется по таймауту → context не передан драйверу.
