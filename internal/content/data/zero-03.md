# Вычисления и ветвления

## Зачем это нужно

Тарифы, правила доступа и термометр должны по-разному реагировать на разные входы. Компьютер не угадывает условие: программист явно задаёт сравнения и ветви. В этой главе уже знакомые числа и bool из [zero-02](lesson:zero-02) станут основой решения.

## Выражения, числа и логика

Выражение вычисляется в значение: `2+3` даёт `5`, `n<0` — bool. Целочисленные операторы `+ - * / %` работают с целыми числами. Деление `7/2` равно `3`: дробная часть отбрасывается; остаток `7%2` равен `1`. Делитель ноль недопустим и вызывает аварийное завершение, поэтому проверьте его условием прежде операции. Целые числа имеют конечный диапазон; переполнение тоже требует внимания в реальной задаче.

Умножение и деление приоритетнее сложения и вычитания: `2+3*4` равно 14. Скобки `(2+3)*4` меняют порядок и помогают явно показать замысел. Сравнения `< <= > >= == !=` дают true/false. `=` присваивает, `==` проверяет равенство. Логическое `&&` означает «и», `||` — «или», `!` — отрицание. Для `A && B` нужны обе истинные части; `A || B` достаточно одной. Go использует короткое замыкание: при ложном A выражение `A && B` не вычисляет B; при истинном A выражение `A || B` останавливается.

## Ветвление if

`if condition { ... } else if ... else { ... }` выбирает путь. Условие имеет тип bool, круглые скобки вокруг него в Go не нужны, фигурные скобки обязательны. Проверка идёт сверху вниз, и после найденной ветви остальные пропускаются. Это позволяет во второй ветви не повторять отрицание первой, но порядок должен быть осмысленным.

До кода разделите диапазон словами. В контракте погоды: `n < 0`, `0 <= n && n < 20`, `n >= 20`. Ровно 0 принадлежит средней категории, ровно 20 — верхней. Такие граничные значения надо тестировать явно. Для каждой границы проверяйте число до неё, само число и после: 19, 20, 21. Это ловит ошибку на единицу, которая часто скрывается при тестировании только обычного случая.

## Примеры

```go
package main
import "fmt"
func main() {
 temperature := -2
 if temperature < 0 { fmt.Println("Мороз")
 } else if temperature < 20 { fmt.Println("Прохладно")
 } else { fmt.Println("Тепло") }
}
```

`else if` достижим только когда предыдущая проверка ложна, поэтому средняя ветвь фактически означает от нуля до 19. Сохраните в `main.go` и запустите `go run main.go`.

```go
package main
import "fmt"
func main() {
 denominator := 0
 if denominator == 0 { fmt.Println("На ноль делить нельзя")
 } else { fmt.Println(7 / denominator) }
}
```

Ветка с делением не выполняется при нуле. Предварительная проверка предотвращает аварийную остановку.

```go
package main
import "fmt"
func main() {
 age := 21; hasTicket := true
 if age >= 18 && hasTicket { fmt.Println("Вход разрешён")
 } else { fmt.Println("Вход запрещён") }
}
```

Для допуска нужны два факта одновременно. Попробуйте мысленно заменить `&&` на `||`: правило изменится.

## Ошибки и диагностика

Если написать `=` вместо `==`, вы пытаетесь присвоить, а не сравнить. Если пропущено граничное значение, проверьте `<` против `<=`. Если ожидалась дробь от `7/2`, оба операнда целые. Panic при делении означает, что делитель не был проверен. При запутанном `&&`/`||` выпишите таблицу истинности и перевод условия обычными словами. Составьте таблицу интервалов до цепочки if: каждая величина должна входить ровно в одну ветвь.


В начале каждой карточки есть сигнатура — короткое описание имени функции, её входов и результата. Например, `func f(n int) string` означает: функция `f` принимает целое `n` и возвращает строку. Среда сама подставляет входные данные, вызывает функцию и выводит каждый результат как JSON-текст; строковый результат виден в кавычках JSON. Это представление результата, а не команда печати. Сохраните строку `package main` из стартового кода. Не добавляйте `func main`: запускающую функцию предоставляет проверяющая среда. Эталонное решение лежит отдельно и показывается существующим действием раскрытия.

## Практика

### Easy — Знак числа

Верните `ниже нуля`, `ноль` или `выше нуля` в зависимости от знака n. Границы и дальние значения проверяются.

### Medium — Погода

Для температуры ниже 0 верните `мороз`; от 0 включительно до 20 исключительно — `прохладно`; от 20 включительно — `тепло`.

### Hard — Предупреждение о жаре

Ниже 0 — `мороз`, 0..19 — `норма`, 20..34 — `тепло`, от 35 — `жара`. Каждое целое значение должно попасть ровно в одну категорию.


## Приоритет и разбор условия по шагам

Условия часто становятся длинными, поэтому полезно расставить скобки по смыслу, а не полагаться на запоминание сложного приоритета. Например, правило «допуск взрослого с билетом или сопровождающим» можно записать как `age >= 18 && (hasTicket || hasHost)`. Без скобок было бы трудно заметить, что именно может сопровождать человека. Сначала сформулируйте предложение обычными словами, затем разбейте его на сравнения и объедините их оператором, который соответствует слову «и» или «или».

Короткое замыкание полезно и при проверке нескольких фактов. Если сначала проверить `denominator != 0`, то в выражении `denominator != 0 && numerator/denominator > 1` деление справа не выполняется, когда делитель равен нулю. Однако короткое замыкание не должно заменять ясную ветвь, если вычисление сложно или побочный эффект неочевиден. Размещайте безопасную проверку слева, то есть до операции, требующей этого условия.

## Таблица диапазонов перед кодом

Перед классификацией запишите колонки «условие», «первая точка», «последняя точка», «следующий диапазон». Для погоды это: меньше 0; от 0 до 19; от 20 без верхнего ограничения. Так видно, что промежутки соприкасаются и не перекрываются. Если условия оставляют дырку, например `n < 0` и `n > 0`, точный ноль не классифицирован. Если обе ветви используют `<= 0`, то ноль принадлежит сразу двум правилам, хотя цепочка if выберет первую. Оба случая говорят, что контракт надо переписать.

Проверку границы удобно выполнять систематически: взять L-1, L и L+1 для каждой целочисленной границы L. Для диапазона `20..34` значения 19, 20, 21, 33, 34 и 35 проверяют вход и выход. Публичные примеры могут показывать основные правила; закрытые тесты дополнительно защищают от решения, которое случайно работает только на демонстрационных значениях.

## Значение результата функции

Практические задания возвращают категорию, а не печатают её. Вызвавшая программа сможет принять решение, показать интерфейс или проверить результат. В рабочей программе обычно отдельно описывают обработку входа и представление вывода. Такое разделение упрощает тесты: функция классификации вычисляет значение, а другой слой отвечает за печать. В этой главе мы держим контракт простым: целое количество градусов поступает на вход, один из точных текстовых ярлыков возвращается на выход. Имя параметра может быть любым, пока сохраняется тип и порядок.

Самостоятельное упражнение без AI: напишите таблицу диапазонов из Hard, затем закройте код и переведите каждую строку таблицы в `if/else if`. Пройдите по всем указанным тестам вручную. Только после этого запускайте проверку. Если она показывает неожиданный ярлык, сравните первую не совпавшую границу, а не переписывайте всю функцию. Этот метод локализует ошибку и учит объяснять её причину.



Для отладки временно посчитайте каждую часть условия отдельно: `adult := age >= 18`, `allowed := adult && hasTicket`. Так проще увидеть, какая часть неожиданна. После проверки объедините выражение, если отдельные имена не улучшают смысл. Удалите временные диагностические строки до отправки решения, чтобы результат оставался чистым.

Попробуйте ответить без подсказки; затем используйте раскрываемые ответы в самопроверке урока. Что возвращает сравнение? Чем отличаются = и ==? Когда истинно A && B? Почему важны границы? Что дают 7/2 и 7%2? Как защититься от деления на ноль?

## Повторение и итог

Вернитесь к каждой ключевой идее через день и объясните её своими словами. Напишите минимальный пример без копирования, предскажите результат до запуска и затем проверьте программу. Если ответ отличается, установите конкретный шаг расхождения. Следующий урок опирается на это умение и продолжает путь курса без обязательных внешних материалов.

## Мини-глоссарий

**expression** — выражение, **operator** — оператор, **comparison** — сравнение, **condition** — условие, **branch** — ветвь, **boolean expression** — логическое выражение, **boundary** — граница, **remainder** — остаток
