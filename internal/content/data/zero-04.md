# Повторение действий: циклы

## Зачем это нужно

Сто раз повторить команду вручную — долго и легко ошибиться. Цикл описывает короткое правило и повторяет его для последовательности значений. После [zero-03](lesson:zero-03), где мы выбирали одну ветвь, теперь будем выполнять одинаковый шаг много раз.

## Повторение через for

Цикл (loop, цикл) повторяет блок, когда нужно выполнить одно правило для ряда значений. В Go основной цикл записывается `for`. Классическая форма имеет начальное действие, условие продолжения и шаг: `for i := 1; i <= 3; i++ { ... }`. Сначала создаётся i=1; перед телом проверяется условие; затем выполняется тело и шаг; после него условие проверяется заново. При i=4 условие ложно и выполнение выходит. Итерация — одно исполнение тела. Переменная, объявленная в заголовке цикла, доступна внутри его блока.

Граница важна: `< n` не включает n, а `<= n` включает. Начало 1 подходит задаче «от 1 до N»; начало 0 добавило бы лишнее значение. Цикл с одним условием, например `for total < target`, тоже существует, однако тогда продвижение надо менять в теле. Если состояние не меняется к выходу, цикл может стать бесконечным.

Счётчик отслеживает позицию или число повторов; накопитель собирает итог. Для суммы начните `total := 0` до тела цикла, иначе сбросите результат на каждом проходе. Оператор `total += i` означает `total = total + i`.

Инвариант цикла — утверждение, которое верно в начале и сохраняется каждым шагом. Для суммы 1..n можно сказать: после добавления i в `total` содержится сумма от 1 до i. Начальное значение 0 — сумма до обработки элементов; прибавление текущего i сохраняет правило. Когда i превышает n, вся последовательность обработана. Это практический инструмент рассуждения: что верно до цикла, после одного шага, и почему цикл завершится?

Для двух следующих карточек понадобится понять функцию с двумя результатами. `func sumTo(n int) (int, error)` получает целое n и возвращает число вместе с ошибкой. Тип `error` сообщает, что вход не принят или вычисление не выполнено; `nil` означает, что ошибки нет. `errors.New("n вне диапазона")` создаёт простую ошибку, а разрешённый импорт `errors` делает это имя доступным. Успешный результат — сумма и nil; отказ — ноль и ошибка. В проверке error показывается только как bool: `[сумма,false]` или `[0,true]`. Так закрытый ответ не зависит от текста сообщения ошибки. Это краткое знакомство для чтения контракта, подробная обработка ошибок будет позже.

## Примеры

```go
package main
import "fmt"
func main() {
 n := 5
 for i := 1; i <= n; i++ { fmt.Println(i) }
}
```

Сохраните как `main.go`, выполните `go run main.go`: будут пять строк. Замена `<=` на `<` убирает пятёрку. Проверьте также n=1.

```go
package main
import "fmt"
func main() {
 n := 5; total := 0
 for i := 1; i <= n; i++ { total += i }
 fmt.Println(total)
}
```

Последовательность total равна 1, 3, 6, 10, 15. При n=0 цикл не выполняется, значение остаётся нулём.

```go
package main
import "fmt"
func main() {
 number := 4
 for multiplier := 1; multiplier <= 5; multiplier++ {
  product := number * multiplier
  fmt.Printf("%d x %d = %d\n", number, multiplier, product)
 }
}
```

Каждая итерация вычисляет и выводит один результат; `product` существует внутри тела.

## Ошибки и диагностика

Пропущен последний элемент — перепроверьте `<` и `<=`. Лишний ноль — проверьте старт счётчика. Итог сбрасывается — перенесите накопитель перед циклом. Бесконечное повторение — найдите состояние, которое должно изменяться, и проследите направление. Ошибка на единицу — вручную выпишите первые и последние значения. Переполнение — сравните до сложения с максимальным допустимым int; не исправляйте неверный результат после того, как он уже вычислен. Для этой главы не нужен `for {}`: это намеренно бесконечная форма.


В начале каждой карточки есть сигнатура — короткое описание имени функции, её входов и результата. Например, `func f(n int) string` означает: функция `f` принимает целое `n` и возвращает строку. Среда сама подставляет входные данные, вызывает функцию и выводит каждый результат как JSON-текст; строковый результат виден в кавычках JSON. Это представление результата, а не команда печати. В ответе не нужны `package main` и `func main`, потому что запускающую часть предоставляет проверяющая среда. Эталонное решение лежит отдельно и показывается существующим действием раскрытия.

## Практика

### Easy — Посчитай от 1 до N

Сигнатура: `func countTo(n int) string`. При n<=0 верните пустую строку. Иначе соберите числа от 1 до min(n,20), разделив одним пробелом, без пробела в конце. Верхний предел 20 ограничивает длину ответа: поскольку сигнатура не возвращает error, значение больше 20 обрезается по контракту. Публичные примеры: 0, 1, 5; закрытые: -1, 20, 21. Критерии: первая цифра 1, последний элемент включён, пробелы точны.

### Medium — Сумма ограниченного диапазона

Сигнатура: `func sumTo(n int) (int, error)`. Для `0 <= n <= 1_000_000` верните сумму 1..n и nil. Вне диапазона верните 0 и `errors.New(...)`. Это явное ограничение удерживает цикл небольшим и гарантирует отсутствие переполнения на 32- и 64-битной архитектуре. Публичные примеры: 0, 1, 5; закрытые: -1, 20, 1_000_001. При успешном вызове среда показывает `[sum,false]`, при ошибке — `[0,true]`.

### Hard — Таблица умножения строками

Сигнатура: `func multiplicationTable(n int) (string, error)`. Для `0 <= n <= 12` верните десять строк формата `n x i = product`, где i от 1 до 10. Между соседними строками ровно один перевод строки, после десятой строки его нет. Для n вне диапазона верните пустую строку и ошибку. Используйте уже знакомые `fmt.Sprintf` и конкатенацию строк; массивы и срезы не требуются. Публичные входы: 0 и 4; закрытые: -1, 1, 12, 13. Критерии: десять строк в точном порядке, точные пробелы, правильное произведение и точное правило перевода строки.


## Состояние цикла как короткий журнал

Цикл проще отлаживать, если представить его таблицей. Столбцы `i`, `total до шага`, `total после шага`, `условие после шага` сразу показывают, где теряется значение. Для `n=3` сначала `i=1,total=0`, затем сумма становится 1; следующий шаг даёт 3; заключительный — 6. После увеличения i до 4 проверка ложна. Таким способом можно проверить логику, даже не имея работающей среды.

Не смешивайте счётчик с накопителем. Счётчик обычно меняется одинаковым шагом; накопитель меняется в зависимости от текущего элемента. Для вывода последовательности может быть нужен только счётчик. Для суммы требуются оба. Для таблицы умножения `multiplier` — счётчик, а каждый продукт можно вычислить независимо. Хорошие имена поясняют роль и уменьшают риск использовать не ту переменную.

## Завершение — обязательное свойство

Докажите завершение несложным рассуждением: начальный счётчик конечен; шаг увеличивает его на единицу; условие ограничивает его значением n; следовательно, после конечного числа шагов счётчик станет больше n. Если n меньше старта, тело вообще не выполнится. Условие остановки проверяется до тела, поэтому такая пустая последовательность корректна и возвращает начальное значение накопителя.

В условном цикле `for total < target` такое доказательство может потребовать больше внимания: изменяется ли total? Может ли он пропустить цель? Есть ли верхняя граница? При цикле по диапазону классическая форма делает управление заметнее. На первых шагах курса не используйте `break`, несколько счётчиков и вложенные циклы, если задачу можно выразить одним обычным циклом.

## Переполнение и стоимость работы

Сумма первых n положительных чисел математически равна `n*(n+1)/2`, но используемый в уроке цикл проще наблюдать по шагам. В реальном интерфейсе заранее задают предел объёма работы: среднее упражнение ограничивает вход диапазоном 0..1_000_000, который помещается в int на 32- и 64-битной архитектуре и не требует чрезмерного ожидания. Проверяйте границы до запуска цикла. Это ограничение является частью задания, а не универсальным правилом для всех программ.

Успешный результат функции с двумя значениями — это пара: результат и отсутствие ошибки. При входе вне заданного диапазона возвращаются ноль или пустая строка вместе с ошибкой. Частичный результат был бы неоднозначен: вызывающая сторона могла бы принять его за полный ответ. Закрытые проверки включают границы допустимого диапазона и ближайшее значение за ним.

## Проверяем цикл без внешних материалов

Возьмите любое n до 5 и вручную выполните старт, проверку, тело и шаг, включая последнюю ложную проверку. Для каждого состояния проговорите инвариант: «после обработки i накоплено столько-то». Затем измените одно условие и найдите контрпример. Такой эксперимент объясняет причину гораздо лучше, чем запоминание шаблона. После практики попробуйте заново реализовать сумму, не открывая предыдущий код, и сравните поведение на нуле и отрицательном значении.



Не увеличивайте счётчик после завершения тела вручную отдельной строкой, если шаг уже записан в заголовке: это может дать двойное увеличение. Держите изменение состояния в одном понятном месте. Если цикл имеет несколько переменных, назовите каждую по роли и объясните её изменение, иначе остановку трудно проверить.

## Самопроверка

Попробуйте ответить без подсказки; затем используйте раскрываемые ответы в самопроверке урока. Что возвращает countTo при n=0 и n=21? Каково допустимое значение n для sumTo и как обозначается успех? Что означает bool во втором элементе JSON-пары? Как строится таблица multiplicationTable и где расположен последний перевод строки? Когда for проверяет условие? Что делает i++? Где создать накопитель? Что утверждает инвариант суммы? Чем < отличается от <=?

## Повторение и итог

Вернитесь к каждой ключевой идее через день и объясните её своими словами. Напишите минимальный пример без копирования, предскажите результат до запуска и затем проверьте программу. Если ответ отличается, установите конкретный шаг расхождения. Следующий урок опирается на это умение и продолжает путь курса без обязательных внешних материалов.

## Мини-глоссарий

**loop** — цикл, **iteration** — итерация, **counter** — счётчик, **termination** — завершение, **invariant** — инвариант, **accumulator** — накопитель, **overflow** — переполнение, **progress** — продвижение
