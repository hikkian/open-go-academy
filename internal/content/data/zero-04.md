# Повторение действий: циклы

## Что ты сделаешь

Ты напишешь три функции, в каждой из которых одно и то же действие повторяется много раз: `countTo` собирает числа от 1 до N в строку, `sumTo` складывает их и умеет отказать на неверном входе, `multiplicationTable` строит десять строк таблицы умножения. Для этого ты освоишь цикл `for`, научишься отличать счётчик от накопителя и впервые вернёшь из функции два значения — результат и ошибку.

## Цикл for: старт, условие, шаг

Цикл (loop) повторяет блок команд. В Go он один — `for`, и в его заголовке три части через точку с запятой: что сделать перед началом, при каком условии продолжать, что делать после каждого прохода.

```go
package main

import "fmt"

func main() {
    for i := 1; i <= 3; i++ {
        fmt.Println("проход", i)
    }
    fmt.Println("готово")
}
```

Вывод:

```text
проход 1
проход 2
проход 3
готово
```

Порядок всегда такой: `i := 1` один раз; проверка `i <= 3`; тело; шаг `i++` (то же, что `i = i + 1`); снова проверка. Когда `i` станет 4, условие ложно, и выполнение идёт дальше за фигурную скобку. Один проход тела называется итерацией (iteration). Переменная `i` видна только внутри цикла.

> **Важно.** `i < n` не включает `n`, `i <= n` включает. Для задачи «от 1 до N» нужен `<=`. Ошибка на единицу здесь — самая частая, и компилятор её не видит.

## Счётчик и накопитель

Счётчик (counter) считает проходы, накопитель (accumulator) собирает итог. Накопитель объявляют **до** цикла, иначе он будет обнуляться на каждом проходе.

```go
package main

import "fmt"

func main() {
    total := 0
    for i := 1; i <= 5; i++ {
        total += i
        fmt.Println("после", i, "сумма", total)
    }
    fmt.Println(total)
}
```

Вывод:

```text
после 1 сумма 1
после 2 сумма 3
после 3 сумма 6
после 4 сумма 10
после 5 сумма 15
15
```

Проговори правило, которое верно после каждого прохода: «в `total` лежит сумма чисел от 1 до `i`». Это инвариант (invariant) цикла. Если он верен в начале (сумма до первого числа — 0) и каждый шаг его сохраняет, то после последнего прохода в `total` — ответ. При `n = 0` тело не выполнится ни разу, и `total` останется 0 — это правильный ответ, а не ошибка.

> **Типичная ошибка.** Написать `total := 0` внутри цикла. Программа компилируется, но каждый проход начинает с нуля, и в конце получается только последнее число.

## Строка, которая растёт

Накопителем может быть строка. Число превращается в текст через `fmt.Sprintf("%d", i)`, строки склеиваются плюсом. Разделитель ставят **между** элементами, а не после каждого: перед всеми элементами, кроме первого.

```go
package main

import "fmt"

func main() {
    result := ""
    for i := 1; i <= 4; i++ {
        if i > 1 {
            result += "\n"
        }
        result += fmt.Sprintf("%d x %d = %d", 3, i, 3*i)
    }
    fmt.Println(result)
}
```

Вывод:

```text
3 x 1 = 3
3 x 2 = 6
3 x 3 = 9
3 x 4 = 12
```

Тот же приём с пробелом вместо `\n` даёт `1 2 3 4` без пробела в конце. Проверка в заданиях сравнивает строки буква в букву, поэтому лишний пробел или перевод строки в конце — это ошибка.

## Функция с двумя результатами

Что вернуть, если вход бессмысленный, например отрицательное N? В Go функция может вернуть два значения: результат и ошибку (error). `nil` вместо ошибки означает «всё хорошо»; `errors.New("текст")` создаёт ошибку.

```go
package main

import (
    "errors"
    "fmt"
)

func half(n int) (int, error) {
    if n%2 != 0 {
        return 0, errors.New("нечётное число")
    }
    return n / 2, nil
}

func main() {
    fmt.Println(half(8))
    fmt.Println(half(7))
}
```

Вывод:

```text
4 <nil>
0 нечётное число
```

Правило: проверяй вход **до** цикла и возвращай ноль и ошибку сразу; при успехе — результат и `nil`. Частичный результат вместе с ошибкой не возвращают: получатель не поймёт, можно ли ему верить.

> **Зачем.** В заданиях среда показывает пару как `[15,false]` или `[0,true]`: второй элемент — не текст ошибки, а ответ на вопрос «была ли ошибка». Так проверка не зависит от того, какое сообщение ты написал.

## Если что-то пошло не так

- Пропал последний элемент → в условии `<` вместо `<=`.
- Лишний `0` в начале → счётчик стартует с 0, а нужен с 1.
- Итог равен последнему числу → накопитель объявлен внутри цикла.
- Лишний пробел или `\n` в конце → разделитель добавляется после каждого элемента; ставь его перед всеми, кроме первого.
- Программа «зависла» → условие никогда не становится ложным: проверь, что шаг меняет переменную из условия.
- `import … is not allowed` → в карточке задания сказано, какие импорты разрешены; других не добавляй.

## Практика

Три функции, без `main` и без печати: среда вызывает их сама и показывает результаты строками. Строки в кавычках — это JSON-представление, кавычки в значение не входят.

### Задание 1 · Посчитай от 1 до N

**Цель.** Вернуть числа от 1 до N одной строкой через пробел; при N ≤ 0 — пустую строку; не больше 20 чисел.

**Ожидаемый вывод** — для `n` = 0, 1, 5:

```text
""
"1"
"1 2 3 4 5"
```

**Шаги.**
1. Выбери задание «Посчитай от 1 до N»: сигнатура `func countTo(n int) string`. Импорт `fmt` разрешён.
2. Если `n <= 0`, верни `""`. Если `n > 20`, замени `n` на 20.
3. Заведи `result := ""` и цикл от 1 до `n` включительно; перед каждым числом, кроме первого, добавляй пробел, затем `fmt.Sprintf("%d", i)`.
4. «Запустить»: три строки как в блоке выше. «Проверить» — закрытые примеры: −1, 20 и 21.

**Как проверить себя.** Для 5 ровно четыре пробела внутри строки и ни одного в конце; для 21 строка кончается на `20`; все галочки зелёные.

**Если не принято.**
- Красный «пример 3», в «Получили» строка с пробелом в конце → разделитель добавлен после каждого числа.
- Красный закрытый пример при зелёных открытых → нет ограничения 20 или условие `< 20` вместо `<= 20`.
- `undefined: fmt` → добавь `import "fmt"`.

> **Подсказка.** Условие «перед всеми, кроме первого» — это `if i > 1 { result += " " }` внутри цикла.

### Задание 2 · Сумма ограниченного диапазона

**Цель.** Вернуть сумму чисел от 1 до N и `nil`, если `0 ≤ N ≤ 1 000 000`; иначе `0` и ошибку.

**Ожидаемый вывод** — для `n` = 0, 1, 5; второй элемент пары — «была ли ошибка»:

```text
[0,false]
[1,false]
[15,false]
```

**Шаги.**
1. Выбери задание «Сумма ограниченного диапазона»: сигнатура `func sumTo(n int) (int, error)`. Импорт `errors` разрешён.
2. Первой строкой проверь диапазон: если `n < 0 || n > 1_000_000`, верни `0, errors.New("n вне диапазона")`.
3. Затем `total := 0` и цикл от 1 до `n` включительно с `total += i`.
4. Верни `total, nil`. «Запустить», «Проверить» — закрытые примеры: −1, 20 и 1 000 001.

**Как проверить себя.** Для 0 получается `[0,false]` (цикл не выполнился, ошибки нет); для 5 — `[15,false]`; закрытые примеры зелёные.

**Если не принято.**
- Красный закрытый пример 1 или 3 → для −1 и 1 000 001 должно быть `[0,true]`: проверка диапазона стоит не первой или сравнение нестрогое.
- `[0,false]` вместо `[15,false]` → накопитель внутри цикла или цикл до `n` без `=`.
- Отказ из-за импорта → разрешён только `errors`.

> **Подсказка.** Сумма чисел от 1 до 20 равна 210 — удобно проверить руками закрытый пример.

### Задание 3 · Таблица умножения строками

**Цель.** Вернуть десять строк вида `n x i = произведение` для i от 1 до 10, разделённых переводом строки, если `0 ≤ n ≤ 12`; иначе пустую строку и ошибку.

**Ожидаемый вывод** — для `n` = 0 и 4; `\n` внутри кавычек — это перевод строки в JSON-записи:

```text
["0 x 1 = 0\n0 x 2 = 0\n0 x 3 = 0\n0 x 4 = 0\n0 x 5 = 0\n0 x 6 = 0\n0 x 7 = 0\n0 x 8 = 0\n0 x 9 = 0\n0 x 10 = 0",false]
["4 x 1 = 4\n4 x 2 = 8\n4 x 3 = 12\n4 x 4 = 16\n4 x 5 = 20\n4 x 6 = 24\n4 x 7 = 28\n4 x 8 = 32\n4 x 9 = 36\n4 x 10 = 40",false]
```

**Шаги.**
1. Выбери задание «Таблица умножения строками»: сигнатура `func multiplicationTable(n int) (string, error)`. Разрешены импорты `errors` и `fmt`.
2. Проверь диапазон первой строкой: при `n < 0 || n > 12` верни `"", errors.New("n вне диапазона")`.
3. Цикл `i` от 1 до 10: перед каждой строкой, кроме первой, добавь `"\n"`, затем `fmt.Sprintf("%d x %d = %d", n, i, n*i)`.
4. Верни строку и `nil`. «Запустить», сравни с блоком выше. «Проверить» — закрытые примеры: −1, 1, 12, 13.

**Как проверить себя.** Ровно десять строк, пробелы вокруг `x` и `=` по одному, после десятой строки нет `\n`; для 13 — `["",true]`.

**Если не принято.**
- В «Получили» строка кончается на `\n` → перевод строки добавлен после каждой строки.
- Красный закрытый пример для 12 или 13 → граница: 12 ещё допустимо, 13 уже нет.
- Красный открытый пример для 0 → проверка `n <= 0` вместо `n < 0`: ноль — допустимый вход, таблица из нулей.

> **Подсказка.** Это задание 1 с двумя заменами: разделитель `"\n"` вместо пробела и шаблон `"%d x %d = %d"` вместо `"%d"`.

## Проверь себя

- Когда `for` проверяет условие: до тела или после?
- Что делает `i++`?
- Где объявлять накопитель и почему?
- Что утверждает инвариант суммы после каждого прохода?
- Как показать, что цикл обязательно завершится?

## Итог

- `for старт; условие; шаг { тело }`: условие проверяется перед каждым проходом; `<=` включает границу, `<` нет.
- Накопитель живёт до цикла; разделители ставятся перед всеми элементами, кроме первого.
- Функция может вернуть результат и ошибку: проверяй вход до цикла, при ошибке возвращай ноль и `errors.New`, при успехе — результат и `nil`.
