# Ошибки, wrapping, Is/As и defer

## Что ты сделаешь

Ты напишешь три функции: `parsePositiveID` разберёт положительный идентификатор и вернёт ошибку для всего остального, `parseRecord` разберёт строку `id,name` и сохранит причину ошибки, `describeFailure` оберёт исходную ошибку так, чтобы её можно было распознать через `errors.Is` и `errors.As`.

## Ошибка — это обычное значение

В Go ошибка возвращается как второй результат функции, а не выбрасывается исключением. Вызывающая сторона решает, что делать. Если ошибка не nil, остальные результаты обычно не нужны:

```go
package main

import (
    "errors"
    "fmt"
)

var ErrEmpty = errors.New("empty")

func first(items []string) (string, error) {
    if len(items) == 0 {
        return "", ErrEmpty
    }
    return items[0], nil
}

func main() {
    _, err := first(nil)
    fmt.Println(err)
    fmt.Println(errors.Is(err, ErrEmpty))
}
```

Вывод: `empty` и `true`. Ошибку, на которую можно опереться, объявляют как переменную пакета: сравнение с ней через `errors.Is` надёжнее, чем сравнение текста.

> **Важно.** Сравнивай ошибки через `errors.Is`, а не через `err.Error() == "empty"`. Текст может поменяться, а признак останется.

## Оборачивание: %w

`fmt.Errorf` с глаголом `%w` создаёт ошибку, которая содержит исходную. Текст добавляет контекст, а исходная ошибка остаётся доступна для проверки:

```go
package main

import (
    "errors"
    "fmt"
)

var ErrEmpty = errors.New("empty")

func load(name string) error {
    return fmt.Errorf("load %s: %w", name, ErrEmpty)
}

func main() {
    err := load("users")
    fmt.Println(err)
    fmt.Println(errors.Is(err, ErrEmpty))
}
```

Вывод: `load users: empty` и `true`. Контекст помогает читать сообщение, а `errors.Is` всё ещё находит `ErrEmpty` внутри.

> **Типичная ошибка.** `fmt.Errorf("load: %v", err)` тоже печатает текст, но не сохраняет ошибку. После такой обёртки `errors.Is` вернёт `false`. Для сохранения причины используй `%w`.

## errors.As: достать тип ошибки

`errors.As` ищет в цепочке ошибку заданного типа и записывает её в переменную. Так извлекают код или поле, которые есть только у своего типа ошибки:

```go
package main

import (
    "errors"
    "fmt"
)

type CodeError struct {
    Code int
}

func (e *CodeError) Error() string {
    return fmt.Sprintf("code %d", e.Code)
}

func run() error {
    return fmt.Errorf("run: %w", &CodeError{Code: 7})
}

func main() {
    var ce *CodeError
    err := run()
    if errors.As(err, &ce) {
        fmt.Println(ce.Code)
    }
}
```

Вывод: `7`. Переменная `ce` получила указатель на исходный `CodeError`, хотя ошибка пришла обёрнутой.

## defer: выполнение в конце функции

`defer` откладывает вызов до выхода из функции. Несколько отложенных вызовов выполняются в обратном порядке, последний объявленный — первым:

```go
package main

import "fmt"

func main() {
    defer fmt.Println("первый")
    defer fmt.Println("второй")
    fmt.Println("тело")
}
```

Вывод: `тело`, `второй`, `первый`. Так закрывают ресурсы сразу после открытия, не разбрасывая `Close` по всей функции.

## Если что-то пошло не так

- `cannot use err (variable of type error) as string value` → ошибку нельзя печатать как строку без `Error()`; `fmt.Println(err)` подходит.
- `err declared and not used` → ошибку получили и не проверили: проверь `if err != nil` сразу после вызова.
- `errors.Is` возвращает `false` для обёрнутой ошибки → обёртка сделана через `%v`, а не `%w`.
- `imported and not used: errors` → импорт есть, а функции из пакета не вызваны.

### Задание 1 · Разбери положительный идентификатор

**Цель.** Разобрать десятичное число через `strconv.Atoi` и принять только значение больше 0. Любая другая запись даёт 0 и ошибку.

**Ожидаемый вывод** — входы `42` и `0`:

```text
[42,null]
[0,"error"]
```

**Шаги.**
1. Выбери задание «Разбери положительный идентификатор»: в файле есть `parsePositiveID` с `return 0, nil`. Добавь импорты `"errors"` и `"strconv"`.
2. Разбери текст: `n, err := strconv.Atoi(text)`. Если `err != nil`, верни `0` и ошибку, например `errors.New("bad id")`.
3. Если `n <= 0`, верни `0` и такую же ошибку.
4. Иначе верни `n` и `nil`.
5. Нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Две строки: `[42,null]` и `[0,"error"]`; все три критерия зелёные.

**Если не принято.**
- Для `0` вернулось `nil` вместо ошибки → проверка `n <= 0` должна стоять до возврата успеха.
- Пустая строка или текст `x` дают панику → `strconv.Atoi` возвращает ошибку, проверь её до использования `n`.
- Закрытый пример с числом вне диапазона `int64` не совпал → ошибка от `Atoi` тоже означает отказ.

> **Подсказка.** Сначала проверка ошибки парсинга, потом проверка знака: так не придётся думать о значении, которого нет.

### Задание 2 · Разбери CSV-подобную строку с контекстом

**Цель.** Разобрать строку вида `id,name`: разделитель — первая запятая. Имя после обрезки пробелов не пустое. Ошибка любого поля сохраняет исходную причину через `%w`; при ошибке запись нулевая.

**Ожидаемый вывод** — входы `7,Ada` и `x,Bob`:

```text
[{"ID":7,"Name":"Ada"},null]
[{"ID":0,"Name":""},"error"]
```

**Шаги.**
1. Выбери задание «Разбери CSV-подобную строку с контекстом»: в файле есть `parseRecord` с `return Record{}, nil`. Добавь импорты, которые используешь: `"fmt"`, `"strconv"`, `"strings"`, `"errors"`. Неиспользуемый импорт не компилируется.
2. Раздели строку по первой запятой: `strings.Cut(line, ",")`. Если запятой нет, верни ошибку.
3. Разбери часть до запятой через `strconv.Atoi`. Ошибку оберни: `fmt.Errorf("id: %w", err)`.
4. Имя обрежь через `strings.TrimSpace`. Пустое имя — ошибка. Лишняя запятая в имени — тоже ошибка.
5. Нажми «Запустить» и сравни с блоком выше.
6. Нажми «Проверить».

**Как проверить себя.** Две записи: `{"ID":7,"Name":"Ada"}` с `null` и `{"ID":0,"Name":""}` с `"error"`; все три критерия зелёные.

**Если не принято.**
- Имя `Lin` печатается с пробелами → обрезка пробелов не применена к имени.
- Для `2,` вернулось имя → пустое имя после обрезки должно давать ошибку.
- Запись `3,a,b` принята → вторая запятая должна попасть в имя, а имя с запятой запрещено.

> **Подсказка.** `strings.Cut` возвращает три значения: часть до разделителя, часть после и признак, нашёлся ли он.

## Итог

- Ошибка — обычный результат функции; проверяй её сразу после вызова.
- `%w` добавляет контекст и сохраняет причину: `errors.Is` и `errors.As` находят её через цепочку.
- `defer` выполняет отложенные вызовы в обратном порядке, когда функция завершается.
