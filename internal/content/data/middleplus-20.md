# Worker pool, concurrency limit и fairness

## Что ты сделаешь

Ты разберёшь, зачем ограничивать число одновременно исполняемых задач, почему больше обработчиков не значит больше пользы, и как выбирать следующую задачу так, чтобы срочная не ждала вечно, а обычная не голодала. Три функции урока — `WorkerTurn`, `WorkerBatch`, `WorkerFair` — это детерминированные правила выбора по снимку очереди: порог голодания, затем порядок поступления, стабильные ничьи. Горутин они не создают и параллелизм не измеряют.

## Зачем нужна эта граница

Пул обработчиков (worker pool) ограничивает число задач, исполняемых одновременно, и тем самым защищает общий ресурс: память, соединения, нижестоящий сервис. Предел параллелизма (concurrency limit) — это не «сколько можем», а «сколько полезно»: сотня обработчиков, ждущих одну медленную базу, завершает не больше задач, чем десять, но держит в сто раз больше памяти и соединений. Правильный предел находят измерением: увеличивают число обработчиков, пока растёт полезная пропускная способность, и останавливаются там, где она перестаёт расти, а задержка начинает.

После предела остаётся порядок обслуживания. FIFO — первым пришёл, первым обслужен — предсказуем, но длинная задача задерживает всех за ней. Приоритет помогает срочной работе, но без правила старения низкоприоритетная задача ждёт бесконечно. Урок задаёт детерминированное правило: сначала те, кто ждёт дольше порога голодания (starvation bound), среди них — кто ждёт дольше, при равенстве — кто раньше пришёл; остальные — по порядку поступления.

```go group=turn mode=run
package main

import "fmt"

func workerTurn(arrivalA, arrivalB, waitA, waitB, maxWait int) string {
    if arrivalA < 0 || arrivalB < 0 || waitA < 0 || waitB < 0 || maxWait < 0 {
        return "invalid"
    }
    if waitA >= maxWait && waitB >= maxWait {
        if waitA >= waitB {
            return "A"
        }
        return "B"
    }
    if waitA >= maxWait {
        return "A"
    }
    if waitB >= maxWait {
        return "B"
    }
    if arrivalA <= arrivalB {
        return "A"
    }
    return "B"
}

func main() {
    fmt.Println(workerTurn(1, 2, 0, 0, 5), workerTurn(2, 1, 5, 0, 5), workerTurn(1, 2, 0, 5, 5), workerTurn(2, 1, 5, 5, 5), workerTurn(1, 2, 0, 0, 0))
}
```

Вывод:

```text
A A B A A
```

Второй случай: A пришла позже, но ждёт уже пять при пороге пять — порог голодания побеждает порядок поступления. Четвёртый: обе за порогом с равным ожиданием — ничья отдаётся A по стабильному правилу. Пятый: порог ноль означает, что все «голодают» с момента прихода, и решает ожидание, при равенстве — A.

> **Важно.** Ничья решается всегда одинаково — это и есть стабильность. Выбор «кто попался первым в карте» делает поведение невоспроизводимым и тесты — плавающими.

## Пачка на несколько обработчиков

Когда свободны несколько обработчиков, правило применяют повторно: сначала выбираются все, кто за порогом голодания, в порядке убывания ожидания (ничья — ранний приход), затем оставшиеся места заполняются по порядку поступления. Число обработчиков обрезается до числа задач, а ноль обработчиков даёт пустой выбор — это допустимо.

```go group=batch mode=run
package main

import "fmt"

func workerBatch(arrival, wait []int, workers, maxWait int) []int {
    if len(arrival) == 0 || len(arrival) != len(wait) || workers < 0 || maxWait < 0 {
        return nil
    }
    for i := range arrival {
        if arrival[i] < 0 || wait[i] < 0 {
            return nil
        }
    }
    if workers > len(arrival) {
        workers = len(arrival)
    }
    chosen := make([]bool, len(arrival))
    out := []int{}
    for n := 0; n < workers; n++ {
        best := -1
        for i := range arrival {
            if chosen[i] || wait[i] < maxWait {
                continue
            }
            if best < 0 || wait[i] > wait[best] || (wait[i] == wait[best] && arrival[i] < arrival[best]) {
                best = i
            }
        }
        if best < 0 {
            for i := range arrival {
                if !chosen[i] && (best < 0 || arrival[i] < arrival[best]) {
                    best = i
                }
            }
        }
        chosen[best] = true
        out = append(out, best)
    }
    return out
}

func main() {
    fmt.Println(workerBatch([]int{0, 1, 2}, []int{0, 7, 4}, 2, 5))
    fmt.Println(workerBatch([]int{4, 1, 3}, []int{0, 0, 0}, 2, 5))
    fmt.Println(workerBatch([]int{0, 1, 2}, []int{7, 7, 2}, 2, 5), workerBatch([]int{0}, []int{0}, 0, 0))
}
```

Вывод:

```text
[1 0]
[1 2]
[0 1] []
```

Первая пачка: индекс 1 ждёт семь при пороге пять — берётся первым, второе место — индекс 0 как самый ранний из оставшихся. Вторая: никто не голодает, порядок поступления даёт индексы 1 и 2. Третья: двое голодают с равным ожиданием — ничья по раннему приходу. В задании ответ возвращается строкой индексов через запятую; `itoa` придётся написать самому — импорты запрещены.

> **Типичная ошибка.** Сортировать весь список один раз по составному ключу «за порогом, ожидание, приход». Это даёт тот же результат, что повторный выбор лучшего, только если ключ полный; при неполном ключе пачка нарушает правило старения.

## Инвариант справедливости

Правило выбора полезно ровно настолько, насколько его можно проверить. Инвариант простой: ни одна задача, достигшая порога голодания, не остаётся невыбранной, когда выбор сделан. Если такое случилось — обработчиков меньше, чем голодающих, и это сигнал о пределе, а не об алгоритме, но правило всё равно должно отдать места именно голодающим.

```go group=fair mode=run
package main

import "fmt"

func workerFair(arrival, wait []int, selected []bool, maxWait int) bool {
    if len(arrival) == 0 || len(arrival) != len(wait) || len(arrival) != len(selected) || maxWait < 0 {
        return false
    }
    for i := range arrival {
        if arrival[i] < 0 || wait[i] < 0 {
            return false
        }
        if !selected[i] && wait[i] >= maxWait {
            return false
        }
    }
    return true
}

func main() {
    fmt.Println(workerFair([]int{0, 1, 2}, []int{1, 7, 2}, []bool{true, true, true}, 5), workerFair([]int{0, 1}, []int{5, 0}, []bool{false, false}, 5))
    fmt.Println(workerFair([]int{0, 1, 2}, []int{0, 7, 2}, []bool{true, false, true}, 5), workerFair([]int{0, 1}, []int{4, 0}, []bool{true, false}, 5), workerFair([]int{0, 1}, []int{0, 0}, []bool{true, true}, 0))
}
```

Вывод:

```text
true false
false true true
```

Третий случай нарушает инвариант: индекс 1 голодает, но не выбран, хотя выбраны два других. Четвёртый — честен: невыбранный ждёт четыре при пороге пять. Пятый: порог ноль, все голодают, все выбраны. Проверка не говорит, оптимален ли выбор, — только что он не бросил голодающих.

> **Зачем.** Инвариант проверяется на каждом снимке очереди в тесте и в метрике: число невыбранных за порогом должно быть нулём, пока есть свободные обработчики.

## Что ещё входит в контракт пула

Поведение при нуле задач: обработчики ждут, не крутятся в пустом цикле. При переполнении: обратное давление из уроков об очереди и допуске. При отмене: задача, отменённая до взятия, не исполняется; взятая — проверяет контекст перед дорогими шагами. При закрытии очереди: новые задачи не принимаются, взятые завершаются в пределах льготного периода, оставшиеся отменяются с наблюдаемым итогом. Все четыре случая записываются рядом с пределом параллелизма, иначе пул «работает», пока не случится первая выкладка.

## Практическая процедура

Нарисуй таблицу задач: индекс, время прихода, время ожидания, за порогом или нет. Примени правило вручную для одного обработчика, затем для двух, и запиши выбранные индексы. Придумай вход, где двое голодают с равным ожиданием, и вход, где порог ноль. Проверь каждый выбор инвариантом справедливости. Затем прогони те же входы через функции урока и сравни; расхождение — повод уточнить таблицу или найти ошибку в правиле ничьей.

## Типичные ошибки

- Предел параллелизма «побольше»: память и соединения растут, пропускная способность нет.
- Приоритет без порога старения: низкий приоритет голодает.
- Ничья по порядку обхода карты: невоспроизводимый выбор.
- Одна сортировка с неполным ключом вместо повторного выбора лучшего.
- Нет проверки инварианта: несправедливость видна только по жалобам.
- Нет поведения при отмене и закрытии: задачи исполняются после остановки.

## Самостоятельная лаборатория

Собери пул на `N` горутинах с ограниченной очередью и правилом выбора из урока: диспетчер при освобождении обработчика выбирает задачу функцией `workerTurn`/`workerBatch`, храня время постановки. Подай смесь коротких и длинных задач выше ёмкости и запиши распределение ожидания с FIFO и с порогом голодания. Проверяй инвариант справедливости на каждом снимке счётчиком и выведи максимум невыбранных за порогом. Затем увеличь `N` вдвое и покажи, растёт ли завершённая работа или только занятая память. Удали стенд.

## Если что-то пошло не так

- `B` при равном ожидании за порогом → ничья отдаётся A.
- Порог голодания не побеждает ранний приход → проверки порога стоят после сравнения прихода.
- `invalid` при `workers = 0` → ноль обработчиков допустим и даёт пустую строку.
- Пачка не соблюдает старение → выбирай лучшего повторно, не сортируй один раз.
- `true` при невыбранном голодающем → условие инварианта инвертировано.
- `import … is not allowed` → импорты запрещены: напиши преобразование числа в строку сам.

## Практика

Три функции без `main` и печати; среда показывает результаты строками в кавычках и `bool`. Это детерминированные правила по снимку; горутины и каналы не используются.

### Задание 1 · Easy: worker pool, concurrency limit и fairness — классификация

**Цель.** Выбрать `A` или `B`: сначала задание за порогом голодания, при обоих — большее ожидание (ничья — `A`), иначе более ранний приход (ничья — `A`); отрицательные входы → `invalid`.

**Ожидаемый вывод** — для `(1, 2, 0, 0, 5)` и `(2, 1, 5, 0, 5)`:

```text
"A"
"A"
```

**Шаги.**
1. Выбери задание «Easy»: сигнатура `func WorkerTurn(arrivalA int, arrivalB int, waitA int, waitB int, maxWait int) string`. Импорты запрещены.
2. Валидность; обе за порогом → сравни ожидание (`>=` даёт `A`); одна за порогом → она; иначе `arrivalA <= arrivalB` → `A`.
3. «Запустить», «Проверить» — закрытые примеры: только B за порогом → `B`; обе с равным ожиданием → `A`; порог ноль → `A`; отрицательный приход → `invalid`.

**Как проверить себя.** Порог голодания побеждает приход; ничьи всегда отдаются `A`.

**Если не принято.**
- `B` при равном ожидании → строгое `>` вместо `>=`.
- `A` для `(1, 2, 0, 5, 5)` → порог проверен только у A.

> **Подсказка.** Четыре развилки в порядке условия; `>=` в каждой ничьей.

### Задание 2 · Medium: worker pool, concurrency limit и fairness — политика

**Цель.** Выбрать до `workers` индексов: сначала задания за порогом по убыванию ожидания (ничья — ранний приход), затем остальные по порядку прихода; вернуть индексы через запятую; `workers` обрезается до числа заданий.

**Ожидаемый вывод** — для `([0,1,2], [0,7,4], 2, 5)` и `([4,1,3], [0,0,0], 2, 5)`:

```text
"1,0"
"1,2"
```

**Шаги.**
1. Выбери задание «Medium»: сигнатура `func WorkerBatch(arrival []int, wait []int, workers int, maxWait int) string`. Импорты запрещены.
2. `invalid` при пустых или разной длины массивах, отрицательных значениях, `workers < 0` или `maxWait < 0`.
3. Обрежь `workers`; повторяй выбор лучшего: сначала среди голодающих по ожиданию (ничья — приход), иначе самый ранний из невыбранных.
4. Собери индексы в строку через запятую своей функцией `itoa`. «Запустить», «Проверить» — закрытые примеры: двое голодают поровну → `"0,1"`; `workers = 0` → `""`; разная длина → `invalid`.

**Как проверить себя.** Ноль обработчиков — пустая строка, не ошибка; порядок в ответе — порядок выбора.

**Если не принято.**
- `""` вместо `invalid` для `[0,1]` и `[5]` → длины не сравнены.
- `"0,1"` вместо `"1,0"` в первом примере → голодающий должен идти первым.

> **Подсказка.** `itoa` для неотрицательного числа — цикл по остаткам от деления на 10 с приписыванием цифр спереди.

### Задание 3 · Hard: worker pool, concurrency limit и fairness — проверка инварианта

**Цель.** Вернуть `true` только для непустых массивов одинаковой длины с неотрицательными значениями и `maxWait ≥ 0`, если каждое невыбранное задание имеет `wait < maxWait`.

**Ожидаемый вывод** — для `([0,1,2], [1,7,2], [true,true,true], 5)` и `([0,1], [5,0], [false,false], 5)`:

```text
true
false
```

**Шаги.**
1. Выбери задание «Hard»: сигнатура `func WorkerFair(arrival []int, wait []int, selected []bool, maxWait int) bool`. Импорты запрещены.
2. `false` при пустых или несогласованных по длине массивах, отрицательных значениях, `maxWait < 0`.
3. Пройди по заданиям: невыбранное с `wait >= maxWait` → `false`; иначе `true`.
4. «Запустить», «Проверить» — закрытые примеры: невыбранный голодающий → `false`; невыбранный ниже порога → `true`; порог ноль и все выбраны → `true`; `selected` другой длины → `false`.

**Как проверить себя.** Инвариант не оценивает оптимальность — только что голодающих не бросили; порог ноль делает голодающими всех.

**Если не принято.**
- `true` при невыбранном с `wait == maxWait` → порог включительный.
- `true` при несогласованных длинах → проверь все три массива.

> **Подсказка.** Одно условие внутри цикла: `!selected[i] && wait[i] >= maxWait` → `false`.

## Итог

- Предел параллелизма находят измерением полезной пропускной способности, а не задают «побольше».
- Правило выбора детерминировано: порог голодания, ожидание, приход; ничьи стабильны.
- Инвариант справедливости — ни один голодающий не остаётся невыбранным — проверяется тестом и метрикой; поведение при отмене и закрытии входит в контракт пула.
