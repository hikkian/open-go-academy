# P5 — модель угроз и границы доверия

## Активы и границы

Активы: события заказов (возможны персональные данные), tenant IDs, credentials партнёров, журнал аудита, ключи подписи/шифрования, очередь и данные восстановления, а также целостность решений о ранге. Границы: клиент партнёра → публичная точка приёма; API → хранилище/очередь; worker → downstream-провайдер; оператор → административный интерфейс; локальные файлы ученика → платформа оценки; независимый reviewer → подписанное решение.

## Угрозы, контроль и остаточный риск

| Сценарий | Контроль, который должен обосновать ученик | Остаточный риск / проверка |
|---|---|---|
| Подмена tenant ID или перебор чужих event IDs | Tenant из проверенной identity; tenant predicate/составной ключ во всех чтениях и записях; отрицательные интеграционные тесты | Ошибка миграции/нового запроса; тестировать каждую новую операцию и аудитировать запросы |
| Повторная отправка или replay | Подписанный запрос с timestamp/nonce, окно replay; idempotency key с tenant scope и сроком хранения | Украденный credential в окне; ротация и отзыв ключей |
| Stale worker завершает работу после передачи lease | Монотонный fencing token, compare-and-set при фиксации результата, downstream idempotency | Сторонняя система может не поддерживать идемпотентность; нужна сверка/компенсация |
| Сбой между commit и внешним эффектом | Outbox/inbox и повторяемый эффект; не обещать exactly-once без транзакционной границы | Необратимый внешний эффект требует reconciliation |
| Poison message исчерпывает очередь | Ограниченные попытки, DLQ/quarantine, лимит размера, redrive с аудитом | Оператор может ошибочно переиграть; двухстороннее подтверждение и лимиты |
| Всплеск/крупные сообщения истощают CPU, память или диск | Аутентификация, квоты по tenant, bounded body/batches, backpressure, лимиты очереди | DDoS с распределённых адресов; внешний edge зависит от модели размещения |
| Секреты/PII попадают в логи, метрики или трассы | Минимизация, redaction, access control, retention, контроль cardinality | Redaction регрессирует; тестовый canary и аудит логов |
| Компрометация worker или partner key | Отдельные short-lived credentials, least privilege, rotation, egress allowlist | Компрометация доверенной среды; incident response и отзыв |
| Фальшивое доказательство Senior rank | Hash артефакта и независимая аутентифицированная запись решения; серверная привязка к версии | Локальная установка не подтверждает личность публичному verifier; не заявлять аккредитацию |

## Принятый prototype scope

Reference моделирует в памяти только очередное сообщение, lease generation и проверку fencing при завершении. Он не содержит сети, identity, БД, криптографии, tenant authorization или настоящих внешних эффектов. Его тесты подтверждают модель состояния при конкурентном доступе, а не защиту работающей распределённой системы. Для production-проверки нужны SQL-интеграционные и fault-injection тесты на реальном поддерживаемом datastore, тесты авторизации на API и контролируемое восстановительное учение.
