# Безопасность

Сообщайте о потенциальной уязвимости приватно владельцу/сопровождающему проекта, прежде чем публиковать подробности или exploit. В репозитории пока не настроен отдельный security email, bug bounty или SLA ответа; не отправляйте секреты и персональные данные в публичные issue. При открытии проекта владелец должен указать проверяемый приватный канал.

## Поддерживаемая граница

Проверенный сценарий — локальная одиночная установка с API, привязанным к loopback. Исполнитель использует отдельный процесс и rootless OCI-контейнеры с ограничениями; контейнер разделяет ядро с host. Это локальная учебная изоляция, а не сертифицированный sandbox и не защита от всех escape/DoS атак. Публичный или multi-tenant запуск пользовательского кода не поддерживается и не разрешён текущей архитектурой.

Перед включением любого внешнего исполнения требуются отдельный threat review, изолированные workers с более сильной границей (например, microVM), tenant auth/quota/monitoring, полный негативный набор на целевом deployment и закрытие критических/высоких находок. См. [THREAT_MODEL.md](docs/architecture/THREAT_MODEL.md) и [ADR-0002](docs/architecture/ADR-0002-project-execution.md).

## Для сопровождающих

- Не публикуйте `.data/`, `.env`, базы, session/issuer/provider keys, логи с пользовательским содержимым или артефакты с секретами.
- Не запускайте пользовательский Compose/Dockerfile, не добавляйте host fallback при недоступном sandbox и не ослабляйте ограничения ради прохождения теста.
- Перед выпуском проверяйте зависимости и секреты; фиксируйте команды и результаты в validation report.
- Локально выпущенный credential не подтверждает личность, квалификацию или аккредитацию. Публичного доверенного issuer здесь нет.
- Подпись project-review подтверждает только владение ключом, указанным в локальном operator allowlist. Она не подтверждает реальную личность или независимость reviewer; не снимайте advanced-rank fail-closed guard на основании одной подписи или решения ИИ.
- Защищайте reviewer private keys как секреты. Registry содержит публичные ключи, но его изменение меняет локальный trust policy; API принимает только обычный файл mode `0600`, без symlink.

План аудита и известные риски перечислены в [модели угроз](docs/architecture/THREAT_MODEL.md), [плане исполнения](docs/EXECUTION_PLAN.md) и [матрице требований](docs/REQUIREMENT_TRACEABILITY.md). Настоящий файл не является подтверждением завершённого security-аудита.
