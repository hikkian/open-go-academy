# Как писать урок: шаблон и стиль

Это общий шаблон для уроков Open Go Academy и для курсов, собранных на её основе (например, курса классического арабского). Правило одно: ученик в любой момент должен видеть, **что именно от него хотят** и **как понять, что получилось**. Урок — не статья, а маршрут с карточками заданий.

Зачем переписывали: ученик на первом уроке напечатал «Привет, Go!» вместо требуемого «Go готов!». Требование было в тексте, но в середине абзаца; ожидаемый вывод нигде не показывался отдельно. Остальной разбор — в `docs/LESSON_UI_SPEC.md` (интерфейс) и в отчёте задачи OGAUX1.

## 1. Структура урока (порядок обязателен)

1. **Что ты сделаешь** — 2–4 предложения: что конкретно ученик напишет и запустит к концу урока. Не «познакомишься с…», а «напишешь программу, которая…».
2. **Теория маленькими порциями** — разделы `##` по 60–150 слов, у каждого — пример кода или схема. Один раздел = одна мысль. Между разделами — выноски (см. §3).
3. **Практика** — карточки заданий (§4), по одной на каждое упражнение из JSON, в том же порядке.
4. **Проверь себя** — список вопросов (ответы хранятся в JSON и раскрываются в интерфейсе по запросу).
5. **Итог** — ровно три пункта, что запомнить.

Чего в уроке **нет**: мини-глоссария в тексте (слова урока рендерятся из JSON), повтора условия задания прозой вне карточки, советов «вернитесь через день» без конкретного действия, общих абзацев, которые подходят любой теме.

## 2. Тон и язык

- На «ты», короткие фразы, глагол в каждом предложении. Один абзац — 2–4 предложения.
- Сначала «что увидишь», потом «почему». Пример раньше определения.
- Английский термин при первом появлении: *compiler (компилятор)*; дальше — по-русски.
- Не писать «очевидно», «просто», «легко». Не обещать того, что задание не проверяет.
- Цифры, имена кнопок и ожидаемые строки — точно как в интерфейсе: «Запустить», «Проверить», «Результат», «Принято / Не принято».

## 3. Выноски

Выноска — цитата (`>`) с жирной меткой в начале. Метки фиксированы, других не вводить:

```text
> **Важно.** Проверка сравнивает вывод буква в букву.
> **Подсказка.** Если застрял: посмотри на кавычки вокруг текста.
> **Типичная ошибка.** `fmt.Println(answer)` без скобок печатает адрес функции, а не число.
> **Зачем.** Так ты поймёшь сообщение компилятора, а не будешь гадать.
```

Интерфейс (после задачи из `LESSON_UI_SPEC.md`) рисует их как цветные блоки, а **Подсказка** сворачивается до нажатия. До этого они показываются как обычные цитаты — текст остаётся читаемым.

## 4. Карточка задания

Каждое упражнение из `exercises` в JSON получает карточку в разделе «Практика». Заголовок — строго `### Задание N · <title>`, где `<title>` равен `exercises[].title` (по нему интерфейс свяжет карточку с редактором). Внутри — обязательные блоки в этом порядке:

```markdown
### Задание 1 · Поздоровайся с компьютером

**Цель.** Одной строкой: что должно получиться.

**Ожидаемый вывод** — ровно так:

```text
Go готов!
```

**Шаги.**
1. Что открыть.
2. Что написать (с именем функции/кнопки).
3. Нажми «Запустить», сравни с блоком выше.
4. Нажми «Проверить».

**Как проверить себя.** Что ты увидишь в «Результате», когда всё верно (вывод, галочки, статус).

**Если не принято.** 2–4 самые частые причины, каждая — одной строкой «симптом → что исправить».

> **Подсказка.** Один конкретный шаг, не решение целиком.
```

Правила карточки:

- **Цель** — одна строка, без «и», без второго требования. Второе требование — в шаги.
- **Ожидаемый вывод** — отдельный блок `text`, буква в букву, с замечанием о переводе строки там, где он важен. Для функциональных заданий (`kind: function`) — строки в том виде, как их показывает «Запустить»: строки в кавычках, по одному результату на строку, и перед блоком — какие входы им соответствуют.
- **Шаги** — 3–6 пунктов, каждый начинается с глагола. Последние два шага — всегда «Запустить» и «Проверить».
- **Как проверить себя** — наблюдаемые признаки, а не «убедись, что всё верно».
- **Если не принято** — симптом как его видит ученик (текст в «Результате», какая галочка красная) → действие.
- **Подсказка** — не больше двух; не раскрывает решение (эталон есть отдельной кнопкой).
- Критерии в JSON (`criteria`) — те же факты, что и в карточке, короче и в виде чеклиста; каждый критерий должен соответствовать реальной проверке (названиям галочек в «Результате»).
- `prompt` в JSON — это **Цель**, до 90 знаков: он показывается одной строкой над редактором и обрезается. Правило «prompt = цель, правила — в карточке»: если у задания три-четыре правила с приоритетом (как у hard-заданий Junior+ и Middle+), в `prompt` остаётся только главное правило и слова «далее по карточке»; полный порядок правил живёт в блоках «Шаги» и «Как проверить себя».

## 5. Код и формат Markdown (ограничения движка)

- Рендер — CommonMark без расширений: **таблицы и HTML не работают**. Сравнения — списком, раскрывашки — только через интерфейс.
- Каждый блок ```` ```go ```` считается примером и **запускается проверкой курса** (`go run`). Пример должен компилироваться и завершаться без ошибок, не читать ввод, не зависеть от времени и сети. Сломанный код, фрагменты без `package main` и ожидаемый вывод — в блоках ```` ```text ````.
- Атрибуты блока: `go group=<id> mode=run|compile|test file=<имя>`; несколько файлов одной группы — одинаковый `group=`.
- Ссылки только трёх видов: `[текст](lesson:zero-02)`, `[текст](exercise:repair)`, `[текст](#заголовок-урока)`; внешние — только `https://` и только как необязательные.
- Первая строка файла — `# Заголовок`, равный `title` в JSON (интерфейс его не дублирует, но проверка ссылок на него опирается).

## 6. JSON урока: что менять, что нет

Можно: `prompt` (цель), `criteria`, `self_check` (вопросы и ответы), `learning_outcomes`, `glossary`, `estimated_minutes`, порядок карточек в `.md`.

Нельзя без отдельной задачи: `id` упражнений, `title` упражнений и уроков, на которые опираются тесты (например «Поздоровайся с компьютером», «Что такое компьютер, программа и Go»), `starter_code`, `public_output`, `kind`, `skills`, файлы `internal/grading/specs/*` и эталоны. Смысл проверки — неизменен; меняется подача.

Для 88 уроков Middle/Middle+/Senior действует контракт 1800–2200 слов в `.md` (`scripts/test_m11_curriculum_quality.py`): карточки добавляют слова, значит прозу сокращают.

## 7. Чеклист перед сдачей урока

- [ ] Первый раздел — «Что ты сделаешь», последний — «Итог» из трёх пунктов.
- [ ] Каждый теоретический раздел ≤ 150 слов и содержит пример или схему.
- [ ] У каждого упражнения есть карточка с семью блоками в нужном порядке; `### Задание N · title` совпадает с JSON.
- [ ] Ожидаемый вывод совпадает с `public_output` (или с выводом «Запустить» для функций) буква в букву.
- [ ] Все ```` ```go ```` блоки запускаются; сломанный код — в ```` ```text ````.
- [ ] Нет таблиц, HTML, мини-глоссария и повтора условия прозой.
- [ ] `prompt` ≤ 90 знаков; `criteria` соответствуют галочкам проверки.
- [ ] Выноски только с четырьмя метками из §3.
- [ ] Слов в тексте: Zero/Junior/Junior+ — 700–1400; Middle и выше — 1800–2200.

## 8. Для других курсов (арабский и т. п.)

Шаблон не привязан к Go: «ожидаемый вывод» для языка — это ожидаемый ответ (огласованный текст, разбор слова), «Запустить» — «Проверить ответ», эталон — ключ с источником. Карточка остаётся той же: цель одной строкой, точный ожидаемый результат отдельным блоком, шаги, как проверить себя, что делать, если не принято, скрытая подсказка. Выноски те же; «Типичная ошибка» в языковом курсе обязательна в каждом уроке.
