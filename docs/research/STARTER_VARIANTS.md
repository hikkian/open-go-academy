# Варианты несоответствия стартового кода и контракта

Проверено 2026-10-16. Исходный дефект найден выборочным ревью Zero04: инструкция запрещала `package main`, а production parser требовал его. Root cause — копирование инструкции для тела функции в интерфейс, принимающий целый Go-файл; дополнительные заготовки не проверялись тем же компилятором, что эталоны.

Поиск `rg` сначала подтвердил точную фразу в Zero04, затем расширился на все `internal/content/data` и корень репозитория: варианты «не добавляйте package main/func main», «В ответе не нужны package main», архитектурные обещания `32..64`. Подтверждены 9 противоречивых prompts и 3 пояснения Markdown Zero02–04, а также 9 стартовых функций без объявления пакета. Все исправлены: сохранить `package main`, не добавлять `func main`. Два заявления об отсутствии переполнения суммы до1e6 на32bit исправлены: максимальная сумма500000500000 требует64bitint; переносимый вариант используетint64.

Второй уровень поиска — фактическая production source policy и компиляция **каждой** опубликованной заготовки. Он обнаружил ещё6 дефектов: JSONtags boundary-типа Item (Junior11easy/hard), повреждённые generic signatures (Junior12medium/hard), неиспользуемые imports (Junior+17easy/18easy). Исправления сохранили задачи незавершёнными, но корректно объявленными и компилируемыми.

CI-rule — постоянный `TestEveryPublishedGoExampleAndFunctionReference/.../starter-compiles`: production `Spec.Request(false)` затем Go build доверенной заготовки+driver. Это проверяет весь опубликованный набор, а не список имён дефектов. Пользовательский код на тестовом host не исполняется. Результат: `.data/m10-all-starters-fixed.log` PASS48.402s, все117заготовок плюс существующие reference/example tests.

Широкий поиск слов `package/main` также находил корректные объяснения пакетов и исторические отчёты; это false positives, не исправлялись. Не заявляется полный педагогический аудит всех40глав.
