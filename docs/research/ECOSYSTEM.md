# Backend-экосистема: минимальный стек и учебные расширения

Проверено 2026-10-15. Фактические Go module версии ниже получены из официального Go module proxy (`https://proxy.golang.org/<module>/@latest`), который является стандартным публичным proxy Go; JSON `Version` и `Time` фиксируют snapshot и время upstream-тега. Это не утверждение о runtime-совместимости с ещё не созданным приложением. Повторно проверить версии и требования к Go перед добавлением зависимости, закреплять конкретные версии в `go.mod`/`go.sum`.

## Рекомендуемый минимальный набор

1. **HTTP:** сначала стандартные `net/http`, `http.Handler`, `ServeMux`, `httptest`; использовать контекст запросов, явные timeouts, корректное завершение сервера и ограничения размеров входа. По docs Go 1.22 ServeMux понимает HTTP methods и path wildcards; актуальный API snapshot — [Go 1.27.2 net/http](https://pkg.go.dev/net/http@go1.27.2). Внешний router сейчас не нужен: он увеличивает число концепций и затрудняет изучение стандартного API.
2. **Логи:** `log/slog`, стандартная библиотека с Go 1.21, structured key/value logging; достаточно JSON handler и тестируемой конфигурации. Zap (`v1.28.0`, 2026-04-28) и zerolog (`v1.35.1`, 2026-04-20) оставить для сравнительного урока по API/производительности, пока нет измеренного требования ([официальный Go design/background](https://go.dev/blog/slog), [slog API](https://pkg.go.dev/log/slog@go1.27.2)).
3. **SQL API:** преподавать SQL и `database/sql` перед ORM/code generation. Стандартная библиотека не включает драйверы. Для local-first профиля выбрать SQLite через pure-Go `modernc.org/sqlite v1.60.1` (proxy timestamp 2026-09-29); это убирает обязательную cgo-сборку, но всё равно требует проверить поддерживаемые ОС/архитектуры и SQLite semantics при реализации. Альтернатива `github.com/mattn/go-sqlite3 v1.14.52` (2026-09-05) требует cgo/toolchain C и может усложнить воспроизводимые установки.
4. **Хранилище:** SQLite подходит для одиночной локальной установки, файла прогресса, простого backup/restore и обучения SQL без службы БД. Она serverless/embedded, но допускает только одного писателя одновременно; общая БД по network filesystem и высококонкурентный multi-server сервис — плохая граница применения ([SQLite appropriate uses](https://www.sqlite.org/whentouse.html), [serverless](https://www.sqlite.org/serverless.html)). Для размещённой multi-user платформы выбрать PostgreSQL, не SQLite-файл на общей сетевой папке. На дату проверки поддерживаемый PostgreSQL 18 имеет minor `18.6` и заявлен до 2030-11-14 ([официальная политика версий](https://www.postgresql.org/support/versioning/)).
5. **Postgres driver, когда появится hosted mode:** `pgx/v5 v5.11.0` (proxy timestamp 2026-09-07). Если код ориентирован только на PostgreSQL, нативный pgx API даёт PG-специфичные возможности; проект также предоставляет adapter к `database/sql`. Для курса полезно начать с `database/sql`, затем отдельным уроком показать pgx и различия транзакций/types/SQL dialect. Нативный интерфейс предпочесть лишь после конкретной потребности ([upstream pgx](https://github.com/jackc/pgx), [pkg.go.dev](https://pkg.go.dev/github.com/jackc/pgx/v5)).
6. **Migrations:** при SQLite-первом шаге предпочесть малый migration runner или plain SQL migration files. Два проверенных кандидата: `golang-migrate/migrate/v4 v4.20.1` (2026-09-09) и `pressly/goose/v3 v3.29.0` (2026-10-11). Не включать оба; выбрать после прототипа SQLite и проверки поведения rollback/locking на SQLite и PostgreSQL.

## Инфраструктура и темы курса позже

- **Redis:** на официальной странице release notes видны Redis Open Source 8.10.0 (июль 2026), 8.8.0 (май), 8.6.0 (февраль). Уточнять лицензию/условия именно выбранного артефакта и версии: продуктовая страница охватывает несколько Redis offerings ([release notes](https://redis.io/docs/latest/operate/oss_and_stack/stack-with-enterprise/release-notes/redisce/), [license page](https://redis.io/legal/licenses/)). Пока кэш или очереди не нужны вертикальному сценарию.
- **Kafka:** официальный downloads page на дату проверки показывает поддерживаемые 4.3.1 и 4.2.2; это отдельная операционная система, слишком сложная для базового урока ([downloads/releases](https://kafka.apache.org/downloads/)).
- **RabbitMQ, Docker, профилирование, security:** включить как учебные модули позже. Для integration testing Docker runtime — требование окружения, а не зависимость приложения. Профилировать CPU/heap/block/mutex после измеряемого baseline средствами `go tool pprof`; для зависимостей добавить `govulncheck`. Эти инструменты не дают гарантии безопасности или производительности сами по себе ([Go diagnostics](https://go.dev/doc/diagnostics), [govulncheck](https://go.dev/doc/security/vuln/)). Для RabbitMQ/Docker конкретные версии здесь не фиксируются: отдельные upstream compatibility/security checks нужны при проектировании соответствующего milestone.
- `database/sql` API — стандартный abstraction, но конкретный драйвер, SQL диалект, миграции, транзакции и locking определяют фактическую переносимость. Переход SQLite → PostgreSQL потребует тестов миграции и пересмотра запросов/ограничений; он не является автоматическим.

Срез версий фиксирует доступные API на дату, не определяет полную матрицу Go/OS/DB совместимости. Код приложения и тесты не запускались; перед добавлением библиотек нужны проверка license/advisories, `go.mod` требований, тесты на выбранной БД и точные pinned versions.
