## Persisted evidence model

- Migration `internal/store/migrations/0007_project_evidence.sql` adds `project_submissions` and `project_evaluations`. Rows link to the local profile; evaluation has a composite foreign key to the exact submission; foreign-key restrict and SQLite update/delete triggers keep both evidence records immutable.
- Project metadata now has versioned server-authored criteria. `projects.CriteriaHash` hashes canonical JSON of project version, rank, description, requirements, milestones, starter files, and public examples.
- `RecordProjectSubmission` validates P3 files, stores the complete accepted package and the exact files sent to the runner, and computes separate SHA-256 hashes. Canonical hash input is domain-separated and length-prefixed; path order does not affect the hash, while project version, path, or any source byte does.
- The isolated runner returns its evaluation profile with the same execution response: TaskFlow checker version and SHA-256 image digest, project/criteria version, runtime policy hash, and automatic rubric version/hash. The API does not accept these values from the learner. `GET /capabilities` reports P3 only when this immutable profile is available.
- After the synchronous runner response, `RecordProjectSubmission` persists the exact accepted package and the exact source subset sent to that job. `RecordProjectEvaluation` persists evaluation status, exit code, pass/fail, checks JSON/hash and the trusted profile. Same artifact + same evaluation replay returns existing IDs; changed checks conflict. `failed`/`error` evaluations are stored distinctly; a transport/runner error without a terminal result creates no evaluation row. `p3:automatic` remains a compatibility/skill event, not the source of rank eligibility.
- Submit response returns `project_evidence` with submission/evaluation IDs, status, exit code, artifact/executed-source/checks hashes, checker digest, runtime policy and rubric versions/hashes. UI shows this under a collapsed details disclosure. It explicitly says automatic evidence does not complete human review or grant a rank.

## Trust boundary and remaining work

This creates durable, server-owned automatic project evidence, but it is not yet consumed by an advanced exam/rank eligibility transaction. Advanced ranks remain fail-closed by `ErrRankEvidenceRequired`; a future versioned rank policy must bind exact submission/evaluation IDs and hashes through exam start/claim/finish and award. P3 human-review labels are not persisted approvals. This local single-profile application cannot claim independent reviewer identity or public credential trust. Evidence is committed after the synchronous runner response; a process crash before that commit requires a resubmission. There is no durable in-flight job/recovery claim.
