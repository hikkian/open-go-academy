# M12 — mobile lesson and editor width regression

Date: 2026-10-18 (Asia/Atyrau)

## Finding

Visual inspection of the Middle concurrency lesson revealed that a long inline repository path (`content/projects/p3/reference/postgres_integration_test.go`) expanded the document beyond a 390 px mobile viewport. Before correction, Playwright measured `document.documentElement.clientWidth=390`, `scrollWidth=449`; `window.innerWidth` also expanded to 449, so the previous assertions comparing scroll width with `window.innerWidth` were false negatives. The viewport screenshot appeared normal, but the full-page capture was 449 px wide.

## Fix

- Inline code in rendered lessons can now wrap at any safe boundary; fenced code has `max-width:100%` while retaining its own horizontal scrolling.
- All E2E horizontal-overflow assertions now compare `document.documentElement.scrollWidth` with `document.documentElement.clientWidth`, the actual layout viewport.
- The Middle lesson test asserts no document overflow immediately after opening the code editor.
