Runtime semantics
- Local provider accepts only loopback HTTP and no API key; `/v1` normalizes to `/v1/chat/completions`.
- Cloud provider accepts HTTPS public hosts; key is stored server-side in a mode-0600 config, omitted from API responses, and is never submitted until normal request consent.
- Every GET returns an opaque provider revision. POST includes that revision; a provider change invalidates prior consent and is rejected before budget reservation/model call. Provider runtime publication follows the persistence transition; deletion of an absent optional config path is a no-op.
- API usage is billed independently of ChatGPT/Codex; see official links in README.
